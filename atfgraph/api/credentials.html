    issueCredential

    POST /api/v2/credentials

    Requires: invoke role, worker role

    Issue a W3C VC 1.1 credential signed with the issuer node's enrolled DID (Data Integrity eddsa-jcs-2022). The caller must have registered the issuer node, or be a worker executing it under an active lease (403 issuer_forbidden). execution credentials certify a terminal traverser owned by the caller or inside the worker's leased subtree (409 traverser_active before completion) and are idempotent per issuer key. custom credentials carry the caller's subject (string id, at most 64 KiB) and an alphanumeric type other than VerifiableCredential or AgentTagCredential. 409 did_not_enrolled when the issuer has no active DID.

    enrolDid

    POST /api/v2/credentials/dids

    Requires: admin role

    Enrol a node's active identity key as a standard did:key (Ed25519, multicodec 0xed01), creating the identity when the label has none. The private key copy is stored encrypted (XChaCha20-Poly1305, bound to namespace, key id and DID) under the daemon credential key. Enrolling an already enrolled key returns the existing record. Key lifecycle stays with the identities operations.

    proposeTags

    POST /api/v2/credentials/tags

    Requires: invoke role

    Propose tags for a node the caller registered (403 tag_forbidden otherwise). Tags are trimmed, lower-cased `[a-z0-9-_.:]{1,64}` and deduplicated. The namespace policy decides per tag: auto approves immediately, manual records pending, forbidden records rejected. When approvals change, the node's AgentTagCredential is superseded and reissued by the policy issuer if one is enrolled; otherwise warning explains why no credential was issued.
