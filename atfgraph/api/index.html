    API reference

    162 operations in 22 areas, generated from contracts/openapi-v2.json.

    Roles are the contract's own x-required-roles. Credentials carry a namespace and a principal; admin implies every role, and an operation marked "no credentials" is unauthenticated. A role is necessary, not sufficient: the server also enforces ownership.

    The Python distribution is a single wheel, atfgraph. The modules under atfgraph._generated are internal to that wheel and are named here only to show which operations the generated layer covers; they are not a public API and their layout can change without notice.

    AreaOperationsCovers
    Access12Access policies and connector grants: who may start which traversals, and which external connectors a namespace may reach. Server authorization is authoritative; these operations edit the rules it enforces.

    Credentials14Node identity enrolment, credential issuance and verification, revocation and the node tag ledger. Keys stay on the graph server; nothing here hands out private material.
    Discovery8Reading the server description, the registered agent nodes and their capabilities, and the agent-resource-discovery publications and search under /api/v2/ard.
    Emitters10Scheduled and event-driven sources that start traversers, plus their delivery log.
    Evaluations14
    Events3The durable event log of a traverser, as a snapshot or as a stream.
    Health1Unauthenticated liveness of the graph server.
    Identity7Node identities, signed paths and proof verification.
    Knowledge7Document knowledge per scope: put, list, get, delete, lexical BM25 search with citations, and per-scope statistics.
    Memory9Reading and writing the session, actor, workflow and global memory scopes.
    Observability19What the server knows about running work: usage accounting, node logs, traverser metadata, the observability webhook, server-wide stats and model-endpoint health.
    Retention2Preview and apply pruning of old traversers, events and logs.
    RuntimeSettings5Stored runtime documents per namespace: list, read, write and delete a key, then apply it to the running process. Saving a document and applying it are separate steps.
    Sessions7Creating sessions and binding a worker task to one.
    Traversers6Submitting traversers, listing them with status, time-window and cursor paging, reading one traverser and its path, cancelling and restarting.
    Worker10The outbound worker protocol: enrol, claim, renew, report, complete, drain; and the fleet view of every enrolled worker.
