    Install and run a first node

    By the end of this page you will have installed the atfgraph wheel, written an agent node with one traversal and one skill, run its worker three different ways, called it from the atfg CLI and from Client, and read the path the graph server recorded. It requires a Rust toolchain to build atfgraphd and atfg, and Python 3.10 or newer; nothing here needs a model provider or credentials.

    Prerequisites: the repository cloned (the Rust server and CLI at its root, the Python package under python/), cargo, Node 22 for the console, and a python3.10+ interpreter (the macOS system python3 is 3.9 and will not install the wheel). If you use a managed graph server, install the client instead (the release's install.sh --from github:rimon-fc/atfgraph@vnext-<version>, see ../install.md) and skip to step 2.

    1. Build the server and install the SDK

    The graph server and the CLI are Rust binaries built at the root of the repository; the SDK is one Python package under python/. Everything runs from the one checkout, as in ../quickstart.md.

    cargo build --bin atfgraphd --bin atfg
(cd ui && npm ci && npm run build)             # the web console, served by the daemon at /ui/
export PATH="$PWD/target/debug:$PATH"

python3.12 -m venv .venv
.venv/bin/python -m pip install -e 'python[test]'

    python/pyproject.toml declares requires-python = ">=3.10" and depends on httpx, pydantic (v2), jsonschema, python-dateutil and typing-extensions. The wheel installs both halves of the SDK: Agent for writing nodes and Client for calling them. The OpenAPI-generated internals ship inside the same wheel; there is no second package.

    2. Write the node

    An agent node is one Agent object: a label (node_id) plus a version, and the capabilities registered on it. The example below is examples/python/first_node/agent.py, unchanged apart from the module docstring.

    from __future__ import annotations

from pydantic import BaseModel

from atfgraph import Agent

app = Agent(node_id="hello", version="1.0.0", description="Greets travellers")


class Greeting(BaseModel):
    greeting: str
    shouted: str
    length: int


@app.skill()
def shout(text: str) -> dict:
    """Upper-case a string. Synchronous handlers run in a worker thread; heartbeats keep going."""
    return {"text": text.upper()}


@app.traversal()
async def greet(name: str, punctuation: str = "!") -> Greeting:
    """Greet by name, using the ``shout`` skill as a nested child step."""
    if not name.strip():
        raise ValueError("name must not be empty")
    loud = await app.traverse("hello.shout", text=f"hello {name}")
    return Greeting(greeting=f"Hello {name}{punctuation}", shouted=loud["text"], length=len(name))


if __name__ == "__main__":
    app.run()

    What the pieces mean:

    PieceMeaning
    Agent(node_id="hello", version="1.0.0")The label and version the node registers under. node_id must not contain ., / or spaces (python/atfgraph/agent.py raises ValueError otherwise).
    @app.skill()A deterministic capability. shout is a plain def, so the worker runs it in a thread.
    @app.traversal()A capability that may route through the graph. greet calls hello.shout with app.traverse, which becomes a child step.
    -> GreetingThe return annotation becomes the registered output schema; the Pydantic instance is serialised with model_dump(mode="json").
    app.run()The foreground worker: register, enroll, claim, and drain on Ctrl+C.

    The input schema is derived from the keyword parameters: name is required, punctuation is optional because it has a default. Page 02-traversals-skills-and-routers.md covers the derivation rules.

    3. Start the graph server

    atfg server start

    It prints the API and console addresses; the default is http://127.0.0.1:18880. Loopback without an API key is development mode. The SDK reads ATFGRAPH_SERVER and ATFGRAPH_API_KEY from the environment and falls back to that loopback address (python/atfgraph/transport.py), so on one machine nothing else has to be configured. See ../howto-run-graph-server.md for other ways to run it.

    4. Run the worker, three ways

    All three start the same outbound worker. There are no inbound callbacks: the worker registers the definition, enrolls with a capacity, then claims work, heartbeats each lease and completes tasks. Pick the form that fits the moment.

    app.run() in the module

    The if __name__ == "__main__": block above makes the module runnable. From the checkout:

    .venv/bin/python -m examples.python.first_node.agent

    Ctrl+C sets the stop event; the worker drains running tasks and exits.

    python -m atfgraph.worker --module

    The generic worker CLI imports the module and looks for an Agent named app (then agent), or the attribute you name after the colon. Its docstring in examples/python/first_node/agent.py shows this form.

    .venv/bin/python -m atfgraph.worker --module examples.python.first_node.agent:app --server http://127.0.0.1:18880

    Flags, from python/atfgraph/worker.py:

    FlagEffect
    --server URLGraph server (default $ATFGRAPH_SERVER or the loopback address).
    --api-key KEYAPI key, sent as the X-API-Key header (default $ATFGRAPH_API_KEY, then the key atfg login saved for this server).
    `--edge-auth none\databricks`Credential for a platform proxy in front of the server (default $ATFGRAPH_EDGE_AUTH, then what atfg login saved, then none).
    --databricks-profile NAMEDatabricks profile for --edge-auth databricks (default $ATFGRAPH_DATABRICKS_PROFILE). Never chosen for you.
    --capacity NConcurrent handler permits (default Agent(capacity=8)).
    --max-waiting NParents allowed to release their permit while waiting on children.
    --onceExit when the queue is empty and nothing is running.
    --no-registerSkip registration (the definition is already on the server).
    --log-level LEVELPython logging level, default INFO.

    atfg dev

    atfg dev wraps the same worker command, checks that the interpreter can import atfgraph, and reports when the label appears in the registry (../cli-reference.md).

    atfg dev --module examples.python.first_node.agent:app --python .venv/bin/python --expect-label hello

    Whichever way you start it, the first thing serve does is register. Registration is immutable per label and version: if hello@1.0.0 is already registered with a different definition the server answers 409 and the SDK raises ConflictError with the message bump Agent(version=...). Change the code, bump the version.

    5. Call it

    From the CLI

    atfg ls
atfg traverse hello.greet --in '{"name":"Ada"}'

    atfg ls lists hello.greet (kind traversal) and hello.shout (kind skill), each with its timeout and attempt budget. atfg traverse submits a traverser, waits at the barrier and prints the output:

    {
  "greeting": "Hello Ada!",
  "length": 3,
  "shouted": "HELLO ADA"
}

    The input is always a JSON object whose keys are the capability's parameter names, unwrapped. ../howto-start-a-traverser.md lists the other traverse flags (--async, --session, --node-version, --idempotency-key).

    From Python with Client

    Adapted from examples/python/first_node/call.py. Client is an async client; one instance per event loop, used with async with.

    from __future__ import annotations

import asyncio
import os

from atfgraph import Client


async def main(name: str) -> None:
    async with Client(os.getenv("ATFGRAPH_SERVER")) as client:
        handle = await client.submit("hello.greet", {"name": name})
        print("submitted", handle.id, handle.status)
        result = await handle.result(timeout=60)
        print("result", result)
        path = await handle.path()
        for step in path.items:
            print(f"  {step.target:<14} {step.status:<10} attempts={len(step.attempts)}")


if __name__ == "__main__":
    asyncio.run(main("Ada"))

    client.submit returns a Handle; handle.result(timeout) waits for a terminal state and returns the output, or raises TraversalFailed, TraversalCancelled or TraversalTimedOut. client.traverse(target, input, timeout=...) does submit and result in one call. Client(None) uses ATFGRAPH_SERVER or the loopback default.

    tests/python_test_examples.py asserts the exact output above and that the registered output schema requires greeting, shouted and length.

    6. Read the path

    atfg path <traverser-id>

    atfg traverse prints the traverser id on its first line; atfg path prints one row per step:

    #  STEP  TARGET       STATUS     ATTEMPT  PARENT  ELAPSED
1  ...   hello.greet  succeeded  1        -       314ms
2  ...   hello.shout  succeeded  1        <step 1> 6ms

    Two steps: the traversal you called and the skill it called through the graph server. In Python the same data is Path.items, a list of PathStep with step_id, traverser_id, target, status, parent_step_id and attempts (python/atfgraph/models.py). The step with no parent is the root; the edge from step 1 to step 2 is the app.traverse call inside greet. Nothing in the handler recorded that edge explicitly: the call went through the server as a nested child, so the server recorded it.

    When the handler raises

    greet raises ValueError for a blank name. The worker completes the task with an error envelope {"code": "ValueError", "message": "name must not be empty", "retryable": false} and the traverser ends failed. atfg traverse exits with code 3 and prints the envelope; handle.result() raises TraversalFailed whose .code is "ValueError". Page 03-calling-other-nodes.md shows how RetryableError changes that.

    Connecting to a server that needs credentials

    Loopback development needs none of this. A shared graph server does, and there are two separate layers, each in its own header:

    LayerHeaderWhat it answersHow you supply it
    ATFGraph API keyX-API-Keywhich namespace, principal and roles you are--api-key, Client(api_key=...), Agent(api_key=...), $ATFGRAPH_API_KEY, or atfg login
    Edge credential (optional)Authorizationwhether a platform proxy in front of the server lets the request through--edge-auth, Client(edge_auth=...), $ATFGRAPH_EDGE_AUTH (none by default, or databricks)

    The two never share a header, and the API key is never sent as Authorization. (Client(bearer_token=...) still sets a literal Authorization: Bearer value for a server that takes its key that way; it no longer suppresses api_key, and it cannot be combined with an edge provider.)

    Log in once. atfg login checks the credentials against the server and saves them to ~/.config/atfgraph/credentials (mode 0600; a file other users can read is refused, not used):

    $ atfg login https://graph.example.com
API key (leave empty for a server without keys):
server   https://graph.example.com  (credentials accepted)
api key  atfg_9f2…
edge     none
saved    /home/you/.config/atfgraph/credentials (0600); this is now the current server

    After that atfg ls, Client(), Agent("x") and python -m atfgraph.worker need no server or key argument. Each setting resolves on its own: an explicit argument or flag, then the environment variable, then the saved entry for the server being called, then the default. A saved key is only ever sent to the server it was saved for. atfg whoami shows the resolved server, the first characters of the key and where each value came from; atfg logout [url] removes one saved server and leaves the others alone.

    Behind a Databricks Apps proxy. Set the edge mode and name the profile; a profile is never picked for you:

    $ atfg login https://graph.example.com --edge-auth databricks --databricks-profile my-profile
$ pip install 'atfgraph[databricks]'

    The CLI obtains the workspace token with databricks auth token --profile my-profile and keeps it in memory until shortly before it expires. The Python SDK uses databricks-sdk unified authentication, which also finds the client id and secret a Databricks App injects, so a node running as an App sets ATFGRAPH_EDGE_AUTH=databricks and needs no profile. Tokens are refreshed for you and are never written to disk or logged; the credentials file records only the profile name. Pass your own provider as Client(edge_auth=obj) where obj.headers() returns the Authorization header.

    Stop

    Ctrl+C in the worker terminal, then atfg server stop.
