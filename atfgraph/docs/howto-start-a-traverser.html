    Start a traverser and read its path

    Problem: a node is registered and you want to call one of its traversals or skills, get the result, and see the steps it took.

    The target is always label.capability. Input is a JSON object whose keys are the capability's named inputs, unwrapped.

    From the CLI

    atfg ls                                                  # what is registered
atfg traverse hello.greet --in '{"name":"Ada"}'          # wait at the barrier, print the result
    traverser 8d2efb59-8a42-4087-bc80-d9b04b4b2b4d queued; waiting at the barrier (up to 300s)
traverser 8d2efb59-8a42-4087-bc80-d9b04b4b2b4d succeeded (hello.greet)
{
  "greeting": "Hello Ada!",
  "length": 3,
  "shouted": "HELLO ADA"
}

    Asynchronously, then wait and inspect:

    ID=$(atfg traverse hello.greet --in '{"name":"Grace"}' --async)
atfg wait "$ID" --wait-timeout 120 || echo "exit $?"
atfg show "$ID"                         # fields, output, error
atfg path "$ID"                         # every step and attempt
atfg --json show "$ID" | jq .output
atfg ps --status running                # live traversers
atfg cancel "$ID"                       # children are cancelled by the server

    Useful flags on traverse: --in-file PATH (- for stdin), --node-version V to pin a registered version, --session ID or --new-session to attach the traverser to a conversation, --idempotency-key K for safe retries.

    Exit codes: 0 succeeded; 1 error (unreachable server, API error envelope, invalid input); 2 still not terminal after --wait-timeout; 3 terminal but not succeeded (failed, cancelled, timed_out). A handler that raises gives exit 3 with the error envelope:

    traverser 99e794ae-ec1e-4e06-a38c-daf063fb79ab failed (hello.greet)
error: {
  "code": "ValueError",
  "message": "name must not be empty",
  "retryable": false
}

    Over HTTP

    curl -s -X POST http://127.0.0.1:18880/api/v2/traversers \
  -H 'content-type: application/json' \
  -d '{"target":"hello.greet","input":{"name":"Ada"}}'

    The server answers 202 with the traverser. Then:

    ReadRequest
    One traverserGET /api/v2/traversers/{id}
    Its pathGET /api/v2/traversers/{id}/path
    Its event logGET /api/v2/traversers/{id}/events (snapshot) or the stream variant
    CancelPOST /api/v2/traversers/{id}/cancel
    ListGET /api/v2/traversers?status=running&roots_only=true&limit=50

    Off loopback, send the ATFGraph key as X-API-Key: <key>; Authorization is reserved for a platform proxy's credential (ATFGRAPH_EDGE_AUTH=databricks). The operation tables are in the generated Traversers reference.

    From Python

    import asyncio, os
from atfgraph import Client

async def main() -> None:
    async with Client(os.getenv("ATFGRAPH_SERVER", "http://127.0.0.1:18880")) as client:
        handle = await client.submit("hello.greet", {"name": "Ada"})
        result = await handle.result(timeout=60)
        path = await handle.path()
        for step in path.items:
            print(step.target, step.status, len(step.attempts))

asyncio.run(main())

    This is examples/python/first_node/call.py. Inside a traversal, use await app.traverse("label.capability", **inputs) instead; the call is recorded as a child step under the current one.

    Reading a path

    #  STEP                                  TARGET       STATUS     ATTEMPT  PARENT                                ELAPSED
1  0a108d2b-e768-483a-bde9-f5ab3208bedb  hello.greet  succeeded  1        -                                     314ms
2  f6ea3c4a-b8e1-448c-b12c-2183ebe762be  hello.shout  succeeded  1        0a108d2b-e768-483a-bde9-f5ab3208bedb  6ms

    Each row is one step: the target that was called, its status, which attempt this was, and the parent step that called it. A step with no parent is the root. atfg share <id> writes the same path as a self-contained HTML or JSON file.
