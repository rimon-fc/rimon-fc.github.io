    Usage, logs and tracing

    At the end of this page you can see what every model and media call cost inside a traverser, read those totals from a client or from the graph server's durable usage store, ship a node's log records to the server, attach metadata to a run, drive the namespace webhook, and turn on MLflow tracing. Usage accounting works with nothing configured; node logs need an administrator opt-in; MLflow needs the optional extra.

    Prerequisites: a model provider (ATFGRAPH_MODEL_URL, ATFGRAPH_MODEL_NAME) only for the app.ai snippet; python -m pip install './python[mlflow]' only for the tracing section.

    What is recorded without asking

    Every model or media call made through an Agent (app.ai, ai_generate_*, ai_transcribe_audio, harness, realtime turns) records one CostEntry against the traverser it runs in (python/atfgraph/costs.py). Token counts come from the provider's usage object. A price is filled only when the provider reported one (OpenRouter usage.cost, fal and MiniMax billing fields); the SDK never multiplies tokens by a price table, so an unknown price is None and is kept distinct from a reported 0.0.

    Inside a worker task app.record_usage puts the entry in three places (python/atfgraph/agent.py):

    DestinationHow to read itSwitch
    In-process tracker for this executionapp.execution_cost()always on
    The traverser's event log, as a progress event {"usage": ..., "totals": ...}client.events(...) with UsageEvent.from_eventAgent(record_usage_events=False)
    The graph server's durable usage storeapp.observability.usage(...), usage_totals(...)Agent(report_usage=False)

    Accounting never fails a handler. If the server refuses a record, the entry stays in the tracker and the progress event, the failure is logged once, and app.usage_reporting() counts it.

    Return the cost of a traverser

    Adapted from examples/python/features/multimodal/agent.py; this handler needs a chat provider that accepts image parts.

    from typing import List, Optional

from pydantic import BaseModel

from atfgraph import Agent, Image

app = Agent(node_id="media", version="1.0.0")


class Findings(BaseModel):
    summary: str
    objects: List[str]
    readable_text: Optional[str] = None


@app.traversal()
async def describe(image_url: str, question: str = "What is in this image?") -> dict:
    findings = await app.ai(question, Image.from_url(image_url), schema=Findings)
    return {"findings": findings.model_dump(), "cost": app.execution_cost()}

    app.execution_cost() returns total_calls, total_input_tokens, total_output_tokens, total_tokens, total_cost_usd, calls_without_price and by_model. total_cost_usd is None unless at least one call has a price. A price is what the provider reported, or an estimate from the node's rate table (ATFGRAPH_MODEL_PRICES, 06-model-calls.md) recorded with cost_source="table"; the Console marks such calls estimated. The module-level execution_cost(ctx) gives the same totals for an explicit context, and use_tracker() binds a tracker for code running outside a worker task.

    Record usage yourself

    When you call a provider directly, record what it reported so it lands in the same three places. usage_from_response lives in atfgraph.costs; adapted from tests/test_mlflow_tracing.py:

    from atfgraph import Agent
from atfgraph.costs import usage_from_response

app = Agent(node_id="mlf-node", version="1.0.0")


@app.traversal()
async def run(n: int) -> dict:
    await app.record_usage(
        usage_from_response({"prompt_tokens": 7, "completion_tokens": 5}, model="ollama/llama3", provider="ollama")
    )
    return {"value": n * 2}

    You can also build a CostEntry by hand; tests/test_sdk_extension_integration.py records CostEntry(model="openrouter/qwen", provider="openrouter", input_tokens=10, output_tokens=5, total_tokens=15, cost_usd=0.0012, cost_source="provider"). The durable record carries a call_id of the form <step>-<attempt>-<n>, so re-posting the same call deduplicates server-side while a retried attempt, which really did spend tokens again, records new rows.

    Read usage from a client

    The progress events are visible to any caller that can read the traverser. Adapted from examples/python/features/multimodal/call.py:

    import asyncio
import os

from atfgraph import Client, UsageEvent


async def show(client: Client, target: str, payload: dict) -> None:
    handle = await client.submit(target, payload)
    print(target, await handle.result(timeout=300))
    async for event in client.events(handle.id):
        usage = UsageEvent.from_event(event)
        if usage is not None:
            print(f"  usage {usage.operation:<14} {usage.model:<28} tokens={usage.total_tokens} cost_usd={usage.cost_usd}")


async def main() -> None:
    async with Client(os.getenv("ATFGRAPH_SERVER")) as client:
        await show(client, "media.describe", {"image_url": os.environ["DEMO_IMAGE_URL"]})


asyncio.run(main())

    The durable store is read through app.observability (an Observability facade; Observability.for_client(client) works outside an agent). Adapted from tests/test_sdk_extension_integration.py:

    from atfgraph import Client, Observability


async def report(url: str, traverser_id: str) -> None:
    async with Client(url) as client:
        obs = Observability.for_client(client)
        page = await obs.usage(traverser_id=traverser_id)
        for record in page.items:
            print(record.model, record.total_tokens, record.cost_usd, record.cost_known, record.capability)
        totals = await obs.usage_totals(group_by="model")
        print(totals.totals.calls, totals.totals.unpriced_calls)
        print({key: bucket.cost_complete for key, bucket in totals.by_key.items()})

    usage_totals covers the caller's own runs; group_by is one of run, model, provider, day, attempt_status, label, principal, none; since/until are epoch milliseconds; administrators may pass principal or all_principals=True. UsageTotals.cost_complete is true only when every call in the bucket was priced.

    Reporting counters

    app.usage_reporting() returns {"enabled", "recorded", "deduplicated", "failed", "events_failed", "last_error"}. With Agent(report_usage=False) nothing is posted to /api/v2/usage and enabled is False; the progress event and the local tracker still work (tests/test_sdk_extension_integration.py).

    Node logs

    Shipping this process's log records to the graph server is off until two things happen: an administrator enables it for the namespace, and the node installs the handler.

    import logging

from atfgraph import Agent

app = Agent(node_id="sdk-logs")
logger = logging.getLogger("myapp")


@app.traversal()
async def work(step: str) -> dict:
    logger.info("handling %s", step)
    await app.node_logs.flush_async()          # make these lines durable before the attempt ends
    return {"traverser_id": app.ctx.traverser_id}


async def opt_in() -> None:
    await app.observability.set_settings(node_logs_enabled=True)     # administrator, once per namespace


handler = app.enable_node_logs(logger, level=logging.INFO, max_pending=1000, batch_size=100, flush_interval=1.0)

    Adapted from tests/test_sdk_extension_integration.py, which shows against a real daemon that records logged before the opt-in are rejected with node_logs_disabled and counted in handler.failed, not stored. Behaviour from python/atfgraph/observability.py:

    • Only records emitted inside a traversal are shipped; records outside one, and records from the shipping path itself (atfgraph.observability, atfgraph.transport, httpx, httpcore, plus any exclude= prefixes) stay local.
    • The queue holds max_pending records; beyond that the oldest is dropped and counted in handler.dropped.
    • The flusher runs while serve() runs. Logs are written under the task's lease, so anything still queued when an attempt ends can no longer be sent; call await app.node_logs.flush_async() inside a long handler.
    • await app.disable_node_logs() detaches the handler and ships what is queued; calling it twice is harmless. enable_node_logs twice raises RuntimeError.

    Read them back with await app.observability.query_logs(traverser_id=..., levels=["warn", "error"], contains="desk") (levels are trace, debug, info, warn, error, fatal, log; Python's warning and critical map to warn and fatal), or follow a run live with async for record in app.observability.stream_logs(root_id=...), which consumes the server's GET /api/v2/logs/events stream (resumes with Last-Event-ID, returns when the run is terminal and its last batch has arrived); tail_logs is the polling fallback. app.observability.log("message", "warn", step=1) ships a single line for the current task without the logging handler.

    Run metadata

    A run (the root traverser) has a metadata document. Adapted from tests/test_sdk_extension_integration.py:

    from atfgraph import Agent

app = Agent(node_id="sdk-meta")


@app.traversal()
async def tag() -> dict:
    await app.observability.set_run_metadata(set={"display_name": "Trip 21", "labels": ["demo"]})
    return {"root_id": app.ctx.root_id}


async def read_back(root_id: str) -> None:
    metadata = await app.observability.run_metadata(root_id)
    print(metadata.metadata, metadata.mlflow_trace_id, metadata.updated_at)

    Inside a handler the root is taken from the context; outside one pass root_id. set_run_metadata(set=..., unset=[...]) merges; at most 64 keys. Keys reserved by convention: display_name, labels, links, mlflow_trace_id, mlflow_experiment_url.

    The namespace webhook

    Administrators can have the server post observability events to one URL. Adapted from tests/test_observability.py:

    from atfgraph import Client, Observability


async def configure(url: str) -> None:
    async with Client(url) as client:
        obs = Observability.for_client(client)
        config = await obs.set_webhook(
            "https://hooks.example/atfgraph",
            secret_env="HOOK_SECRET",
            headers={"X-Team": "pricing"},
            event_types=["usage.recorded", "run_metadata.updated"],
        )
        assert config.secret_present
        status = await obs.webhook_status()
        print(status.pending, status.delivered, status.failed)
        delivery_id = await obs.test_webhook("ping")
        redriven = await obs.redrive_webhook(limit=100)
        print(delivery_id, redriven)
        await obs.delete_webhook()

    The secret is never sent by the SDK: secret_env names an environment variable on the graph server host. set_webhook accepts only the event types in atfgraph.observability.WEBHOOK_EVENT_TYPES: usage.recorded, node_logs.appended, run_metadata.updated, webhook.test. Deliveries carry an x-atfgraph-signature: sha256=... HMAC over the body, which the bridge listener in tests/test_mlflow_tracing.py verifies against a real daemon.

    run.completed

    Subscribe the namespace webhook to run.completed to be told, once per root traverser, when it reaches a terminal status. The signed payload is {root_id, traverser_id, target, label, version, status, principal, session_id, started_at, finished_at, duration_ms, error?, output_bytes}; it never carries the output itself, so integrators fetch GET /api/v2/traversers/{id} for the result. Child steps do not emit it. This replaces polling for the callers that only need a completion signal; Client.wait and the event stream remain for callers that want the result inline.

    MLflow tracing

    atfgraph.mlflow is optional: import atfgraph never imports mlflow, and nothing is contacted until you call enable. Adapted from python/atfgraph/mlflow.py and tests/test_mlflow_tracing.py:

    import asyncio

from atfgraph import Agent
from atfgraph import mlflow as tracing

app = Agent(node_id="trace-node", version="1.0.0")


@tracing.trace(kind="tool")
async def score(nights: int) -> float:
    await asyncio.sleep(0.01)
    return nights * 1.5


@app.traversal()
async def plan(city: str, nights: int) -> dict:
    with tracing.span("lookup", kind="retriever", attributes={"atfgraph.city": city}) as live:
        if live is not None:
            live.set_attribute("rates", 3)
    return {"city": city, "score": await score(nights)}


if __name__ == "__main__":
    tracing.enable(app, tracking_uri="sqlite:///./data/mlflow.db")
    app.run()

    enable(app) returns False after one warning when mlflow is not installed. It wraps every registered handler (and handlers registered later), app.traverse, app.ai, app.harness and app.record_usage on that Agent instance; each worker task becomes one trace tagged with atfgraph.root_id, atfgraph.node, atfgraph.capability and atfgraph.session_id. The root step writes mlflow_trace_id (and mlflow_experiment_url for browsable stores) into the run metadata under its lease; a failure is counted in tracing.stats()["metadata_failed"] and never reaches the handler. Inputs and outputs are not recorded unless you pass capture_inputs/capture_outputs (with an optional redact callback). tracing.enable_from_env(app) activates from ATFGRAPH_MLFLOW_TRACING=true; call tracing.flush() before a process exits. Configuration, span types and the bridge for runs traced elsewhere are in ../mlflow.md.

    OpenTelemetry export

    atfgraph.otel is the OpenTelemetry sibling of the MLflow module, for teams whose traces live in Grafana Tempo, Honeycomb, Datadog or any OTLP collector rather than in MLflow. It is optional (pip install './python[otel]'), import atfgraph never imports opentelemetry, and it never installs a global tracer provider. Adapted from python/atfgraph/otel.py and tests/test_otel.py:

    from atfgraph import Agent
from atfgraph import otel

app = Agent(node_id="trace-node", version="1.0.0")


@app.traversal()
async def plan(city: str, nights: int) -> dict:
    with otel.span("lookup", attributes={"atfgraph.city": city}):
        return {"city": city, "nights": nights}


if __name__ == "__main__":
    otel.enable(app, endpoint="http://localhost:4318", service_name="atfgraph.trace-node")
    app.run()

    enable(app) wraps the same points the MLflow module wraps: every handler becomes a SERVER span carrying atfgraph.node, atfgraph.capability, atfgraph.traverser_id, atfgraph.root_id, atfgraph.session_id, atfgraph.attempt and atfgraph.kind; app.traverse opens a CLIENT child span and the child step joins the same trace through a W3C traceparent; app.ai spans carry gen_ai.request.model, and recorded usage adds gen_ai.usage.input_tokens, gen_ai.usage.output_tokens and atfgraph.usage.cost_usd. The root step forwards otel_trace_id and otel_traceparent into run metadata, so the console's run detail links the two systems. otel.enable_from_env(app) activates from ATFGRAPH_OTEL_TRACING=true with the standard OTEL_EXPORTER_OTLP_ENDPOINT, OTEL_EXPORTER_OTLP_HEADERS and OTEL_SERVICE_NAME variables (atfgraph.<node_id> by default); Agent.serve calls it, so an installed node needs only those variables in its package .env. ATFGRAPH_OTEL_CAPTURE_PAYLOADS=true records inputs and outputs; otel.flush() drains the exporter before a process exits; otel.stats() reports spans, failures and forwarded metadata.
