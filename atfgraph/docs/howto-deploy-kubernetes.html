    Deploy to Kubernetes, Helm or Databricks

    Problem: you want the graph server and workers on a cluster or in a Databricks workspace rather than on one machine.

    These targets are applied with their own tools; the CLI validates and scaffolds but does not manage their state the way it does for Compose. The rendered files live under deploy/.

    Kubernetes with kustomize

    kubectl -n atfgraph-vnext apply -k deploy/kubernetes/base

    deploy/kubernetes/base renders a ServiceAccount, the graph server and a worker Deployment; deploy/kubernetes/overlays holds environment variants. The worker reads its API key from a Secret named atfgraph-vnext-api, key api-key.

    Helm

    helm install atfgraph deploy/helm/atfgraph-vnext -n atfgraph-vnext --set auth.existingSecret=atfgraph-api

    Databricks

    scripts/product/build-databricks-bundle.sh
# then, from target/dist/databricks/<label>:
databricks bundle deploy -t dev --profile <PROFILE> --var server_app_name=<graph-server App> --var api_key_scope=<SCOPE>

    The bundle runs the worker as a Databricks App. It binds the graph server's own App with CAN_USE, discovers its URL at start and sends the App's workspace OAuth token as the edge credential (Authorization) with the ATFGraph key from the secret scope as X-API-Key. For a graph server on Kubernetes or Compose instead, replace the graph-server resource and the ATFGRAPH_SERVER_APP entry in the built databricks.yml with a static ATFGRAPH_SERVER URL and deploy with --var edge_auth=none. Pass the workspace profile explicitly; nothing here selects one for you. Details: deploy/databricks/README.md.

    Kubernetes files for your own node

    atfg deploy scaffold ./my-node --label my-node --module my_node:app --target kubernetes
    wrote my-node/k8s/deployment.yaml
wrote my-node/k8s/kustomization.yaml
next: build the image, create secret atfgraph-vnext-api with key api-key, then `kubectl apply -k k8s/`.

    Validate before applying

    atfg deploy validate --path deploy --target kubernetes
atfg deploy validate --path deploy --target helm --require-tools

    validate runs kubectl kustomize, helm lint and helm template locally. No cluster or registry is contacted. Tools that are not on PATH are skipped unless --require-tools is given.

    Readiness

    Every target uses GET /health for server readiness and node-healthcheck.py (the server lists the label) for worker readiness, and requires an API key because the daemon listens on 0.0.0.0 inside a container.
