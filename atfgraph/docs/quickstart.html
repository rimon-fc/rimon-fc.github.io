    Quickstart

    Ten minutes from a source checkout to a traverser with a recorded path, seen in the web console. You need a Rust toolchain, Node 22 (for the console) and Python 3.10 or newer; the system python3 on macOS is 3.9 and will not do.

    Using a managed graph server instead? You do not build anything: the release's install.sh --from github:fclimited/ai-lab-atfgraph@vnext-<version> installs the atfg CLI, the SDK and the skills from the GitHub Release into a prefix you own, then atfg login <url> connects you. See Install. The rest of this page runs everything on your laptop, which is what you want while changing code.

    ATFGraph vNext is one repository: the graph server atfgraphd, the atfg CLI and the web console (Rust and TypeScript) beside the atfgraph Python package (python/), the examples, the guides and the skills.

    1. Build the server and the console

    git clone https://github.com/fclimited/ai-lab-atfgraph.git
cd ai-lab-atfgraph
cargo build --bin atfgraphd --bin atfg          # about five minutes the first time
(cd ui && npm ci && npm run build)              # the console; the daemon serves ui/dist at /ui/
export PATH="$PWD/target/debug:$PATH"

    2. Start the graph server

    atfg server start
    ATFGraph vNext started: pid 77649 listening on 127.0.0.1:18880 (log …/.atfgraph-vnext/server-127.0.0.1-18880.log)
API http://127.0.0.1:18880/api/v2  UI http://127.0.0.1:18880/ui/

    Loopback without an API key is development mode. Nothing else is needed. Open http://127.0.0.1:18880/ui/ now: the console is empty until a node registers.

    2b. Install the SDK

    python3 -m venv .venv
.venv/bin/python -m pip install -e 'python[test]'

    3. Run an agent node

    In a second terminal, from the checkout, with target/debug on PATH:

    cd ai-lab-atfgraph
export PATH="$PWD/target/debug:$PATH"
atfg dev --module examples.python.first_node.agent:app --python .venv/bin/python --expect-label hello

    The node is one file, examples/python/first_node/agent.py: a traversal greet that calls a skill shout. atfg dev checks that the interpreter can import atfgraph, starts the worker attached to your terminal, and reports when the label hello is registered. Leave it running.

    4. Start a traverser

    Back in the first terminal:

    atfg ls
    LABEL  VERSION  ELEMENT      KIND       TIMEOUT  ATTEMPTS
hello  1.0.0    hello.greet  traversal  300s     1
hello  1.0.0    hello.shout  skill      300s     1
    atfg traverse hello.greet --in '{"name":"Ada"}'
    traverser 8d2efb59-8a42-4087-bc80-d9b04b4b2b4d queued; waiting at the barrier (up to 300s)
traverser 8d2efb59-8a42-4087-bc80-d9b04b4b2b4d succeeded (hello.greet)
{
  "greeting": "Hello Ada!",
  "length": 3,
  "shouted": "HELLO ADA"
}

    5. Read the path

    atfg path 8d2efb59-8a42-4087-bc80-d9b04b4b2b4d
    path of traverser 8d2efb59-8a42-4087-bc80-d9b04b4b2b4d (root 8d2efb59-8a42-4087-bc80-d9b04b4b2b4d)
#  STEP                                  TARGET       STATUS     ATTEMPT  PARENT                                ELAPSED
1  0a108d2b-e768-483a-bde9-f5ab3208bedb  hello.greet  succeeded  1        -                                     314ms
2  f6ea3c4a-b8e1-448c-b12c-2183ebe762be  hello.shout  succeeded  1        0a108d2b-e768-483a-bde9-f5ab3208bedb  6ms

    Two steps: the traversal you called, and the skill it called through the graph server. In the console, Runs lists the same traverser; open it for the path, the events and the usage.

    6. Stop

    Press Ctrl-C in the worker terminal, then, from either checkout:

    atfg server stop

    The server's SQLite file (data/graph.db under the server checkout) and its pid/log files (~/.atfgraph-vnext/) remain; delete them to start clean. atfg server status reports what is running.
