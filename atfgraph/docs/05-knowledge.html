Type to search.

    Document knowledge

    By the end of this page you will be able to store text documents in a memory scope, search them with BM25 and return passages that carry stable citations, page through a corpus, delete with compare-and-set, and decide when vector memory or the semantic layer is the better tool. It requires only the SDK and a running graph server; the features/knowledge example needs no model provider because every answer is built from stored text.

    What the knowledge store is

    app.knowledge is a Knowledge facade (python/atfgraph/knowledge.py) bound to the global scope of the caller's namespace. It talks to the seven POST /api/v2/knowledge/{put,put-batch,get,list,delete,search,stats} operations on the graph server. The server chunks the text, indexes the chunks and ranks them with BM25; the SDK validates every request against the server bounds before any I/O, so a bad doc_id or an oversize text fails locally with ValueError.

    Ownership follows the memory model exactly: the server derives the namespace from authentication, and inside a traversal every request carries the task's lease so session and workflow resolve to the running traverser. Read 04-sessions-and-memory.md for the scopes themselves.

    Two facts shape everything below:

    • Retrieval is lexical. BM25 ranks chunks by the query terms they contain. A query for "luggage" does not find a chunk that only says "baggage".
    • Every hit has a citation doc_id#ordinal that stays valid until the document is rewritten. That is what makes an answer checkable.

    Ingest documents

    put writes one document; put_many writes up to 100 atomically. Pass text and let the server chunk it, or pass chunks you split yourself. The node in examples/python/features/knowledge/agent.py exposes the batch write as a traversal:

    from __future__ import annotations

from typing import Any, Dict, List

from atfgraph import Agent
from atfgraph.knowledge import Knowledge

app = Agent(node_id="knowledge_desk", version="1.0.0", description="Document knowledge with cited BM25 retrieval")

knowledge = Knowledge(lambda: app.client)


@app.traversal()
async def ingest(documents: List[Dict[str, Any]]) -> dict:
    """Write documents atomically. Each item: ``doc_id``, ``title``, ``metadata`` and
    ``text`` or ``chunks``."""
    result = await knowledge.put_many(documents)
    return {
        "documents": result.documents,
        "chunks": result.chunks,
        "items": [{"doc_id": item.doc_id, "revision": item.revision, "chunks": item.chunks, "created": item.created} for item in result.items],
    }

    Knowledge(lambda: app.client) is the same object as app.knowledge; the example constructs it explicitly so the module reads on its own. The documents it ingests come from examples/python/features/knowledge/fixtures.py. One uses server chunking, the other supplies chunks with page numbers and chunk metadata:

    from __future__ import annotations

from typing import Any, Dict, List

DOCUMENTS: List[Dict[str, Any]] = [
    {
        "doc_id": "policy:refunds",
        "title": "Refund policy",
        "metadata": {"kind": "policy", "owner": "finance"},
        "text": (
            "Refunds are issued to the original form of payment within 14 days of approval. "
            "Refund fees apply to non-flexible fares; flexible fares are refunded in full."
        ),
    },
    {
        "doc_id": "policy:baggage",
        "title": "Baggage allowance",
        "metadata": {"kind": "policy", "owner": "operations"},
        "chunks": [
            {"text": "Checked baggage allowance is 23 kg per passenger on domestic sectors and 30 kg on international sectors.", "page": 1},
            {"text": "Excess baggage fees apply above the allowance and are charged per kilogram at the airport.", "page": 2, "metadata": {"section": "fees"}},

]

    The keys put_many accepts per item are exactly doc_id, text or chunks, title, metadata, chunk_size, chunk_overlap and expected_revision; anything else raises ValueError before the request is sent. Duplicate doc_id values in one batch are rejected the same way.

    Limits and chunking

    BoundValueWhere it fails
    doc_id1–256 printable characters, no control charactersclient
    titleup to 512 charactersclient
    text per document1 MiBclient
    chunk text32 KiB each, at most 2000 per documentclient
    batch1–100 documents, unique doc_idclient
    chunk_size64–8000 characters, default 1200client
    chunk_overlap0 to half of chunk_size, default 100client
    query1–2048 charactersclient
    top_k1–100client
    offset0–10000client

    chunk_size and chunk_overlap apply to text ingestion only; passing them with chunks raises. chunk_text(text, size, overlap) (exported from atfgraph) runs the same algorithm as the server so you can preview where citations will fall before ingesting; the server split remains authoritative (tests/test_knowledge.py::test_chunk_text_mirrors_the_server_rules).

    Text and queries are normalised to Unicode NFC before they are sent (normalize=True), so composed and decomposed spellings index and match identically. Pass Knowledge(lambda: app.client, normalize=False) to send text verbatim.

    Replace and compare-and-set

    put on an existing doc_id replaces the document and bumps its revision. Pass expected_revision= to make the write conditional: 0 means "create only", any other value must equal the live revision or the server answers ConflictError. delete(doc_id, expected_revision=...) behaves the same way and returns False when the document was already gone (tests/test_knowledge.py::test_real_daemon_knowledge_routes).

    Search with citations

    search(query, top_k=, offset=, filters=, doc_id=, min_score=) returns a KnowledgeSearchResult. items are KnowledgeHit objects ordered by score descending, then doc_id, then ordinal, so the ranking is deterministic. filters match document metadata exactly; doc_id restricts the search to one document. Adapted from the ask traversal in examples/python/features/knowledge/agent.py:

    from __future__ import annotations

from typing import List, Optional

from pydantic import BaseModel, Field

from atfgraph import Agent
from atfgraph.knowledge import Knowledge

app = Agent(node_id="knowledge_desk", version="1.0.0")
knowledge = Knowledge(lambda: app.client)


class Passage(BaseModel):
    citation: str
    title: str
    text: str
    score: float
    page: Optional[int] = None
    matched_terms: List[str] = Field(default_factory=list)


class Answer(BaseModel):
    question: str
    terms: List[str]
    passages: List[Passage]
    total: int
    scanned: int


@app.traversal()
async def ask(question: str, top_k: int = 5, kind: Optional[str] = None) -> Answer:
    result = await knowledge.search(question, top_k=top_k, filters={"kind": kind} if kind else None)
    return Answer(
        question=question,
        terms=result.terms,
        passages=[
            Passage(citation=hit.citation, title=hit.title, text=hit.text, score=hit.score, page=hit.page, matched_terms=hit.matched_terms)
            for hit in result.items
        ],
        total=result.total,
        scanned=result.scanned,
    )

    Against the real daemon, search("refund fees", top_k=3) on the fixture documents reports terms == ["refund", "fees"], the first hit is policy:refunds#0 and its matched_terms are ["fees", "refund"] (test_real_daemon_knowledge_routes). total is the number of matching chunks after filters, scanned the number before, corpus_chunks the size of the scope, and next_offset is set while more pages exist.

    Three helpers on the result save prompt-building code:

    • result.citations() is the list of doc_id#ordinal strings.
    • hit.reference() renders Refund policy (policy:refunds#0) or (b#2, p. 4) when a page is known.
    • result.context(max_chars=6000) renders numbered [n] reference passages and cuts on passage boundaries, so a citation never points at truncated text.

    The example's extractive_answer shows what a cited answer looks like without a model: it picks the sentences covering the most query terms and tags each with the [n] of its passage. When a model does write the answer, the pattern in examples/python/docs_assistant/main.py applies: reject any citation_ids the model returns that were not in the retrieved set.

    Paging through a ranking

    search_all(query, page_size=100, max_results=10000) is an async iterator that walks the ranking through offset pages in the same deterministic order, so iterating it yields the same citations as one search(..., top_k=100) (test_example_node_runs_end_to_end_through_the_contract_double).

    Scopes and layered knowledge

    app.knowledge.scope("session"), .scope("actor") and .scope("workflow") return siblings bound to another scope. Inside a traversal, session and workflow without ids resolve to the running traverser's session and root on the server; outside one, pass session_id= or root_id=. Knowledge.search_across([session_kb, kb], query, top_k=5) queries several scopes and merges by score, then scope order, doc_id and ordinal. The scores come from separate corpora and are comparable only approximately; each merged hit carries its scope label so you can tell them apart. From the same test:

    from __future__ import annotations

import asyncio
import os

from atfgraph import Client
from atfgraph.knowledge import Knowledge


async def main() -> None:
    async with Client(os.getenv("ATFGRAPH_SERVER")) as client:
        kb = Knowledge.for_client(client)
        session_kb = kb.scope("session", session_id="se_demo")
        await session_kb.put("note", "Traveller prefers refund to voucher.", title="Session note")
        merged = await Knowledge.search_across([session_kb, kb], "refund voucher lounge", top_k=5)
        for hit in merged.items:
            print(hit.scope, hit.reference(), round(hit.score, 3))


if __name__ == "__main__":
    asyncio.run(main())

    Knowledge.for_client(client) is the constructor to use from a script or test that has a bare Client; inside a node use app.knowledge.

    Catalog, statistics and deletion

    stats() returns a KnowledgeStats for one scope: documents, chunks, tokens, terms, postings, average_chunk_tokens, strategy == "bm25" and the server's limits. list(prefix=, cursor=, limit=) returns one page of KnowledgeDocumentSummary rows in doc_id order with a next_cursor; documents(prefix=, page_size=) follows the cursors for you. get(doc_id, include_chunks=True) returns the stored document with its chunks and citations, or found == False. The catalog and forget traversals in examples/python/features/knowledge/agent.py combine them:

    from __future__ import annotations

from atfgraph import Agent
from atfgraph.knowledge import Knowledge

app = Agent(node_id="knowledge_desk", version="1.0.0")
knowledge = Knowledge(lambda: app.client)


@app.traversal()
async def catalog() -> dict:
    stats = await knowledge.stats()
    documents = [
        {"doc_id": item.doc_id, "title": item.title, "chunks": item.chunks, "revision": item.revision, "metadata": item.metadata}
        async for item in knowledge.documents(page_size=100)
    ]
    return {"documents": stats.documents, "chunks": stats.chunks, "terms": stats.terms, "strategy": stats.strategy, "items": documents}


@app.traversal()
async def forget(doc_id: str) -> dict:
    return {"doc_id": doc_id, "deleted": await knowledge.delete(doc_id)}

    examples/python/docs_assistant/main.py uses the same documents(prefix="docs:<namespace>:") listing to find and delete every document of one namespace, which is the pattern for bulk deletion: there is no delete-by-prefix operation.

    Run the example

    Start a worker and the driver from this repository's root, with ATFGRAPH_SERVER pointing at your graph server. Nothing else needs to be configured.

    python -m atfgraph.worker --module examples.python.features.knowledge.agent:app
python -m examples.python.features.knowledge.call

    tests/test_knowledge.py::test_real_daemon_knowledge_routes runs the same helpers against atfgraphd with the fixture from 15-testing.md. The same file also defines KnowledgeFakeServer, an in-memory BM25 double built on atfgraph.testing.FakeGraphServer; it exists for fast SDK unit tests only, and the real-daemon test is the check that a node works.

    When to use vector memory instead

    The knowledge store is the right place for text you want to quote back with a citation. Vector memory (app.memory.set_vector, get_vector, delete_vector, similarity_search and search on Memory and MemoryScope, described in 04-sessions-and-memory.md) stores one embedding per key with metadata and ranks by cosine similarity; it holds no text and produces no citation, and you bring the embeddings.

    NeedUse
    Quote a passage with a checkable locatorapp.knowledge
    Exact-term or identifier lookup (booking codes, error strings)app.knowledge
    Match meaning across different wordingvector memory, or the semantic layer below
    Rank arbitrary embedded items (not text chunks)vector memory

    When you want both, kb.semantic(EmbeddingConfig(provider=..., model=...)) returns a SemanticKnowledge that writes the document to the knowledge store first, then embeds the server's chunks into the same scope's vector memory under keys kb:<index>:<doc_id>#<ordinal>. Its search(query, mode="hybrid" | "semantic" | "lexical") fuses BM25 and cosine rankings by reciprocal rank and re-reads every semantic hit against the live document revision, dropping stale vectors. Embeddings come only from the provider you configure: http_embedding_provider(url, model, api_key=...) for an OpenAI-compatible endpoint, or any callable that maps a list of texts to a list of vectors. examples/python/features/retrieval/agent.py selects the provider from ATFGRAPH_EMBEDDING_URL and ATFGRAPH_EMBEDDING_MODEL and otherwise falls back to a deterministic local lexicon embedder so it runs offline; examples/python/retrieval_basics and examples/python/docs_assistant are built on the same layer. The semantic layer is covered by tests/test_semantic_knowledge.py.

    Not verified: search behaviour in the actor scope against the real daemon. tests/test_knowledge.py exercises global and session end to end and pins the actor request body only over a mock transport; confirming it needs a run of kb.scope("actor").put(...) and .search(...) against atfgraphd.
