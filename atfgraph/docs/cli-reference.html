    `atfg` command reference

    Command reference for atfg 0.3.15 (ATFGraph vNext). Use atfg <command> --help for help in your terminal.

    ATFGraph vNext: start the graph server, list elements, start traversers, wait at the barrier, read paths.

    Usage: atfg [OPTIONS] <COMMAND>

    Commands

    • atfg server — Start, inspect or stop the sibling atfgraphd graph server
      • atfg server start — Start atfgraphd from the same directory as this binary
      • atfg server status — Report pid metadata, process state and /health for a server started by this CLI
      • atfg server stop — Stop a server started by this CLI. Only the recorded pid is signalled, and only if it is still atfgraphd
    • atfg ls — List elements: every traversal and skill registered on the graph
    • atfg ps — List traversers known to the graph server
    • atfg traverse — Start a traverser on label.capability and print its result
    • atfg wait — Block at the barrier until a traverser reaches a terminal state
    • atfg cancel — Cancel a traverser and its children
    • atfg path — Print the recorded path of a traverser: every step and attempt
    • atfg share — Export a recorded path as a self-contained, offline file you can keep or send
    • atfg show — Show one traverser
    • atfg config — Validate a graph server configuration file
      • atfg config validate — Check a YAML configuration against the vNext contract shape
    • atfg dev — Run a Python agent node worker against a local graph server
    • atfg install — Install an agent node package (directory, .tar.gz artifact or git URL with agentnode.yaml) into an isolated venv
    • atfg run — Start an installed agent node as a detached outbound worker and wait until its label is registered
    • atfg stop — Stop a worker started by atfg run: SIGTERM the recorded pid after checking it is that worker; it drains first
    • atfg logs — Show a worker's log written by atfg run
    • atfg list — List installed agent node packages with process and registration state
    • atfg uninstall — Remove an installed package (refuses while its worker runs)
    • atfg package — Build a local .tar.gz artifact with SHA-256 checksums and version metadata from an agent node project
    • atfg login — Save a graph server, its API key and edge settings to the shared credentials file
    • atfg logout — Remove one saved graph server (default: the current one). Other entries are untouched
    • atfg whoami — Show the resolved server, key prefix and edge settings, where each came from, and whether the server accepts them
    • atfg doctor — Inspect this machine: binaries, Python SDK, container/cluster tools and the graph server
    • atfg migrate — Migrate history, back up, verify or restore a store. Run atfg migrate --help for tool options
    • atfg skill — Install a bundled coding skill into a coding harness (Claude Code or Codex)
      • atfg skill install — Install one bundled skill; scripts/install-skills.py does the copying and ownership checks
    • atfg docs — Serve the documentation site on the loopback address and open it in the browser
    • atfg deploy — Validate, scaffold or manage deployments
      • atfg deploy validate — Run the local validation commands for the deployment files (no cluster or registry is contacted)
      • atfg deploy scaffold — Write Dockerfile, Compose or Kubernetes files for a Python agent node worker
      • atfg deploy compose — Manage a local Docker Compose deployment: desired state on disk, observed state from Docker and the graph server
      • atfg deploy compose up — Create or re-apply a deployment: docker compose up --wait, then verify /health and node registration
      • atfg deploy compose status — Observe containers, health and registered labels; exit 3 when they differ from the desired state
      • atfg deploy compose logs — Print container logs of the deployment
      • atfg deploy compose down — Stop and remove the deployment's containers and network; --volumes also removes its data volume
      • atfg deploy compose rollback — Re-apply the previous successfully deployed image tag
      • atfg deploy list — List deployments recorded by this CLI

    Global options

    Accepted by every command; each command's own help repeats them under Global:, and that repeated section is omitted from the help blocks below.

    OptionDescription
    -s, --server <SERVER>Graph server URL [env: ATFGRAPH_SERVER=] [default: http://127.0.0.1:18880]
    -k, --api-key <API_KEY>API key sent as the X-API-Key header. Omit for loopback development without keys [env: ATFGRAPH_API_KEY]
    --edge-auth <EDGE_AUTH>Edge credential for a platform proxy in front of the graph server. databricks sends a workspace OAuth token as Authorization; the API key stays in X-API-Key [env: ATFGRAPH_EDGE_AUTH=] [default: none] [possible values: none, databricks]
    --databricks-profile <DATABRICKS_PROFILE>Databricks CLI profile for --edge-auth databricks. Always explicit; never auto-selected [env: ATFGRAPH_DATABRICKS_PROFILE=]
    --jsonPrint raw JSON instead of tables
    --timeout <TIMEOUT>HTTP request timeout in seconds [default: 30]
    --state-dir <STATE_DIR>Directory for pid metadata and daemon logs written by atfg server [env: ATFGRAPH_VNEXT_HOME=]

    Start, inspect or stop the sibling `atfgraphd` graph server

Usage: atfg server [OPTIONS] <COMMAND>

Commands:
  start   Start `atfgraphd` from the same directory as this binary
  status  Report pid metadata, process state and `/health` for a server started by this CLI
  stop    Stop a server started by this CLI. Only the recorded pid is signalled, and only if it is still `atfgraphd`
  help    Print this message or the help of the given subcommand(s)

Options:
  -h, --help     Print help
  -V, --version  Print version

Arguments:
  <TARGET>  Target in the form `label.capability`

Options:
      --in <JSON>
          JSON input document
      --in-file <PATH>
          Read the JSON input document from a file (`-` for stdin)
      --node-version <VERSION>
          Pin the agent node version (the contract's optional `version` field)
      --session <SESSION>
          Attach the traverser to a session (created with `atfg traverse --new-session`)
      --new-session
          Create a session first and attach the traverser to it
      --idempotency-key <IDEMPOTENCY_KEY>
          Idempotency key for safe retries
      --async
          Return immediately with the traverser id instead of waiting at the barrier
      --wait-timeout <WAIT_TIMEOUT>
          Seconds to wait when not `--async` (exit code 2 on timeout) [default: 300]
  -h, --help
          Print help
  -V, --version
          Print version

  up        Create or re-apply a deployment: `docker compose up --wait`, then verify `/health` and node registration
  status    Observe containers, health and registered labels; exit 3 when they differ from the desired state
  logs      Print container logs of the deployment
  down      Stop and remove the deployment's containers and network; `--volumes` also removes its data volume

  help      Print this message or the help of the given subcommand(s)
