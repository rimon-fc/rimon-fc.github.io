    API reference: what each area is for

    The operation tables, schemas and examples are generated from contracts/openapi-v2.json every time the site is built, so they are always the contract as it stands. This page is the hand-written part: what each area is for and when you would reach for it. Each heading links to that area's generated page.

    Base URL: http://127.0.0.1:18880/api/v2. Every response that is not a success is an error envelope:

    {"error":{"code":"traverser_not_found","message":"unknown traverser"},"request_id":"c9ec0e4b-08a4-44d6-aff0-4f46eb76889f"}

    Authentication is a bearer token in Authorization. Roles are admin, invoke and worker; admin implies the others. On loopback with no tokens configured the server runs in development mode and accepts unauthenticated requests. Quote the request_id when you report a problem.

    Starting and reading work

    Traversers

    Start a traverser on label.capability, read one back, list them with status, session, time-window and cursor paging, read the recorded path, cancel and restart. This is the area a client application uses most. See Start a traverser.

    Events

    The durable event log of one traverser, as a snapshot or a stream. Use it to follow progress while a traverser is live; the console's live rail is built on it.

    Sessions

    Create a session that many traversers share, so a conversation keeps its memory across calls. atfg traverse --new-session calls this for you.

    Approvals

    A traversal asks for a human decision and the traverser waits in status waiting. List the open requests and decide them.

    What is registered

    Discovery

    The server description (GET /api/v2/server), the registered agent nodes and their capabilities, and the agent-resource-discovery publications and search under /api/v2/ard. atfg ls reads this area.

    Admin

    Register an agent node definition. The worker does this at startup; registration is immutable per version.

    Worker

    The outbound worker protocol: enrol, claim, renew a lease, report progress, complete, drain. You call this only if you write a worker in another language. GET /api/v2/workers is the fleet view for operators; see Monitor over HTTP.

    State a traverser can use

    Memory

    Key-value state in the global, session, actor and workflow scopes, with compare-and-set revisions and a change feed.

    Knowledge

    Documents per scope with server-side chunking and lexical BM25 search that returns citations. Not an embedding store; use memory vectors for similarity.

    Checkpoints

    Named, revisioned state a live traverser writes and reads back, so a long traversal can resume after a retry.

    Artifacts

    Files a traverser produced or consumed: upload, list, download, delete.

    Operating the server

    Observability

    Usage accounting, node logs, traverser metadata, the observability webhook, GET /api/v2/stats for server-wide counts and GET /api/v2/model-health for model endpoint circuit state.

    RuntimeSettings

    Per-namespace stored documents: list, read, write, delete a key, then apply it to the running process. Saving and applying are separate calls.

    Emitters

    Scheduled and event-driven sources that start traversers without a caller, plus their delivery log and replay.

    Retention

    Preview and then apply pruning of old traversers, events and logs. Preview first; the console does.

    Health

    GET /health, unauthenticated liveness. Every deployment target probes it.

    Identity and access

    Access

    Access policies and connector grants: who may start which traversals, and which external connectors a namespace may reach.

    Credentials

    Node identity enrolment, credential issuance and verification, revocation and the tag ledger. Keys never leave the graph server.

    Identity

    Node identities, signed paths and offline proof verification.
