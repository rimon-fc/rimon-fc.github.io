    MLflow tracing (optional, developer opt-in)

    atfgraph.mlflow adds MLflow Tracing to an agent without changing how it is written or registered. It is off unless you turn it on, import atfgraph never imports mlflow, and no tracking server is contacted unless you name one. The optional dependency supports MLflow versions >=3.11,<4.

    python -m pip install './python[mlflow]'

    From configuration alone

    Agent.serve() (and therefore app.run() and atfg run) calls enable_from_env(app) before the first claim, so a node needs no code change to be traced: set ATFGRAPH_MLFLOW_TRACING=true and a tracking URI in the worker's environment or its package .env. For Databricks:

    ATFGRAPH_MLFLOW_TRACING=true
MLFLOW_TRACKING_URI=databricks
DATABRICKS_HOST=https://<workspace>.cloud.databricks.com
DATABRICKS_TOKEN=<personal access token>            # or DATABRICKS_CONFIG_PROFILE=<profile>
ATFGRAPH_MLFLOW_EXPERIMENT=/Shared/atfgraph/co-consult   # optional; this is the default for that node

    mlflow must be installed in the node's environment (pip install './python[mlflow]', or mlflow>=3.11,<4 into the package venv); without it the worker logs one warning and runs untraced. Inputs and outputs are not captured unless ATFGRAPH_MLFLOW_CAPTURE_PAYLOADS=true.

    Three ways in, all combinable

    from atfgraph import Agent
from atfgraph import mlflow as tracing

app = Agent(node_id="pricing")

@app.traversal()
async def quote(city: str, nights: int) -> dict:
    with tracing.span("lookup-rates", kind="retriever") as s:   # 1. context manager
        rates = await load_rates(city)
        if s is not None:
            s.set_attribute("rates", len(rates))
    total = await price(rates, nights)                          # helper below
    breakdown = await app.traverse("pricing.breakdown", total=total)
    return {"total": total, **breakdown}

@tracing.trace(kind="tool")                                     # 2. decorator (helpers or handlers)
async def price(rates: dict, nights: int) -> float: ...

@app.skill()
@tracing.trace()                                                # on a handler: keeps the schema, span type from the registration
def breakdown(total: float) -> dict: ...

if __name__ == "__main__":
    tracing.enable(app, tracking_uri="sqlite:///./data/mlflow.db")  # 3. instrument the whole agent
    app.run()

    enable(app) (or python -m atfgraph.mlflow --module pkg:app --tracking-uri ..., which takes every atfgraph.worker argument) wraps, on this Agent instance only:

    WhatSpanTypeNotes
    every registered handler, and handlers registered later<node>.<capability>AGENT (traversal) / TOOL (skill)the root span of the task's trace
    await app.traverse(...)traverse <label.capability>CHAINatfgraph.child.traverser_id once submitted; the child's spans hang under it
    await app.ai(...)aiLLMapp.record_usage adds mlflow.chat.tokenUsage, mlflow.llm.model/provider, atfgraph.usage.cost_usd when the provider priced the call
    await app.harness(...)harnessCHAINprovider, model, return code, duration

    with tracing.span(...)as namedkind= (default TOOL)MLflow's LiveSpan, or None while tracing is off

    kind accepts the friendly names in tracing.SPAN_KINDS (tool, chain, agent, llm, retriever, embedding, parser, memory, workflow, task, guardrail) or any MLflow SpanType verbatim. Decorator order: @app.traversal() stays outermost so the signature-derived input schema is unchanged; instrument recognises a @trace-decorated handler and does not wrap it twice.

    This is manual instrumentation with an instance-level hook, not mlflow.autolog(): model providers called through app.ai are covered by the ai span, but a framework you call directly (LangChain, OpenAI SDK, …) is only traced if you enable that framework's own mlflow.<framework>.autolog() yourself; its spans then nest under the handler span because the context is shared.

    What a trace carries

    Attributes on every span (fixed set, never a lease token, API key or worker credential): atfgraph.node, atfgraph.version, atfgraph.capability, atfgraph.kind, atfgraph.traverser_id, atfgraph.step_id, atfgraph.root_id (and its alias atfgraph.run_id), atfgraph.attempt, atfgraph.is_root, atfgraph.session_id, atfgraph.parent_id, atfgraph.worker_id, and for emitter deliveries atfgraph.trigger.source / atfgraph.trigger.event_type.

    Trace tags (tracing.TRACE_TAG_KEYS): atfgraph.node, atfgraph.capability, atfgraph.traverser_id, atfgraph.root_id, atfgraph.session_id; the session also becomes MLflow's own session (mlflow.trace.session), so the MLflow UI groups a conversation. Find everything about one traverser tree:

    mlflow.search_traces(locations=[experiment_id], filter_string="tag.atfgraph.root_id = '<root id>'")

    Nesting, concurrency, threads, cancellation

    MLflow rides on OpenTelemetry's contextvars, which the worker already uses for the traverser context: concurrent handlers in one worker never see each other's spans, and a synchronous handler running in asyncio.to_thread inherits its parent. A child traverser claimed by the same process joins its parent's trace under the traverse span (link_children="process", the default; nothing leaves the process). link_children="metadata" also writes the W3C traceparent of the root step into the root traverser's metadata (mlflow_traceparent) and a child claimed by another worker process reads it under its lease and joins too (one GET .../metadata per child task). link_children=False keeps every task in its own trace; they stay related by tag.

    When the graph server cancels a task or the lease is lost, the handler's span ends with status ERROR, description cancelled: CancelledError and atfgraph.cancelled = true, and the cancellation keeps propagating. (MLflow's own context manager records only Exception subclasses and would have closed the span OK.)

    Payloads are opt-in

    Nothing about inputs or outputs is recorded by default. Turn it on per process (enable(capture_inputs=True, capture_outputs=True), ATFGRAPH_MLFLOW_CAPTURE_INPUTS, _OUTPUTS, or the retained ATFGRAPH_MLFLOW_CAPTURE_PAYLOADS for both) or per function (@tracing.trace(capture_inputs=True)). Captured values pass through redact first:

    def redact(value):
    if isinstance(value, dict):
        return {k: "[redacted]" if "secret" in k or "token" in k else redact(v) for k, v in value.items()}
    return value

tracing.enable(app, capture_inputs=True, capture_outputs=True, redact=redact)

    Inputs are the handler's bound arguments (inspect.signature), outputs its return value; app.ai records user/system/messages/context and the response, app.harness the prompt and the text. The worker's lease token, the API key and the MLflow tracking credentials are never in scope of any capture.

    Link traces to traversers

    The root step writes mlflow_trace_id and mlflow_experiment_url both keys through app.observability.set_run_metadata(...) under its own lease as soon as its span opens (forward_run_metadata=True, default; bounded by forward_timeout=5.0). experiment_url is only set for browsable stores (an HTTP tracking server or Databricks; SQLite and file stores have none). A failure is counted in tracing.stats()["metadata_failed"], logged once, and never reaches the handler. Synchronous handlers hand the write to the agent's event loop.

    Read it back like any traverser metadata:

    meta = await app.observability.run_metadata(root_id)
meta.mlflow_trace_id, meta.mlflow_experiment_url

    For traversers traced elsewhere (plain @mlflow.trace with an atfgraph.root_id tag, or a process without lease authority) the bridge in integrations/mlflow (../integrations/mlflow/README.md) writes the same keys from outside a worker, and keeps MLflow traces tagged with the traverser's status, target, usage totals and API URL.
