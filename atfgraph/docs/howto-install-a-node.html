    Package, install and run an agent node

    Problem: you have a node as a directory, archive or git repository and want it running as a detached worker on this machine, restartable, with logs.

    atfg dev (see the Quickstart) runs a node attached to your terminal. This page is the installed, detached alternative.

    The manifest: agentnode.yaml

    An installable node is a directory (or git repository, or atfg package artifact) with agentnode.yaml at its root. The shape is config_version: v2; vNext reads the same fields and adds one additive key, entrypoint.module. Either of these tells the worker what to load:

    config_version: v2
name: hello                       # package name and default label
version: 1.0.0
description: Greets travellers
entrypoint:
  start: python -m atfgraph.worker --module hello_node.agent:app   # compatible form
  # module: hello_node.agent:app                                  # or the additive key
agent_node:
  node_id: hello                  # label if it differs from name
dependencies:
  python: [pydantic>=2]           # pip installed after requirements.txt and `pip install .`
user_environment:
  required:
    - name: HELLO_REGION
      description: region label used in logs
  require_one_of:
    - options: [{name: SOURCE_URL}, {name: SOURCE_FILE}]
  optional:
    - name: HELLO_LOG_LEVEL
      default: INFO

    language other than python, a config_version above v2, or an entrypoint.start that is not the worker command are refused with a message. Only one package is installed per command; dependencies.nodes is reported, not resolved. examples/python/first_node/agentnode.yaml is a complete minimal manifest.

    Install, run, stop

    atfg install ./hello --python python3.12          # or https://github.com/org/repo//subdir@v1.2.3, or hello-1.0.0.tar.gz
atfg run hello                                    # detached worker; waits until `hello` is registered
atfg list                                         # NAME VERSION LABEL PROCESS PID ON SERVER MODULE
atfg traverse hello.greet --in '{"name":"Ada"}'
atfg logs hello --tail 50
atfg stop hello                                   # SIGTERM -> drain -> exit
atfg uninstall hello

    install copies the package (git clones are shallow; .git, virtual environments, caches and .env files are excluded), creates <state>/packages/<name>/venv with --python, installs the atfgraph package from --sdk, ATFGRAPH_SDK, an atfgraph-*.whl next to the binary or the source checkout, then requirements.txt, pip install . when a pyproject.toml or setup.py exists, and dependencies.python. It records source, resolved commit, manifest digest and interpreter in installed.json. --python must be 3.10 or newer; the default python3 on macOS is 3.9 and is refused (see Troubleshooting).

    run resolves user_environment from your shell and from <pkg>/.env or the package's own .env; a missing required variable or an unsatisfied require_one_of group stops the start and names the variables. SDK platform settings in those .env files reach the worker without a declaration: every ATFGRAPH_* variable (model provider, MLflow tracing), MLflow's own MLFLOW_*, and DATABRICKS_HOST, DATABRICKS_TOKEN, DATABRICKS_CONFIG_PROFILE. The worker is spawned detached in its own process group with its log in <pkg>/worker.log and its pid in run.json; run waits until the label is registered and prints the version and element count, exits 1 with the log tail if the worker dies first, and exits 2 (worker left running) if registration takes longer than --wait. stop signals only the recorded pid, only if its command line is still this package's worker; a reused pid is reported and left alone. The state directory defaults to ~/.atfgraph-vnext (--state-dir, ATFGRAPH_VNEXT_HOME).

    Package an artifact

    atfg package ./hello --out target/dist/packages
# packaged hello 1.0.0 (4 files) -> target/dist/packages/hello-1.0.0.tar.gz
# sha256 ...   metadata hello-1.0.0.package.json   checksums SHA256SUMS
atfg install target/dist/packages/hello-1.0.0.tar.gz

    The archive holds the package files (same exclusions as install); the metadata file lists every file with its SHA-256, the worker module, the manifest digest and the git commit when the directory is a checkout; SHA256SUMS in the output directory is verifiable with shasum -a 256 -c. Digests identify an artifact; byte-identical archives across tar implementations are not claimed.
