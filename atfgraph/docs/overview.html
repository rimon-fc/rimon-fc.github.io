    ATFGraph vNext overview

    ATFGraph vNext is a graph server for multi-agent systems: agent nodes register their functions, and every call between them is routed and recorded by the server as a step on a path. You write nodes in Python, start work with a CLI or HTTP call, and get back a result plus the complete, inspectable record of how it was produced.

    What it is not

    • Not a model provider or an LLM framework. The server never calls a model. Your traversals call whatever provider you configure; the server records the steps and their usage.
    • Not a message bus. Nodes do not talk to each other. Every call crosses the graph server, which is the only inbound endpoint. Workers connect outbound and open no port.
    • Not a hosted service. Nothing here runs anywhere until you start a graph server and at least one worker. Deployment targets exist, but a package is not a service until a deployment reports healthy workers.
    • Installed from a release, not from a package index. There is no pip install or Homebrew formula. The client (the atfg CLI, the atfgraph wheel, the coding-assistant skills) installs from a GitHub Release with the release's own install.sh, which verifies every file against the release's checksums and then connects you to a graph server (Install). A graph server is a source build or a deployment target. See *How it is installed today*.

    The three processes

    ProcessWhat it doesCommand
    Graph serverOwns the graph: routes edges, schedules traversers, stores paths and memoryatfgraphd
    CLIStarts the server, lists elements, starts traversers, reads pathsatfg
    WorkerRuns one agent node and connects outbound to the serverpython -m atfgraph.worker

    Default ports: the graph server listens on 127.0.0.1:18880 and serves the web console at http://127.0.0.1:18880/ui/. The optional gRPC admin surface uses 18882.

    How it is installed today

    Installation is a source build. You need a Rust toolchain and Python 3.10 or newer. From a checkout of the repository:

    cargo build --bin atfgraphd --bin atfg          # the server and the CLI, in target/debug/
python3.12 -m venv .venv                        # any interpreter >= 3.10
.venv/bin/python -m pip install ./python        # the atfgraph Python package

    target/debug/atfg is not installed over any other atfg you may have; put target/debug on your PATH or call it by path. The state directory is ~/.atfgraph-vnext.

    The Quickstart takes it from here. If a command in these pages does not behave as written, the Troubleshooting page lists the messages you may see.
