    Identity, credentials and access boundaries

    At the end of this page you can give an agent node a server-held signing key, sign and verify a finished path, enrol a DID and issue, verify and revoke credentials from app.credentials, run the node tag ledger, and install access policies and connector grants that the graph server enforces before any handler runs. Everything cryptographic happens on the graph server; the SDK holds no key material and signs nothing locally.

    Prerequisites: a graph server started with configured API keys, because creating keys, enrolling DIDs, deciding tags and writing policies are administrator operations. examples/python/features/access_boundaries/config.example.yaml is a ready-made configuration with one admin, one admin, worker and one invoke token for a loopback daemon.

    Three mechanisms, all server-side

    MechanismSDK surfaceWhat it answers
    Node identitiesapp.identities (Identity)Who produced this path? Ed25519 key per node, signed terminal paths
    Credentialsapp.credentials (Credentials)Is this W3C credential valid, and does this namespace trust it? DIDs, issuance, revocation, tag ledger
    Access policies and connector grantsREST routes under /api/v2/access through client.transport.requestMay this principal call this capability with this input, and how often?

    The first two have typed facades. The third has no facade in /tmp/sdk-api.md; the shipped example drives it with client.transport.request, and this page does the same.

    Node identities and signed paths

    Identity borrows a Client. create, rotate, revoke and sign need an admin key; list, proofs and verify work with an invoke key. The following is adapted from tests/test_discovery_identity.py, where it runs against a real daemon.

    import asyncio

from atfgraph import Agent, Client, ConflictError
from atfgraph.identity import Identity


async def main(url: str) -> None:
    async with Client(url, api_key="discovery-admin") as admin:
        app = Agent(node_id="travel", version="1", client=admin)

        @app.skill()
        async def quote(amount: int) -> dict:
            return {"amount": amount}

        await app.register()
        identities = Identity(admin)
        key = await identities.create("travel")          # or return the existing active key
        assert key.algorithm == "Ed25519" and key.state == "active"

        run = await admin.submit("travel.quote", {"amount": 42}, version="1")
        try:
            await identities.sign(run.id, key.id)          # refused while the path is still active
        except ConflictError as exc:
            assert exc.code == "path_active"

        await run.result(timeout=30)                     # a worker must be serving "travel"
        proof = await identities.sign(run.id, key.id)
        checked = await identities.verify(proof)
        assert checked.valid and checked.trusted and checked.key_state == "active"


asyncio.run(main("http://127.0.0.1:18880"))

    app.identities returns the same facade bound to the agent's own client. What the test shows about key lifecycle:

    ActionEffect on an existing proof
    rotate(key_id)New key for the node; old proofs stay valid and trusted, key_state becomes retired; signing with the retired key raises ConflictError
    revoke(key_id)Old proofs stay valid but trusted is False, key_state is revoked
    tampering with proof.to_dict()["signed"]valid is False

    proofs(traverser_id) lists every proof on a path. A caller in another namespace gets NotFoundError for the same traverser; Identity.verify does not re-sign anything.

    Credentials

    app.credentials is a typed client for the fourteen /api/v2/credentials routes. It validates arguments before any I/O (ValueError/TypeError for a bad label, an http:// web_base_url, a kind outside execution/custom, a TTL outside 1 second to one year, an empty tag list) and then asks the server. Outside a handler use Credentials.for_client(client).

    Enrol a node

    from atfgraph import Client, Credentials


async def enrol(url: str) -> None:
    async with Client(url) as client:
        credentials = Credentials.for_client(client)
        enrolment = await credentials.enroll("desk")          # administrator, once per registered node
        assert enrolment.active and enrolment.did.startswith("did:key:z6Mk")
        alias = await credentials.did("desk", web_base_url="https://graph.example.test")
        print(alias.also_known_as)                            # ['did:web:graph.example.test:agents:desk']
        resolution = await credentials.resolve(enrolment.did)
        assert resolution.is_local

    Adapted from tests/test_credentials_sdk.py. The node must be registered first; issuing before enrolment fails with APIError code did_not_enrolled.

    Issue and verify a custom credential

    from atfgraph import Client, Credentials


async def issue(url: str) -> None:
    async with Client(url) as client:
        credentials = Credentials.for_client(client)
        issued = await credentials.issue(
            "desk",
            subject={"id": "urn:example:quote:1", "amount": 1200, "currency": "AUD"},
            type="TravelQuoteCredential",
            expires_in_seconds=3600,
        )
        verified = await credentials.verify(issued.credential)
        assert (verified.valid, verified.trusted, verified.reason) == (True, True, None)

        tampered = dict(issued.credential)
        tampered["credentialSubject"] = {**tampered["credentialSubject"], "amount": 1}
        broken = await credentials.verify(tampered)
        assert (broken.valid, broken.reason) == (False, "invalid_signature")

        later = await credentials.verify(issued.credential, at=issued.expires_at + 600_000)
        assert later.reason == "expired"

    Adapted from tests/test_credentials_sdk.py. verify returns two answers:

    FieldMeaningReasons seen in the tests
    validCryptographic result: signature, proof shape, validity windowinvalid_signature, expired
    trustedThis namespace knows the credential, it is not revoked, the issuer key is not revokedunknown_credential, revoked

    A credential from another deployment can be valid without being trusted. at is epoch milliseconds; resolve_remote=True allows fetching a did:web issuer document that is not enrolled locally.

    Certify a finished traverser

    issue_execution(traverser_id, issuer_label=...) signs an execution credential whose subject the server builds from what it recorded: status plus hashes of input, output and error. Adapted from tests/test_credentials_sdk.py:

    from atfgraph import Client, Credentials


async def certify(url: str, traverser_id: str) -> None:
    async with Client(url) as client:
        credentials = Credentials.for_client(client)
        receipt = await credentials.issue_execution(traverser_id, issuer_label="desk")
        assert receipt.kind == "execution"
        assert receipt.subject["id"] == f"urn:atfgraph:traverser:{traverser_id}"
        assert receipt.subject["execution"]["status"] == "succeeded"
        again = await credentials.issue_execution(traverser_id, issuer_label="desk")
        assert again.id == receipt.id                           # re-issuing returns the same credential
        listed = await credentials.list(issuer_label="desk", kind="execution")
        assert receipt.id in listed.ids

    Inside a handler, issue, issue_execution, get and verify carry the running task's task_id and lease_token; those three routes are the only credential routes on the gateway's worker allowlist. The test shows the server-side refusals a worker meets: issuing as another node is 403 issuer_forbidden, certifying its own still-running traverser is traverser_active, and a stale lease token on get is 409 parent_lease_invalid. Call issue_execution() without arguments only for a child the handler already awaited.

    Revoke

    await credentials.revoke(credential_id, "quote superseded") returns the Credential with revoked true and revocation_reason set. The signature stays valid: verifying the same document afterwards gives (valid, trusted, reason) == (True, False, "revoked") (tests/test_credentials_sdk.py). list(revoked=False) excludes revoked credentials and list(revoked=True) returns only them; revoked is a filter, not a flag.

    Tag ledger

    Nodes carry capability tags that go through a namespace policy. Adapted from tests/test_credentials_sdk.py:

    from atfgraph import Client, Credentials
from atfgraph.credentials import TagRule


async def tags(url: str) -> None:
    async with Client(url) as client:
        credentials = Credentials.for_client(client)
        policy = await credentials.set_tag_policy(               # administrator
            default_mode="manual",
            rules=[TagRule(tags=["travel"], approval="auto", reason="reviewed once")],
            issuer_label="desk",
        )
        assert policy.mode_for("travel") == "auto" and policy.mode_for("pii") == "manual"

        proposed = await credentials.propose_tags("desk", ["Travel", "pii", "travel"])   # node owner
        assert proposed.modes == {"travel": "auto", "pii": "manual"} and proposed.pending == ["pii"]

        decided = await credentials.decide_tags("desk", "approve", tags=["pii"], reason="reviewed")
        assert decided.changed == ["pii"]
        ledger = await credentials.tags(label="desk")
        assert sorted(ledger.approved) == ["pii", "travel"]

    Tags are lower-cased and de-duplicated client-side. Modes are auto, manual and forbidden; decisions are approve, reject and revoke; an auto-approved tag refreshes a signed tag credential (list(kind="tag")) that verifies like any other.

    Access policies and connector grants

    Authorisation lives on the graph server so it applies to every surface (REST, MCP, A2A, emitters). The node in examples/python/features/access_boundaries/agent.py knows nothing about it; boundaries.py installs the rules with an operator key and then shows a partner key being refused. The policy shapes, adapted from that file:

    from typing import Any, Dict, List

LABEL = "concierge"
PARTNER_GRANTS = ["traversers.submit", "traversers.get", "traversers.path", "agents.capabilities"]


def policy_bodies(principal: str) -> List[Dict[str, Any]]:
    return [
        {"name": "example-partner-no-refunds", "label": LABEL, "capability": "refund", "principal": principal, "effect": "deny"},
        {
            "name": "example-partner-quote-limits", "label": LABEL, "capability": "quote", "principal": principal, "effect": "allow",
            "constraints": {"currency": {"operator": "==", "value": "AUD"}, "nights": {"operator": "<=", "value": 7}},
        },
        {
            "name": "example-partner-itinerary-rate", "label": LABEL, "capability": "itinerary", "principal": principal, "effect": "allow",
            "rate": {"requests_per_second": 0.001, "burst": 2},
        },
    ]

    Installing them and binding the partner's connector manifest, adapted from the same file:

    from atfgraph import APIError, Client


async def install(operator: Client, principal: str, bodies: list) -> dict:
    policies = [await operator.transport.request("POST", "/api/v2/access/policies", json_body=body) for body in bodies]
    manifest = {"grants": ["traversers.submit", "traversers.get", "traversers.path", "agents.capabilities"], "enabled": True}
    try:
        current = await operator.transport.request("GET", f"/api/v2/access/connectors/{principal}")
        manifest["expected_revision"] = current["revision"]
    except APIError as exc:
        if exc.status != 404:
            raise
    connector = await operator.transport.request("PUT", f"/api/v2/access/connectors/{principal}", json_body=manifest)
    return {"policies": policies, "connector": connector}

    tests/test_feature_examples_extended.py runs this against a real daemon started with ATFGRAPH_CONFIG_FILE pointing at config.example.yaml and pins the refusals the partner sees:

    Call by the partnerResult
    quote with nights=2, currency="AUD"allowed; the handler runs
    quote with nights=14, or without currency403 constraint_denied (an absent constrained field cannot satisfy its rule)
    refund403 policy_denied
    list_agents()403 connector_forbidden (the manifest, not the role, stops it)
    third itinerary call in a burst429 rate_limited
    any call after POST /api/v2/access/connectors/{principal}/revoke403 connector_forbidden; there is no fallback to a plain bearer

    Two read-only routes help while writing rules: GET /api/v2/access/connector returns the caller's own manifest, and POST /api/v2/access/evaluate with {"operation", "target", "input"} previews a decision (allowed, reason) without submitting anything. Re-running the installer replaces only the policies whose names carry its prefix.

    There is no atfg command for access policies in ../cli-reference.md; the REST routes above are the surface.

    Tag-scoped policies

    A policy may carry tags; it then matches an admission only when the target capability, or its node, carries at least one of them, on top of the label, capability and principal match. Tags are read from the newest registered version of the label. This is how "deny every pii capability to the analytics principal" is written once instead of per capability:

    curl -s -X POST http://127.0.0.1:18880/api/v2/access/policies -H 'content-type: application/json' \
  -d '{"label":"*","principal":"analytics","effect":"deny","tags":["pii"]}'

    Budgets

    A budget caps what one scope may consume over a rolling window and is checked at admission, next to access policies. Scope is principal, label (a node), target (label.capability) or namespace (admin only); metric is tokens or cost_usd from recorded usage, or runs (admitted root executions); window is 1h, 24h, 7d or 30d. A deny budget refuses POST /api/v2/traversers with 429 budget_exceeded once the window's consumption has reached the limit; a warn budget never blocks and only appears in POST /api/v2/access/evaluate (warnings) and GET /api/v2/budgets/status. A run already admitted is never stopped by a budget.

    curl -s -X POST http://127.0.0.1:18880/api/v2/budgets -H 'content-type: application/json' \
  -d '{"name":"co-consult daily spend","scope":"label","subject":"co-consult","metric":"cost_usd","limit":25,"window":"24h","action":"deny"}'
curl -s 'http://127.0.0.1:18880/api/v2/budgets/status?target=co-consult.consult'   # allowed + headroom per budget

    Routes: GET/POST /api/v2/budgets, GET/PATCH/DELETE /api/v2/budgets/{id} (compare-and-set with expected_revision), GET /api/v2/budgets/{id}/usage (consumed, remaining, exceeded, window start) and GET /api/v2/budgets/status?target&principal. Non-admins may only budget their own principal or labels they registered. The console's Policies page lists budgets with the consumed share of each window.

    API tokens

    Tokens in atfgraph.yaml under auth.tokens remain the configuration-time credentials and are checked first. Administrators can also issue stored tokens over the API, which need no restart and can expire, be rotated and be revoked:

    curl -s -X POST http://127.0.0.1:18880/api/v2/auth/tokens -H "authorization: Bearer $ADMIN_TOKEN" \
  -H 'content-type: application/json' -d '{"principal":"ci-runner","roles":["invoke"],"label":"nightly evals","expires_at":1800000000000}'
# {"id":"…","prefix":"atfg_ab1","token":"atfg_…","roles":["invoke"],…}   the plaintext appears in this response only

    The server stores only the SHA-256 of the secret and never logs it; GET /api/v2/auth/tokens lists prefix, principal, roles, label, expiry, revocation and last use. POST /api/v2/auth/tokens/{id}/rotate returns a new secret and revokes the old one after an optional grace_seconds; DELETE /api/v2/auth/tokens/{id} revokes immediately (callers get 401 token_revoked; an expired token gets 401 token_expired). Give the token to a node through ATFGRAPH_API_KEY or Client(api_key=...); nothing changes in the SDK. The console's Access page manages stored tokens and shows the secret once, on creation.

    What a worker credential may do

    The example configuration gives the node process a token with roles admin, worker because registering a definition is an admin operation and enrolling a worker needs worker. Once a task is leased, the SDK sends the lease with requests made inside the handler:

    • Credentials: issue, get and verify carry task_id and lease_token; the worker may issue only as the node it is executing and only over its own task subtree (python/atfgraph/credentials.py).
    • Usage and node logs: record_usage, append_logs, run_metadata and set_run_metadata carry the same authority (python/atfgraph/observability.py), see ./14-observability.md.
    • Knowledge and memory inside a handler resolve session and workflow scopes from the leased task (tests/test_sdk_extension_integration.py).

    Not verified: whether a token with only the worker role is refused when it reads memory or knowledge outside a leased task. Confirming it needs a real-daemon run with a roles: [worker] token calling client.memory_read directly.
