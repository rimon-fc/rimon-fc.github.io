    Deploy with Docker Compose

    Problem: you want the graph server and a worker running in containers on one machine, with the CLI tracking what it applied so you can observe, roll back and tear down.

    The Compose target is managed by the CLI with persisted desired and observed state. It needs Docker with the Compose plugin. Because the daemon listens on 0.0.0.0 inside a container, an API key is required.

    Commands

    export ATFGRAPH_API_KEY="$(openssl rand -hex 24)"     # handed to the containers; only the variable name is recorded
atfg deploy compose up --name demo --build            # project atfgv-demo on a free loopback port; waits for /health and node registration
atfg deploy compose status --name demo                # containers, health, registered labels, image drift; exit 3 when not converged
atfg deploy compose up --name demo --image-tag v2     # re-apply with another image tag (ATFGRAPH_IMAGE_TAG in compose.yaml)
atfg deploy compose rollback --name demo [--build]    # previous successfully applied tag from the record's history
atfg deploy compose logs --name demo --tail 100 --service co-consult
atfg deploy compose down --name demo --volumes --forget
atfg deploy list

    up writes <state>/deployments/demo.json (desired running, project, port, image tag, expected labels from the Compose file's dev.atfgraph.vnext.label service labels, the key variable's name) before starting anything, so an interrupted apply can still be observed and torn down. A failed up records the failure with the container log tail and leaves resources for inspection; removal is always the explicit down, scoped to that project's containers, network and (with --volumes) data volume.

    Options on up: --file F for a different Compose file, --port P, --api-key-env VAR to name a different key variable, --expect-label L to wait for a specific label, --wait S.

    Validate the files without a cluster

    atfg deploy validate --path deploy
    passed   compose config
         $ docker compose -f deploy/docker/compose.yaml config --quiet
passed   kubernetes kustomize render
         $ kubectl kustomize deploy/kubernetes/base
skipped  helm lint
         $ helm lint deploy/helm/atfgraph-vnext
         `helm` not on PATH
ok: 2 passed, 0 failed, 2 skipped

    Missing tools are skipped unless you pass --require-tools.

    Container files for your own node

    atfg deploy scaffold ./my-node --label my-node --module my_node:app
    wrote my-node/.dockerignore
wrote my-node/Dockerfile
wrote my-node/compose.yaml
next: add the atfgraph Python package to requirements.txt, then `docker compose up --build` with ATFGRAPH_SERVER and ATFGRAPH_API_KEY set.

    The Dockerfile installs requirements.txt, copies the project and runs python -m atfgraph.worker with $ATFGRAPH_SERVER. The Compose file requires ATFGRAPH_API_KEY in the environment. Existing files are never overwritten without --force:

    atfg: my-node/.dockerignore exists; pass --force to overwrite

    Readiness

    Every target uses GET /health for server readiness and node-healthcheck.py (the server lists the label) for worker readiness.
