    Resilience and client-side controls

    By the end of this page a capability asks the graph server for another attempt with RetryableError, is cut off by its own timeout_seconds budget, stops cleanly when a traverser is cancelled, and the calling code bounds its own load with RateLimiter, ResultCache, retry_rate_limited and ModelRouter. It requires a running graph server for the first three sections; the client-side controls run in any event loop.

    What the server enforces and what the client does

    The client-side controls in python/atfgraph/controls.py sit above the SDK's bounded HTTP layers and coordinate nothing across processes; the graph server's admission limits remain authoritative.

    Retries: RetryableError and max_attempts

    A handler that raises RetryableError (a HandlerError with retryable=True) tells the server this attempt may be scheduled again while the capability's max_attempts allows it. Any other exception is terminal. current_context().attempt tells the handler which attempt it is on. Adapted from examples/python/features/resilience/agent.py:

    from pydantic import BaseModel

from atfgraph import Agent, RetryableError, current_context
from atfgraph.model import ModelError

app = Agent(node_id="disruption", version="1.0.0", capacity=4)


class RebookingNote(BaseModel):
    summary: str
    rebook_within_hours: int


@app.skill(max_attempts=3)
async def rebooking_note(flight: str, model: str = "fixture-flaky") -> dict:
    attempt = current_context().attempt
    try:
        note = await app.ai(
            system="You are a disruption desk. Answer with the requested fields only.",
            user=f"Flight {flight} was cancelled. Summarise the rebooking action and the hours we have to act.",
            schema=RebookingNote,
            model=model,
        )
    except ModelError as exc:
        raise RetryableError(f"provider failed on attempt {attempt}: {exc}") from exc
    return {"flight": flight, "attempt": attempt, "summary": note.summary, "rebook_within_hours": note.rebook_within_hours}

    This needs a model provider. The example ships one: examples/python/features/resilience/fixture_model.py is a local OpenAI-compatible server whose fixture-flaky model answers 503 twice and then succeeds, and whose fixture-slow model stalls.

    python -m examples.python.features.resilience.fixture_model --port 18899
export ATFGRAPH_MODEL_URL=http://127.0.0.1:18899 ATFGRAPH_MODEL_NAME=fixture-fast
python -m atfgraph.worker --module examples.python.features.resilience.agent:app
python -m examples.python.features.resilience.call

    tests/test_feature_examples_extended.py runs this against the daemon and asserts: the output reports attempt: 3, the traverser record shows attempt == 3 and max_attempts == 3, the event log holds two requeued events whose error.retryable is True, and the provider was called exactly three times. With the fixture set to fail nine times, the fourth failure is terminal: the traverser ends failed after attempt 3. The budget is per capability, not per handler call. Without ATFGRAPH_MODEL_URL / ATFGRAPH_MODEL_NAME, app.ai raises ModelNotConfigured and the run fails saying so.

    Capability budgets: timeout_seconds

    timeout_seconds (default 300) is the handler budget. The worker runs the handler under asyncio.wait_for and, when the budget passes, completes the traverser with error code handler_timeout (not retryable). If the worker itself had disappeared, the server's own deadline would mark the same run timed_out, which the client sees as TraversalTimedOut. Adapted from the same example:

    from pydantic import BaseModel

from atfgraph import Agent

app = Agent(node_id="disruption", version="1.0.0")


class RebookingNote(BaseModel):
    summary: str
    rebook_within_hours: int


@app.skill(timeout_seconds=2)
async def stalled_note(flight: str) -> dict:
    note = await app.ai(user=f"Flight {flight} was cancelled.", schema=RebookingNote, model="fixture-slow")
    return {"flight": flight, "summary": note.summary}

    The test submits this against a fixture that stalls for 30 seconds and asserts the traverser ends within 20 seconds with status failed or timed_out and code handler_timeout or timed_out. Synchronous handlers run in a thread that Python cannot interrupt: the worker stops waiting and reports the timeout, but the thread runs to its own end.

    Guardrails: refuse bad input and bad output

    A guardrail is a named check the worker runs around a handler. input guardrails see the admitted payload before the handler runs; output guardrails see the encoded result before it is reported. A refusal fails the step with the envelope {"code": "guardrail_violation", "retryable": false} and a message that names the rule and the reason, so the run's path, atfg path and the console's Runs page show exactly which rule refused what. Nothing is redacted or rewritten silently.

    import json
import re

from atfgraph import Agent, allowed_values, deny_patterns, max_chars, require_keys

app = Agent(node_id="support")


@app.guardrail("no_card_numbers", phase="output", description="refuse card-like digit runs")
def no_card_numbers(value, ctx):
    # Return None to pass, or a message (or list of messages) to refuse.
    if re.search(r"\b\d{13,19}\b", json.dumps(value)):
        return "output contains a card-number-like sequence"


@app.traversal(
    guardrails=[
        "no_card_numbers",                                  # registered by name above
        require_keys("has_answer", ["answer", "sources"]),  # output must carry these keys
        max_chars("short_reply", 4000, fields=["answer"]),  # bound one field's length
        allowed_values("lang", "lang", ["en", "fr"]),       # an input guardrail
    ]
)
async def answer(question: str, lang: str = "en") -> dict:
    ...

    Built-in checks: deny_patterns(name, patterns, fields=…) (the reason names the pattern, never the matched text), max_chars, require_keys, json_schema(name, schema) and allowed_values(name, field, values); each takes phase="input" | "output" | "both". Any callable (value, ctx) -> None | bool | str | list[str], sync or async, becomes a guardrail through @app.guardrail(...) or Guardrail(name, check, phase); app.add_guardrail(...) registers a prebuilt one. app.call_local applies the same guardrails, so a unit test can assert a GuardrailViolation without a server:

    import pytest
from atfgraph import GuardrailViolation

async def test_card_numbers_are_refused():
    with pytest.raises(GuardrailViolation) as refused:
        await app.call_local("answer", question="pay with 4111111111111111")
    assert refused.value.rule == "no_card_numbers" and refused.value.phase == "output"

    Guardrails run in the worker, next to the handler, which is where the output exists; the graph server never sees model output before the worker reports it. Access policies (docs/python/13-identity-credentials-and-access.md) decide who may call what with which input at admission; guardrails decide what a handler may accept and return. A violation counts as a failed attempt and is never retried.

    Cooperative cancellation

    Handle.cancel() (or atfg cancel) sets cancel_requested on the server. The worker learns of it on the next lease renewal, sets the context's cancel event and cancels the handler task; an async def handler observes that at its next await. Long loops should also poll app.cancel_requested() between slices so partial work is reported as progress rather than lost. Adapted from the same example:

    import asyncio

from atfgraph import Agent, ConflictError

app = Agent(node_id="disruption", version="1.0.0")


@app.traversal(timeout_seconds=600)
async def watch(flight: str, seconds: float = 30.0, slice_seconds: float = 0.1) -> dict:
    ticks = max(1, int(seconds / slice_seconds))
    per_note = max(1, int(1.0 / slice_seconds))
    done = 0
    while done < ticks and not app.cancel_requested():
        await asyncio.sleep(slice_seconds)
        done += 1
        if done % per_note == 0:
            try:
                await app.progress({"flight": flight, "watched_seconds": round(done * slice_seconds, 1)})
            except ConflictError:
                break
    return {"flight": flight, "watched_seconds": round(done * slice_seconds, 1), "cancelled": app.cancel_requested()}

    app.progress after the cancel landed raises ConflictError, which is why the loop catches it. The test cancels after 1.2 seconds, sees TraversalCancelled from handle.result(), finds the first progress event {"flight": "QF-541", "watched_seconds": 1.0} in the event log, and the traverser record has cancel_requested: True. This snippet needs no provider.

    RateLimiter

    RateLimiter(default=None, policies={...}) gives bounded per-key admission for one event loop. A RateLimitPolicy combines rate admissions per per seconds (a token bucket of burst tokens), a concurrency cap and max_pending waiters; at least one of rate or concurrency is required. Keys are plain strings; a policy key ending in : acts as a prefix ("node:" applies to "node:slow" unless "node:slow" has its own). A key with no policy and no default is unlimited. Adapted from examples/python/features/serverless/agent.py and tests/test_python_controls.py:

    import asyncio

from atfgraph import Agent, RateLimiter
from atfgraph.controls import RateLimitExceeded, RateLimitPolicy

app = Agent(node_id="quoter", version="1.0.0", capacity=2)
limiter = RateLimiter(policies={"node:quoter": RateLimitPolicy(rate=20, per=1.0, concurrency=2, max_pending=50)})


@app.traversal()
async def quote(legs: list[dict]) -> dict:
    async def one(leg: dict) -> dict:
        try:
            async with limiter.limit("node:quoter", timeout=5.0):
                return await app.traverse("quoter.price", **leg)
        except RateLimitExceeded as exc:
            return {"error": str(exc), "retry_after": exc.retry_after}

    priced = await asyncio.gather(*(one(leg) for leg in legs))
    return {"legs": priced, "admitted": limiter.stats("node:quoter").admitted}

    Admission is FIFO per key. limit(key, timeout=...) raises RateLimitExceeded when max_pending callers already wait or when timeout passes; a waiter cancelled by its caller leaves the queue and never holds a permit. run(key, func, *args) holds the permit for the whole call; acquire/release are the manual pair; stats(key) reports admitted, refused, timed_out, cancelled_waits, max_in_flight and max_pending.

    ResultCache

    ResultCache(ttl=300.0, max_size=1024) is an expiring, LRU-bounded, single-flight cache for one event loop. get_or_compute(key, factory) returns the cached value or runs factory once for every concurrent caller of the same key. Values are deep-copied on the way in and out; a failing factory propagates to all coalesced waiters and caches nothing; if the computing caller is cancelled, a waiter takes over. Adapted from examples/python/features/serverless/agent.py:

    import asyncio

from atfgraph import Agent, ResultCache

app = Agent(node_id="quoter", version="1.0.0", capacity=2)
cache = ResultCache(ttl=60.0, max_size=256)


@app.traversal()
async def quote(legs: list[dict]) -> dict:
    async def one(leg: dict) -> dict:
        key = ("price", leg.get("origin"), leg.get("destination"), leg.get("nights", 1))

        async def compute() -> dict:
            return await app.traverse("quoter.price", **leg)

        return await cache.get_or_compute(key, compute)

    priced = await asyncio.gather(*(one(leg) for leg in legs))
    return {"legs": priced, "cache": {"hits": cache.stats.hits, "misses": cache.stats.misses}}

    tests/test_python_controls.py runs this on the daemon with three legs of which two are identical: the path holds quoter.quote and two quoter.price steps (the duplicate leg never became a child), and a repeated invocation of the first leg claims one task and reports a cache hit. A cache hit therefore also means no step on the path. The optional background sweep (start() / stop(), or async with cache:) is bound to the loop that started it; sweep() also runs on every len() and keys().

    retry_rate_limited

    await retry_rate_limited(func, max_attempts=3, base_delay=0.2, max_delay=5.0, deadline=None) calls a zero-argument coroutine function again only when it failed with a rate limit: APIError with status 429 from the graph server, RateLimitExceeded, or a ModelError whose text contains HTTP 429. It honours a retry_after carried by the error, otherwise backs off exponentially up to max_delay, and stops before sleeping past deadline (a monotonic time). Any other exception propagates at once. Adapted from tests/test_python_controls.py:

    import asyncio

from atfgraph import Client, retry_rate_limited


async def main() -> None:
    async with Client("http://127.0.0.1:18880") as client:
        async def once() -> dict:
            return await client.traverse("quoter.quote", {"legs": [{"origin": "BNE", "destination": "SYD"}]}, timeout=30)

        print(await retry_rate_limited(once, max_attempts=3))


if __name__ == "__main__":
    asyncio.run(main())

    ModelRouter

    ModelRouter is a ModelProvider that dispatches complete and stream to explicitly registered providers only. It reads nothing from the environment and never constructs a provider; an unroutable request raises ModelNotConfigured. Resolution order for model: "<route>:<model>" names a route explicitly; then a route whose models contain the name or whose prefixes match; then the default route with its default_model. Adapted from tests/test_python_controls.py:

    from atfgraph import Agent, ModelRouter, RateLimiter
from atfgraph.controls import RateLimitPolicy
from atfgraph.model import HTTPChatModel

limiter = RateLimiter(policies={"model:fast": RateLimitPolicy(concurrency=2)})
router = ModelRouter(limiter=limiter, admission_timeout=10.0)
router.register("fast", HTTPChatModel("http://127.0.0.1:18899", "fixture-fast"), default_model="fixture-fast", prefixes=["fixture-"])

app = Agent(node_id="routed", version="1.0.0", model=router)


@app.skill()
async def answer(question: str) -> dict:
    text = await app.ai(question)
    bigger = await app.ai(question, model="fast:fixture-fast")
    return {"default": str(text), "explicit": str(bigger), "calls": dict(router.calls)}

    With limiter= set, every call is admitted under the route's limit_key (default "model:<route>"); a stream holds its permit from the first event until the stream ends or is closed. resolve(model, needs=["vision"]) skips routes whose provider lacks a required capability. The snippet needs the fixture provider from the resilience example (or any OpenAI-compatible endpoint) at the given URL.
