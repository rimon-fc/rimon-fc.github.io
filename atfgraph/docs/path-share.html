    Sharing a path offline

    atfg share turns a recorded path — the steps one traverser took through the graph — into a single file you can keep, archive, screenshot or hand to someone else.

    Nothing is uploaded. There is no link to mint, no host to reach and no account to have: the file is the artifact.

    $ atfg share 7720ccc2-e96d-436b-b06b-39b51bb67ad5
/home/you/path-7720ccc2-e96d-436b-b06b-39b51bb67ad5.html
2 step(s), succeeded — 16405 bytes

    Open it in any browser, from disk, on a machine that has never heard of your graph server.

    Using it

    FlagWhat it does
    <ID>The traverser whose path is exported. Any step id works: the export follows the path the graph server returns for it.
    -o, --out PATHWhere to write. Default path-<id>.html (.json with --format json) in the working directory.
    `--format html\json`html (default) is the readable, self-contained document. json writes the versioned bundle on its own.
    --title TEXTNames the path. Default: path of <target> taken from the entry step.
    --redactReplaces every input, output and error preview with [redacted] before anything is written.
    --forceRequired to overwrite an existing file. Without it the command stops and writes nothing.

    The global flags work as they do everywhere else: --server, --api-key (ATFGRAPH_SERVER, ATFGRAPH_API_KEY), --timeout, and --json for a machine-readable summary of the export:

    $ atfg --json share $ID --out audit.html
{
  "id": "7720ccc2-…",
  "root_id": "7720ccc2-…",
  "out": "audit.html",
  "format": "html",
  "bundle_version": 1,
  "bytes": 16405,
  "steps": 2,
  "steps_omitted": 0,
  "status": "succeeded",
  "redacted": false
}

    Sharing is a read, not a privilege escalation. The export calls GET /api/v2/traversers/{id}/path and GET /api/v2/usage?root_id=… with your own credentials; if you cannot read the path, you cannot export it.

    What is in the artifact

    The HTML document shows, in this order:

    • the path's title, id, export time and rolled-up status;
    • a summary strip — steps, status, wall clock, cost, tokens;
    • the DAG, as a tree of steps linked to their detail;
    • one card per step: ids, kind, version, attempt, start, finish, duration, model, cost, error code, and disclosure panels for the input, output and error previews;
    • the caveats that apply to this particular export; and
    • the same data as a versioned JSON bundle, inlined in a <script type="application/json" id="atfgraph-path-bundle"> block.

    That inlined bundle is byte-identical to what --format json writes (modulo the export timestamp), so a program can read either one.

    Bundle schema, version 1

    {
  "bundle_version": 1,
  "kind": "atfgraph.path-share",
  "product": "ATFGraph vNext",
  "path_id": "…", "root_id": "…", "title": "path of travel.plan",
  "generated_at": "2026-09-15T04:11:07.123Z",
  "generated_by": "atfg share (ATFGraph vNext 0.1.0)",
  "redacted": false,
  "limits": { "preview_limit_bytes": 2048, "max_nodes": 1000, "nodes_omitted": 0 },
  "totals": {
    "steps": 2, "status": "succeeded",
    "status_counts": { "succeeded": 2 },
    "wall_clock_ms": 219,
    "cost_usd": 0.0125,          // null = unknown, never a stand-in for 0
    "cost_complete": true,
    "total_tokens": 15
  },
  "nodes": [ { "id": "…", "step_id": "…", "parent_id": null,
               "target": "travel.plan", "label": "travel", "capability": "plan",
               "version": "1.0.0", "kind": "traversal",
               "status": "succeeded", "attempt": 1, "max_attempts": 1,
               "created_at_ms": 0, "started_at_ms": 0, "finished_at_ms": 0,
               "duration_ms": 219,
               "input_preview":  { "state": "unavailable", "text": null, "truncated": false, "source_bytes": null },
               "output_preview": { "state": "available", "text": "{…}", "truncated": false, "source_bytes": 434 },
               "error_preview":  { "state": "absent", "text": null, "truncated": false, "source_bytes": null },
               "error_code": null, "model": null, "cost_usd": null, "total_tokens": null } ],
  "edges": [ { "from": "…", "to": "…" } ],
  "notes": [ "…" ]
}

    bundle_version is the contract. Bump it on any breaking change to this shape.

    Preview states. A preview never silently conflates "nothing there" with "nothing shown", because on a shared path those mean very different things:

    StateMeaning
    availableText is present (possibly truncated; truncated and source_bytes say so).
    emptyThe step recorded this field, and it was empty.
    absentThe step recorded nothing here — no output yet, or no error at all.
    unavailableThe read API does not carry this field, so the export could not include it.
    redactedPresent, and deliberately stripped by --redact.

    Unknown is not zero. cost_usd and model are null when the graph server reported nothing, and the document renders them as unknown. A step that recorded a priced call at $0 renders $0.0000; a step with no usage record never does. When a step has several model calls and only some were priced, its cost stays null rather than reporting the priced subtotal as if it were the whole.

    Safety

    The artifact is built to be sent to someone. Everything in it except the headings is attacker-influenced — a step's output is whatever an agent node returned — so:

    • No JavaScript. The document has exactly one <script> element, and it is type="application/json": data, never executed. Everything visible is server-rendered HTML; the collapsible panels are <details>. There is no code path in the file that could run a payload.
    • No network. No remote asset, no @import, no url(), no absolute URL anywhere — not even in the stylesheet. The only links are #step-… fragments within the file. A Content-Security-Policy meta tag (default-src 'none') makes a browser enforce this too.
    • Escaped at both layers. Text is HTML-escaped (& < > " '). The inlined bundle is escaped for its container: <, >, &, U+2028 and U+2029 become \uXXXX, so a payload containing </script> cannot close the block. A status the renderer does not recognise becomes unknown rather than reaching a CSS class name.
    • Sanitised text. C0/C1 control characters (so cat-ing the file is safe) and Unicode bidi/invisible-format characters (so a preview cannot display in an order other than the bytes it holds) are dropped from untrusted text.
    • Bounded. 2 KiB per preview, 1000 steps per artifact; both record what was dropped. A 100× larger payload produces the same-sized file.
    • No credentials. The bundle is built from response bodies only. No API key, no bearer token, not even the server address is written to it.
    • No publishing. There is no --public, no upload and no browser launch; posting a bundle to a hosted share service is deliberately not implemented.

    --redact is the stronger setting, not the default one: the default is already safe to keep, and redaction is for when the payloads themselves must not leave the machine. It removes input, output and error previews. Structure — the DAG, statuses, timing, attempts, token counts and error_code — survives, so a redacted export is still worth sending.

    Not available over HTTP

    The export exists only in the CLI. There is no GET /api/v2/traversers/{id}/share route; a browser or another client that wants the same artifact runs atfg share.

    Known gap: step inputs

    The export marks every input preview unavailable, and says so in the artifact and in the bundle notes. This is a data gap, not a renderer one: GET /api/v2/traversers/{id}/path returns each step's status, timing, output and error, but not its input. Trav::to_json in src/store.rs does not carry input_json; the only place an input crosses the wire is worker/claim, which is a worker-role lease operation and not a read API.

    Closing it needs a contract change (an input field on the path item). The renderer already reads item["input"] leniently, so input previews start working the day the field appears, with no change to the export.
