    Historical data migration and backup/restore

    The CLI exposes the same tool and options through atfg migrate. These commands run locally; they do not send database credentials to the graph API. Set ATFG_PYTHON to an interpreter with the optional migration extra for PostgreSQL. Full local artifacts bundle the tool and its SQL migrations; a server source checkout is selected with ATFGRAPH_VNEXT_SOURCE (the server checkout root) or atfg migrate --tool-root /path/to/atfgraph ... (the migration tool ships in the repository and in the self-host bundle).

    atfg migrate plan --source graph.db
atfg migrate run --source graph.db --destination new/graph.db
atfg migrate plan --source-postgres env:PARENT_DSN
atfg migrate run --source-postgres env:PARENT_DSN --destination-postgres env:VNEXT_DSN --archive new/legacy.sqlite3
atfg migrate backup --database-postgres env:VNEXT_DSN --out backups/snapshot
atfg migrate verify --backup backups/snapshot
atfg migrate restore --backup backups/snapshot --destination-postgres env:VNEXT_DSN
atfg migrate plan --help

    Arguments are passed directly to Python without shell expansion. env:NAME is resolved only inside the migration process and keeps DSN values out of the command line. Tool exit codes are preserved: 0 success, 2 usage, 3 rejected, 4 execution failure. Put dispatcher options (--python, --tool-root) before the migration subcommand. SQLite operations use Python's standard library.

    scripts/migrate.py (package migration/) moves history out of a parent graph server (the Go server in ../graph-server, local or postgres storage mode) into a new, separate ATFGraph vNext store (SQLite file or empty PostgreSQL database), and backs up / restores vNext stores on either backend. Run it through atfg migrate or directly with Python. The SQLite path needs only the Python standard library; the PostgreSQL path needs the optional psycopg driver (python -m pip install 'psycopg[binary]>=3.2' into the workspace .venv), and says so with code psycopg_missing when it is absent.

    python scripts/migrate.py plan    --source graph.db [--source-memory kv.db] [--unfinished reject|archive]
python scripts/migrate.py plan    --source-postgres env:PARENT_DSN
python scripts/migrate.py run     --source graph.db --destination new/graph.db [--archive new/graph.legacy-archive.sqlite3]
python scripts/migrate.py run     --source-postgres env:PARENT_DSN --destination-postgres env:VNEXT_DSN --archive new/legacy-archive.sqlite3
python scripts/migrate.py backup  --database graph.db --out backups/2026-09-15
python scripts/migrate.py backup  --database-postgres env:VNEXT_DSN --out backups/2026-09-15
python scripts/migrate.py verify  --backup backups/2026-09-15
python scripts/migrate.py restore --backup backups/2026-09-15 --destination graph.db [--replace]
python scripts/migrate.py restore --backup backups/2026-09-15 --destination-postgres env:VNEXT_DSN [--replace]
python scripts/migrate.py archive --archive new/graph.legacy-archive.sqlite3
python scripts/migrate.py fixture --out /tmp/legacy-fixture [--unfinished] [--duplicate-execution]
python scripts/migrate.py fixture --postgres env:EMPTY_DSN [--unfinished] [--duplicate-execution]

    PostgreSQL options take a libpq connection string or env:NAME, which reads it from that environment variable so passwords stay out of shell history and process listings. Connection strings are never printed, stored or archived with their password: reports, ledgers, manifests and the archive carry postgresql://user@host:port/dbname only. Supported combinations are SQLite parent → SQLite vNext and PostgreSQL parent → PostgreSQL vNext (the legacy archive is always a SQLite file, so --archive is required with --destination-postgres). Cross-backend runs are refused as a usage error (exit 2).

    Exit codes: 0 success or idempotent no-op, 2 usage, 3 rejected by a validation rule (nothing written), 4 failure while the tool was writing (temporary files removed, no destination created).

    Safety rules the tool enforces

    RuleBehaviour
    Source is read-onlySQLite: opened mode=ro, copied with the SQLite online-backup API into a private snapshot; every query runs on the snapshot. The main file and -wal are never written (SQLite may create a -shm index next to a WAL-mode source). The BoltDB memory file is memory-mapped read-only. PostgreSQL: one connection in READ ONLY REPEATABLE READ mode, so every table and the kv_store memory table are read from a single consistent snapshot and the server itself rejects any write on that connection.
    Source ≠ destinationDestination and archive may not be the source database or memory file, and may not be each other. PostgreSQL: source and destination may not be the same host/port/database.
    Destination must be newSQLite: any existing destination file, side file (-wal, -shm, -journal) or archive path is refused. PostgreSQL: the database must hold no vNext data (no tables, or a daemon-initialised schema whose data tables are all empty and whose traverser_seq counter is 0). One exception on both: a destination holding a committed import of the same source (same content digest) is an idempotent no-op.
    Supported schema onlyThe source schema_migrations ledger must equal the parent runner's set for that backend (SQLite 007–015, 036; PostgreSQL 015, 036) and every documented column must exist (schemas captured from real atfgraphd starts: migration/legacy_ddl.py). Anything else is unknown_schema, incompatible_schema or unsupported_backend (a SQLite file carrying the PostgreSQL ledger).
    Unfinished legacy workParent workflow_executions, workflow_runs, workflow or step rows in a non-terminal status, pending approvals or held leases are rejected (unfinished_runs) unless --unfinished archive, which archives those trees and imports nothing for them natively. Stop the parent graph server first in either case.
    Duplicate IDsDuplicate execution_id rows or agent rows that collapse onto one (label, version) are rejected (duplicate_ids); nothing is merged or overwritten.
    Atomic commitSQLite: destination and archive are built as hidden temp files in the destination directory and hard-linked into place only after all checks pass, archive first. PostgreSQL: migrations, native rows, checks and the atfgraph_legacy_import ledger row are written in one transaction holding the runtime's own advisory lock (7346210991, so a daemon starting concurrently waits); the archive is linked into place immediately before COMMIT and removed again if the commit fails. Any failure rolls back / removes temp files; no partial destination ever exists under the final name. Re-running after an interruption is the resume path: IDs are UUIDv5 of the legacy identity, so a re-run produces identical records on either backend.
    Referential checksBefore commit the destination is checked for: terminal statuses only, root/parent/step links, contiguous seq, counters.traverser_seq, session and agent-version references, event ordering and event_seq, memory scope owners, JSON validity, and (SQLite) PRAGMA integrity_check. The same portable SQL runs on both backends.

    What is imported natively and what is archived

    "Native" rows are written to the vNext tables the runtime reads. Everything else, and every legacy row without exception, is preserved in the archive.

    Legacy (parent)vNext destinationNotes
    agent_nodesagentslabel = node id; capabilities from reasoners (traversal) and skills (skill) with their schemas; retry.max_attempts=1, timeout_seconds=300 (the runtime defaults, the parent stored neither); empty legacy version → 0.0.0 (reported). Capability names containing . are dropped from the native definition (reported) because vNext splits label.capability on the dot.
    sessionssessionsowner = --namespace/--principal (default local/local); active_root_id NULL. Actor id, name, parent/root session and totals are archive-only.
    workflow_executions (finished trees)traversersstatus mapped through the parent's own alias table (completed→succeeded, timeout→timed_out, …); input/output JSON; input_hash computed with the runtime's exact algorithm; error envelope {code,message,retryable:false} from status_reason/error_message; parent/root/step links and depth recomputed from parent_execution_id; seq by start time; attempt = retry_count+1. Agent version resolved by instance_id, else the highest registered version. Executions of unregistered agent nodes are archived (unknown_agent) unless --synthesize-missing-agents. A session that no longer exists yields session_id NULL (reported), never an invented session.
    workflow_execution_events (of native trees)eventstype legacy.<event_type>, ordered by emitted_at, renumbered per root; payload and legacy identifiers kept under data.legacy. Root event_seq set accordingly.
    BoltDB memory (kv_store_path) or PostgreSQL kv_store (JSONB types.Memory)memoryglobal → scope global (scope_id ""); session → owning imported session; workflow → the imported root traverser of that workflow; actor → scope actor with the legacy actor id (vNext binds actor scope to the authenticated principal, so only a principal named exactly like the legacy actor reads it; --actor-memory archive to skip). revision=1; Go ttl → expires_at. reasoner scope, dangling sessions/workflows, values that are not a types.Memory object and key collisions are archive-only. Both memory sources go through the same mapping; the same fixture yields identical memory rows.
    memory_events, distributed_locks (PostgreSQL mode only)archive onlyChange feed and lock state of the parent; the runtime keeps its own (memory_changes, leases).
    attempts, workers, leases—Not fabricated. Imported traversers have no attempts; path shows attempts: [].
    execution_vcs, workflow_vcs, agent_tag_vcs, did_registry, agent_dids, component_dids, did_documentsarchive onlyLegacy proofs and identities are historical facts about the parent graph server. They are stored verbatim, never re-signed, and no node_keys/signed_paths rows are created. --redact-identity-material stores only a SHA-256 of did_registry.master_seed_encrypted. verify-proof checks the preserved proofs afterwards (see below).

    Legacy execution_logs, usage, workflow_runs/workflow_steps rows and proofs remain queryable in the archive but are not served by the vNext API. Raw archival storage does not make a legacy traverser continuable, replayable or verifiable in vNext; it makes it inspectable.

    The archive store

    <destination stem>.legacy-archive.sqlite3 (override with --archive), format version 1 (migration/archive.py). The vNext runtime never opens it.

    • archive_meta: format version, tool version, run id, source paths and digests, source ledger, policy, native counts, proof note.
    • legacy_tables: every source table with its DDL and row counts.
    • legacy_rows: every source row as typed JSON (blobs base64), its disposition (native/archive), reason, and the native id it became.
    • legacy_memory: every BoltDB record, raw and decoded, with disposition.
    • id_map: (kind, legacy_id) → native_id for agent, session, traverser, step; both directions unique.
    • findings: the same warnings the report prints.

    The destination records the import in atfgraph_legacy_import (run id, source digest, archive path and SHA-256, policy, counts). migrate.py archive --archive … summarises an archive.

    Verifying preserved proofs

    migrate.py verify-proof --archive <archive> [--truststore keys.json] [--json] checks the parent's preserved credentials offline against the parent's actual historical formats (migration/proofs.py; formats, statuses and evidence in docs/historical-proof-evidence.md). It reads the archive read-only, never opens the parent or the destination, never re-signs anything and never reads private key material (did_registry.master_seed_encrypted is not even selected). Each record is verified, invalid (signature mismatch, tampered or inconsistent row, broken chain reference) or unverifiable (no proof, unsupported proof type, no public key, oversized document, or a format the parent never stored proof material for: workflow_vcs). verified states where the key came from (key_source, issuer_binding, trust); only --truststore yields trust: caller_truststore. Exit codes: 0 every selected record verified, 5 at least one invalid, 6 at least one unverifiable or nothing selected. --document <file> verifies one standalone credential document (for example the workflow credential the parent's chain API returned). fixture --real-proofs builds a rehearsal parent store with real Ed25519 proofs from the Go-generated fixture under migration/fixtures/historical_proofs/.

    Backup and restore (vNext SQLite)

    • backup copies a live vNext store with the SQLite online-backup API in one read transaction (consistent even while the daemon writes; uncommitted work is excluded), verifies integrity, and writes graph.sqlite3 plus manifest.json (SHA-256, size, applied runtime migrations, per-table row counts, legacy-import ledger, product and distribution identity from ../project.yaml). The directory is staged and renamed into place.
    • verify re-checks checksum, size, integrity_check, migrations and counts.
    • restore verifies first and refuses an existing destination. With --replace it moves the current file(s) aside as <name>.pre-restore-<ts>; a non-empty -wal is refused because it means the daemon is running or exited uncleanly. The restored copy is validated against the manifest and linked into place. The report lists rows present before the restore but absent from the backup.

    Restore is a rollback to the backup point. Every write the daemon made after the backup is gone from the live store (kept only in the moved-aside file). Nothing else is rolled back: workers, the legacy archive, or state held by callers.

    Backup and restore (vNext PostgreSQL)

    Logical, driver-only (no pg_dump), same manifest contract with "backend": "postgres":

    • backup --database-postgres opens one READ ONLY REPEATABLE READ transaction and COPYs every base table of the current schema (in primary-key order, explicit column list) into tables/<name>.copy; a write committed by another session after the snapshot is not in the backup. The manifest records per-table columns, row counts, SHA-256 and size, a combined SHA-256, applied runtime migrations, the legacy-import ledger, the server version and snapshot, the redacted DSN, and the distribution identity from ../project.yaml. The directory is staged and renamed into place.
    • verify re-checks every file's size, SHA-256 and row count (one COPY line per row), the combined digest and the manifest's internal consistency.
    • restore --destination-postgres verifies first, refuses a database with other client connections (destination_active: stop the daemon), refuses a database that already holds vNext data unless --replace, then in one transaction under the runtime advisory lock: applies the runtime migrations from migrations/, requires the applied set to equal the manifest's (migrations_mismatch otherwise: a backup is restored into the schema version it was taken from), creates the legacy-import ledger table if the manifest has it, truncates all manifest tables in one statement, COPYs them back in foreign-key dependency order, and verifies the counts before COMMIT. lock_timeout is 5 s so a contended table fails instead of hanging. The report lists rows present before the restore but absent from the backup (data tables only).

    As on SQLite, a PostgreSQL restore is a rollback to the backup point for the database only; other databases, workers and the legacy archive are untouched.

    Operating procedure

    1. Stop the parent graph server. plan warns when a SQLite source -wal is non-empty.
    2. plan --source … (or --source-postgres env:PARENT_DSN) and read the report: native counts, per-table dispositions and reasons, findings.
    3. run --source … --destination <new path>; the parent's kv.db next to the source is used automatically, or pass --source-memory. PostgreSQL: run --source-postgres env:PARENT_DSN --destination-postgres env:VNEXT_DSN --archive <path> into an empty database you created (CREATE DATABASE); memory comes from the parent's kv_store table automatically.
    4. Start the vNext daemon on the destination (`--database-url sqlite://<path>?mode=rwc or --database-url postgresql://…); the imported agents, traversers, paths, event logs and memory are served through /api/v2. The daemon must be at least as new as the migrations/` directory the importer applied (it skips versions already recorded).
    5. backup --database <destination> / --database-postgres env:VNEXT_DSN --out <dir> before opening it to traffic; verify; keep the archive next to the backup.

    Rehearse on a synthetic store first: fixture --out /tmp/legacy creates a parent-shaped SQLite/BoltDB store, fixture --postgres env:EMPTY_DSN fills an empty PostgreSQL database with the parent's postgres-mode schema (captured from a real parent start) and the same data, memory in kv_store.

    Not supported

    • Cross-backend migration (SQLite parent → PostgreSQL vNext or the reverse); the archive is always a SQLite file.
    • The parent's Lakebase/Databricks-token PostgreSQL authentication and non-default schema search paths: the tool connects with the connection string it is given (static credentials) and reads the connection's current schema.
    • pg_dump-format backups; the PostgreSQL backup is the tool's own COPY format and is restored only by this tool into the same migration version.
    • Payload/VC documents kept outside the database (input_uri, result_uri, storage_uri, the parent's file keystore under ~/.atfgraph). Only what is in the database (and BoltDB file) is read.
    • Continuation of unfinished legacy traversers (the parent's executions), approvals or leases.
    • Re-signing legacy proofs or deriving vNext node identities from legacy DIDs.
