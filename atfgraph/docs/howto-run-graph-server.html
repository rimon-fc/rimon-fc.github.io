    Run the graph server

    Problem: you need a graph server running, configured and stoppable on this machine.

    Start it

    The server is Rust, at the root of this repository (src/). From the checkout:

    cargo build --bin atfgraphd --bin atfg
(cd ui && npm ci && npm run build)      # once, for the console at /ui/
export PATH="$PWD/target/debug:$PATH"
atfg server start
atfg server status

    An installed self-host bundle has the same binaries under <prefix>/bin; a client install has atfg only and talks to a server elsewhere.

    atfg server start:

    1. Probes http://127.0.0.1:18880/health. If ATFGraph vNext already answers, nothing is started. If another product answers, it refuses.
    2. Locates atfgraphd next to the atfg binary, or at --daemon / ATFGRAPHD_BIN.
    3. Spawns it detached with --listen, optional --config and --database-url, logs to a file, and writes pid metadata to ~/.atfgraph-vnext/server-<listen>.json (override the directory with --state-dir or ATFGRAPH_VNEXT_HOME).
    4. Waits up to --wait seconds for /health. If the daemon exits early, the tail of its log is printed.

    --foreground runs the daemon attached to your terminal instead. To run a second server, or one on a throwaway database:

    atfg server start --listen 127.0.0.1:18890 \
  --database-url "sqlite:///tmp/scratch/graph.db?mode=rwc" \
  --state-dir /tmp/scratch/state

    Stop it

    atfg server stop

    stop reads the pid record and signals only that pid, and only if the pid still runs a process named atfgraphd. A reused pid is reported and left alone. A dead pid just clears the record. It never scans for processes and never stops a server it did not start.

    Configure it

    The daemon reads YAML in the contract shape:

    atfgraph:
  server:
    listen: 127.0.0.1:18880
  storage:
    url: sqlite://./data/graph.db?mode=rwc      # or postgres://user:pass@host/db
  execution:
    lease_seconds: 30
  auth:
    tokens:
      - token: a-long-random-value
        namespace: local
        principal: operator
        roles: [admin]                          # admin | invoke | worker

    Environment overrides: ATFGRAPH_CONFIG_FILE, ATFGRAPH_LISTEN, ATFGRAPH_DATABASE_URL, ATFGRAPH_LEASE_SECONDS, ATFGRAPH_API_KEY (a single key that grants the local namespace admin).

    Loopback without keys is development mode. The daemon refuses to start on a non-loopback address with no tokens and no ATFGRAPH_API_KEY.

    Validate a file before starting:

    atfg config validate deploy/config/atfgraph.yaml          # exit 0 valid, 1 invalid
atfg config validate my.yaml --strict                     # warnings also fail
atfg --json config validate my.yaml

    The validator checks the shape, listen as ip:port, the storage URL scheme, lease_seconds > 0, every token's token/namespace/principal/roles, duplicate tokens, unknown keys (warnings), and the non-loopback-without-tokens rule. It also notes which override variables are set in your shell. A failing file looks like this:

    error: atfgraph.storage.url: `mysql://x` must start with sqlite: or postgres://
error: atfgraph.server.listen: 0.0.0.0:18880 is not loopback and no auth tokens are configured; the daemon refuses to start this way (set auth.tokens or ATFGRAPH_API_KEY)
invalid: 2 error(s), 0 warning(s)

    Check it

    GET /health is unauthenticated liveness. GET /api/v2/server reports the build:

    {"api_version":"v2","features":{"a2a":false,"durable_execution":true,"managed_deployment":false,"mcp":true,"outbound_workers":true},"namespace":"local","product":"ATFGraph vNext","version":"0.1.0","worker_protocol":"v1"}

    atfg doctor checks the binaries, the state directory, the Python interpreter and whether it can import atfgraph, and the presence of container and cluster tools.

    Prune it

    The database grows with every run. Two administrator operations trim it, both read-only until you say otherwise:

    # What would go: the journal of runs that finished before the cutoff.
curl -s -X POST "$ATFGRAPH_URL/api/v2/retention/plan" -H "X-API-Key: $KEY" \
  -H 'content-type: application/json' -d '{"cutoff": "2026-06-01T00:00:00Z"}'
# Do it, one run at a time under a lock; repeat until "scanned" is 0.
curl -s -X POST "$ATFGRAPH_URL/api/v2/retention/apply" -H "X-API-Key: $KEY" \
  -H 'content-type: application/json' -d '{"cutoff": "2026-06-01T00:00:00Z", "dry_run": false}'

    mode: "journal" (the default) deletes events, attempts, execution artifacts, signed paths, node logs, decided approvals and checkpoints of finished run trees. The runs themselves, their usage, run metadata, sessions and memory stay, so idempotency keys remain spent and traversers.get keeps answering.

    mode: "sessions" deletes the brief artifacts (files attached to a session before a run, as the Console's Studio does) of sessions whose last activity is older than the cutoff and that have no active turn and no unfinished run. The session, its runs, memory and knowledge stay. It pages with cursor / next_cursor instead of after_seq:

    curl -s -X POST "$ATFGRAPH_URL/api/v2/retention/apply" -H "X-API-Key: $KEY" \
  -H 'content-type: application/json' \
  -d '{"mode": "sessions", "cutoff": "2026-06-01T00:00:00Z", "dry_run": false}'

    The per-file and per-session size caps for brief artifacts are configuration, not retention: brief_artifacts.max_file_bytes (default 25 MiB) and brief_artifacts.max_session_bytes (default 100 MiB), or the environment variables ATFGRAPH_BRIEF_ARTIFACT_MAX_BYTES and ATFGRAPH_BRIEF_SESSION_MAX_BYTES. Deleting a session (DELETE /api/v2/sessions/{id}) removes its brief artifacts at once.
