    Core concepts

    Ten nouns. Every CLI command, console label and SDK docstring uses exactly these words, so once you know them the rest of the documentation reads directly. The full vocabulary, including the structural terms, is in the repository's graph model document; this page is the subset you need first.

    Graph server

    The server that owns the graph. It routes every edge, schedules traversers, stores memory and records paths. It is the only inbound endpoint in the system: clients call it, workers connect out to it, and nothing calls a node directly. Binary: atfgraphd. Default address: 127.0.0.1:18880.

    Agent node

    A deployable process that registers under a label (for example hello) with a version and a set of traversals and skills. In Python it is an Agent object run by python -m atfgraph.worker. Registration is immutable per version: to change what a node offers, register a new version.

    Traversal

    An LLM-backed function on an agent node. It decides its own route through the graph by calling other traversals and skills with await app.traverse(...). Declared with @app.traversal().

    Skill

    A deterministic function on an agent node. No model, no routing decision. It does one thing and returns. Declared with @app.skill(). Traversals call skills; skills do not call anything through the graph.

    Traverser

    One live walk through the graph, started by a request or an emitter. It has an id, a status (queued, running, waiting, succeeded, failed, cancelled, timed_out), memory and a path. atfg traverse starts one; atfg ps lists them; atfg wait blocks at the barrier until one is terminal. The word is always traverser, in the CLI, the console and the SDK.

    Path

    The recorded sequence of steps a traverser took. atfg path <id> prints it; the console shows it; atfg share <id> exports it as a self-contained file. When node identity is enabled, each step also carries a signature, and the chain of signatures is a signed path that can be verified offline.

    Step

    One edge as recorded in a path: which target was called, by which parent step, with what status, attempt number and elapsed time. In the quickstart, the traversal hello.greet is step 1 and the skill hello.shout it called is step 2, with step 1 as its parent.

    Decision

    A traversal whose job is one typed judgement: it calls a model, returns a schema, and reports its own confidence. Declared with @app.decision() and dispatched exactly like a traversal; the kind travels onto the step, and confidence_field= on app.ai records the confidence and any fallback on the usage row, so unsure and fallen-back decisions can be counted per capability. See Decisions.

    Harness

    A coding-agent CLI (the bundled harness, Claude Code, Codex, Gemini CLI or OpenCode) run as one bounded step of a traversal with app.harness: confined to a directory, tools off unless listed, a wall-clock deadline and a dollar cap, every CLI event a progress event on the path. See Delegating to a coding harness.

    Emitter

    An external event source that starts a traverser without a caller: a cron schedule, an inbound webhook or a queue. Emitters are declared on traversals and have their own delivery log. The console's Triggers page configures and fires them.

    How they fit together

    1. An agent node registers its label, version, traversals and skills with the graph server and then claims work from it as an outbound worker.
    2. A request (or an emitter) starts a traverser on label.capability.
    3. The graph server hands the task to a worker for that label. Inside the traversal, each app.traverse(...) call goes back through the server, which records it as a step and routes it to the right node.
    4. When the traverser is terminal, its path holds every step, and atfg wait returns from the barrier.

    Two words you will also meet: a session is one conversation across many traversers, and memory is key-value state scoped to global, session, actor or workflow that traversers read and write.
