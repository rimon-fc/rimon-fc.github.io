Type to search.

    Discovery publication

    Set policy in the graph server YAML selected by ATFGRAPH_CONFIG_FILE:

    atfgraph:
  protocols:
    mcp_enabled: true
    a2a_enabled: true
    public_base_url: https://graph.example.test
  ard:
    enabled: true
    publish_catalog: true
    public_registry: false

    GET /api/v2/ard/settings explains effective policy and its YAML source. The same three switches can be set from the environment as ATFGRAPH_ARD_ENABLED, ATFGRAPH_ARD_PUBLISH_CATALOG and ATFGRAPH_ARD_PUBLIC_REGISTRY (ATFGRAPH_MCP_ENABLED, ATFGRAPH_A2A_ENABLED and ATFGRAPH_PUBLIC_BASE_URL for the protocols). publish_catalog defaults to false, so a fresh server answers POST /api/v2/ard/publications with 403 publication_disabled and the catalog with 404 until it is enabled; the console's Agents → Publish tab says so and shows the fix. Publishing also requires protocols.public_base_url (the address callers will use; http://127.0.0.1:18880 for a local server), otherwise the request is refused with 403 public_url_required. Changing these deployment settings requires a restart (atfg server stop && atfg server start --config <file>). Public catalog publication and unauthenticated registry search are separate controls. Only explicitly published records appear in the catalog. Starting a traverser continues to require the graph server credentials.

    An administrator publishes a registered node using POST /api/v2/ard/publications:

    {"label":"co-consult","artifact_type":"mcp","display_name":"Travel consultant","published":true}

    Use artifact_type of mcp, a2a or http. The selected protocol must already be enabled. Publication does not create a worker or switch on a protocol. Published MCP and A2A URLs include the immutable node version, so later registrations do not change the published invocation target. The immutable definition version is recorded; configured validation establishes the local registered definition and protocol, not remote reachability.

    GET /api/v2/ard/publications and POST /api/v2/ard/search are namespace-scoped; search accepts {"query": "...", "tags": [...]} and returns publications carrying any of the tags (node and capability tags are frozen into the publication at publish time). Realtime entrypoints appear only in http artifacts; a node whose every capability is realtime cannot be published over mcp or a2a (422 realtime_http_only). DELETE /api/v2/ard/publications/{id} removes a record. Publishing again updates the same node/version/protocol record.

    The opt-in public manifest is /.well-known/ai-catalog.json, published artifact documents are /ard/artifacts/{id}, and registry search is /ard/agents?query=travel. Registry search requires credentials unless public_registry is true. A disabled protocol is removed from public results after restart even when its publication record is retained. Public artifacts use the currently configured base URL and authentication requirements after restart.

    Publication and search apply to the catalog on this graph server. Register and run the node on this server before publishing its capabilities.
