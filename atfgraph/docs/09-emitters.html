    Emitters: schedules and webhooks

    By the end of this page a capability on your agent node fires on a cron schedule or on an authenticated webhook delivery, reads the emitter's TriggerContext, reshapes a provider payload with a transform, and you can inspect, fire, replay and pause the emitters the graph server created. It requires a running graph server and a worker; for webhooks the source's secret must be present in the environment of the graph server process, never in the worker.

    Prerequisites: a webhook source needs its secret exported on the graph server host under the name you pass as secret_env (the daemon reads it; the SDK never does).

    How emitters work

    An emitter is a persistent server-side definition, either a schedule or a webhook source, that admits one traverser per delivery. A capability declares its emitters in code with triggers=[...] on @app.traversal() / @app.skill(), or with the @on_schedule / @on_event sugar. When app.serve() (or app.run()) starts and Agent(sync_emitters=True) is in effect (the default), the worker registers the node and then calls app.sync_emitters(), which posts one binding per (capability, source). The server upserts a code-managed emitter for each binding and marks bindings that disappeared as orphaned and disabled. Emitters created through Emitters.create or the web console are UI-managed and never touched by a sync.

    Two rules from python/atfgraph/emitters.py matter for input handling:

    • A code-managed delivery bypasses the server's input-schema check at admission. The worker then applies the binding's transform (if any), binds the result to the handler's parameters and validates it against the capability's input_schema before the handler runs.
    • A UI-managed delivery is validated against the input schema by the server on admission and reaches the handler unchanged; no transform runs.

    A capability may declare at most one binding per source; two EventTrigger(source="github") on one capability raise ValueError at import time.

    Declare a schedule

    ScheduleTrigger takes exactly one of cron (5 fields, or 6 with leading seconds) or every_seconds (1 to 31536000), an IANA timezone (default UTC) and a JSON object input that the handler receives on every tick. Adapted from examples/python/features/schedule_emitter/agent.py:

    from __future__ import annotations

from atfgraph import Agent, ScheduleTrigger, TriggerContext, on_schedule

app = Agent(node_id="ticker", version="1.0.0", description="Scheduled fixture ticks")


@app.traversal(triggers=[ScheduleTrigger(cron="* * * * * *", input={"region": "AU"})])
async def tick(region: str, trigger: TriggerContext) -> dict:
    count = await app.memory.global_scope().update(f"ticks:{region}", lambda current: (current or 0) + 1)
    return {"region": region, "count": count, "delivery_key": trigger.idempotency_key, "emitter_id": trigger.emitter_id}


@app.skill()
@on_schedule(every_seconds=1)
async def heartbeat(trigger: TriggerContext | None = None) -> dict:
    beats = await app.memory.global_scope().update("heartbeats", lambda current: (current or 0) + 1)
    return {"beats": beats, "via_emitter": trigger is not None}


if __name__ == "__main__":
    app.run()

    @app.traversal() stays the outermost decorator; @on_schedule only stages the trigger. Run the worker and it logs each synced emitter:

    python -m atfgraph.worker --module examples.python.features.schedule_emitter.agent:app
python -m examples.python.features.schedule_emitter.inspect_emitters

    tests/test_emitter_authoring.py runs this against the real daemon and asserts: the emitter is named code:ticker:heartbeat:cron, every tick's trigger.source is cron, event_type is tick, managed_by is code, each delivery key starts with schedule: and is unique per due time, so a restarted server never fires the same due time twice. This snippet needs no model provider.

    Declare a webhook

    EventTrigger(source, types, secret_env, config, transform) binds a capability to an authenticated source. types filters event types on the server (exact match, or a dotted prefix; empty or "*" means all). config holds header and tolerance settings for the generic sources.

    SourceSignature the server checksWhere the event type and delivery key come from
    stripeStripe-Signature: t=<ts>,v1=<hmac> over <ts>.<body>Stripe's type and event id
    githubX-Hub-Signature-256: sha256=<hmac> over the bodyX-GitHub-Event, X-GitHub-Delivery
    slackX-Slack-Signature: v0=<hmac> over v0:<ts>:<body>Slack event callback
    generic_hmachex HMAC of the body in signature_header (default X-Signature)event_type_header, idempotency_header
    generic_bearerAuthorization: Bearer <secret>event_type_header, idempotency_header
    databricksbasic or bearer per auth_modedotted event_type_path / event_id_path overrides

    Not verified: the exact header and payload layout of the databricks source; I read the EventTrigger docstring and the emitter creation in tests/test_databricks_integration.py but not the source's server-side verification. The other five are exercised end to end by tests/test_emitter_authoring.py and tests/test_migrated_ops_examples.py.

    Adapted from examples/python/features/webhook_emitter/agent.py:

    from __future__ import annotations

from typing import Any, Dict, Optional

from pydantic import BaseModel

from atfgraph import Agent, EventTrigger, TriggerContext, on_event

app = Agent(node_id="hooks", version="1.0.0")


class Payment(BaseModel):
    id: str
    amount: int
    currency: str = "aud"
    customer: Optional[str] = None


def _payment_from_event(event: Dict[str, Any]) -> Dict[str, Any]:
    obj = event["data"]["object"]
    return {"id": obj["id"], "amount": obj["amount"], "currency": obj.get("currency", "aud"), "customer": obj.get("customer")}


@app.traversal(
    triggers=[
        EventTrigger(
            source="generic_bearer",
            types=["payment.succeeded"],
            secret_env="HOOKS_PAYMENT_SECRET",
            config={"idempotency_header": "X-Delivery-Id", "event_type_header": "X-Event-Type"},
            transform=_payment_from_event,
        )
    ]
)
async def handle_payment(payment: Payment, trigger: TriggerContext | None = None) -> dict:
    return {"payment_id": payment.id, "amount_cents": payment.amount, "delivery_key": trigger.idempotency_key if trigger else None}


@app.traversal()
@on_event("github", types=["pull_request"], secret_env="HOOKS_GITHUB_SECRET")
async def handle_pr(event: dict, trigger: TriggerContext | None = None) -> dict:
    pr = event.get("pull_request") or {}
    return {"action": event.get("action"), "title": pr.get("title")}

    Start the daemon with HOOKS_PAYMENT_SECRET and HOOKS_GITHUB_SECRET in its environment, then run the worker. After the sync app.webhook_urls() returns {"handle_payment": ".../hooks/<id>", "handle_pr": ...}; the server owns the URL /hooks/{emitter_id}.

    Declare a memory trigger

    A memory source fires when a memory key is written or deleted, so a reasoner can react to state instead of polling the change feed. The emitter is kind: event, source: memory, and source_config names the scope (global, session, actor or workflow), an optional scope_id, an optional key prefix, the entry kinds (value, vector) and actions (set, delete) to react to. Each matching change admits one traverser to the target with input {key, scope, scope_id, action, kind, revision, principal, value?}; value is included only for set and only when it is 16 KiB or smaller. The delivery key memory:<scope>:<scope_id>:<key>:<revision> makes a replay idempotent, and a failed admission never fails the memory write; it is counted in GET /api/v2/emitters/metrics as memory_dispatch_failures.

    from atfgraph import Agent
from atfgraph.decorators import on_event

app = Agent(node_id="briefs")


@app.traversal()
@on_event(source="memory", config={"scope": "global", "prefix": "brief.", "actions": ["set"]})
async def brief_changed(key: str, action: str, revision: int, value: dict | None = None) -> dict:
    return {"key": key, "revision": revision, "summary": (value or {}).get("destination")}

    From the console, Build → Triggers → Create trigger → kind "memory change" builds the same emitter.

    Transforms and input binding

    A transform is a synchronous callable (an async def raises TypeError at declaration) applied by the worker to the raw event of a code-managed delivery. bind_trusted_input then binds the result in this order: a dict whose keys are all handler data parameters and that covers every required one binds as keyword arguments; otherwise a handler with exactly one data parameter receives the whole payload there (this is how handle_pr gets the raw GitHub event as event); a handler with no data parameter drops the payload. Anything else fails the traverser with invalid_input.

    The daemon test shows the failure modes. A transform that raises (KeyError on a malformed envelope) fails the traverser with error code transform_failed and the worker keeps serving. A transform that succeeds but produces amount="lots" fails with invalid_input before the handler is invoked. In both cases the handler never ran, which the test checks through global memory.

    Read the TriggerContext

    Declare a parameter named trigger or webhook, or annotate any parameter with TriggerContext, and the worker injects it. It is None for ordinary calls, so give it a default when the capability is also called directly.

    FieldMeaning
    trigger_id / emitter_idthe emitter's server id, also its webhook slug
    source, event_type, event_idwhat the server authenticated
    idempotency_keythe delivery key the server deduplicated on
    received_ataware UTC datetime
    managed_by / code_managed"code" for declared bindings, "ui" for manual emitters

    Inside the handler app.ctx.trigger and app.ctx.via_emitter expose the same object.

    Duplicate suppression, filtering and dead letters

    Behaviour observed in tests/test_emitter_authoring.py against the daemon:

    • A wrong bearer token or HMAC is refused with 401 and nothing is admitted.
    • A second delivery with the same key returns 202 with the same event id and traverser id; the handler ran once. The same key with a different body is 409.
    • An event type not in types is stored with status filtered and no traverser.
    • A UI-managed delivery whose raw input fails the schema is 202 with status failed, error code invalid_input, and lands in the dead-letter list; Emitters.metrics() reports dlq_depth.

    Manage emitters from code

    app.emitters (or Emitters(client) from any Client) wraps the /api/v2/emitters routes. Adapted from examples/python/features/schedule_emitter/inspect_emitters.py and the daemon test:

    import asyncio
import os

from atfgraph import Client, Emitters


async def main() -> None:
    async with Client(os.getenv("ATFGRAPH_SERVER")) as client:
        emitters = Emitters(client)
        for emitter in await emitters.list():
            print(emitter.name, emitter.target, emitter.managed_by, emitter.enabled, emitter.orphaned)
            for event in (await emitters.events(emitter.id))[:5]:
                print("   ", event.delivery_key, event.status, event.traverser_id)
        manual = await emitters.create(
            "manual-receive", "hooks.receive", source="generic_bearer",
            secret_env="HOOKS_PAYMENT_SECRET", source_config={"idempotency_header": "X-Delivery-Id"},
        )
        fired = await emitters.fire(manual.id, "fire-1", input={"value": 7})
        print(await fired.result(timeout=10))
        current = await emitters.get(manual.id)
        await emitters.update(manual.id, expected_revision=current.revision, enabled=False)


if __name__ == "__main__":
    asyncio.run(main())

    fire admits the target by hand with an explicit delivery key: repeating the key returns the same traverser, no emitter context is attached (trigger is None), and input is validated normally. replay(emitter_id, event_id) re-delivers a stored inbound event under a fresh key and runs the handler again. update needs expected_revision; disabling a code-managed emitter sets sticky_paused and its webhook URL answers 404 until re-enabled. A code-managed emitter cannot be deleted while its binding exists (409); remove the trigger from code and the next sync orphans it instead. update(managed_by="ui") converts a code-managed emitter to UI management, never the reverse. create, sync, replay and update are administrator operations.

    Test a handler without a server

    simulate_trigger runs a registered handler in-process as if a delivery had arrived: it applies the matching transform for managed_by="code", binds and validates exactly like the worker, and injects a synthetic TriggerContext. Adapted from tests/test_migrated_ops_examples.py:

    import asyncio

from atfgraph import simulate_trigger
from examples.emitters.python.agent import app


async def main() -> None:
    result = await simulate_trigger(
        app.entry("handle_tick"), source="cron", body={}, event_type="tick",
        event_id="evt-1", idempotency_key="schedule:2026-01-01T00:00:00Z",
    )
    print(result)


if __name__ == "__main__":
    asyncio.run(main())

    This still needs a graph server if the handler touches app.memory, as handle_tick does; the test runs it with the worker bound to a real daemon. The full end-to-end check is the daemon fixture pattern in ./15-testing.md.
