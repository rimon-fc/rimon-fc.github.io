    Hosting a node

    By the end of this page you can run an agent node as a long-running worker with a clean shutdown, as one bounded invocation per event through serverless_host, and open a realtime provider session from inside a handler; you also know where the container and Compose guides pick up. It requires a running graph server; the realtime section additionally needs a provider key on the worker host.

    Long-running worker

    app.run() is the foreground entry: it installs SIGINT/SIGTERM handlers that set a stop event, then awaits app.serve(). app.serve() registers the definition (unless register=False), syncs emitter bindings, enrols an outbound worker, and claims until stop is set; on the way out it drains the worker and stops the node-log flusher. Adapted from examples/python/container_node/agent.py:

    import asyncio
import logging
import os
import signal

from atfgraph import Agent

app = Agent(node_id="container-node", version="1.0.0")
log = logging.getLogger("container-node")
if os.getenv("ATFGRAPH_DEMO_SHIP_LOGS") == "1":
    app.enable_node_logs(log)


@app.traversal()
async def hello(name: str = "ATFGraph") -> dict:
    log.info("Greeting a traveller")
    return {"greeting": f"Hello, {name}!", "node_id": app.node_id}


async def main() -> None:
    stop = asyncio.Event()
    loop = asyncio.get_running_loop()
    for sig in (signal.SIGINT, signal.SIGTERM):
        loop.add_signal_handler(sig, stop.set)
    try:
        await app.serve(stop=stop)
    finally:
        await app.client.aclose()


if __name__ == "__main__":
    asyncio.run(main())

    Writing main() yourself, instead of app.run(), lets you run other tasks next to the worker on the same loop, as the example does with a heartbeat printer. This snippet needs no provider.

    Startup behaviour

    serve(startup_timeout=30.0) retries registration and enrolment while the graph server is unavailable: TransportError and HTTP 429, 502, 503, 504 are retried with backoff up to 2 seconds until the deadline, after which TimeoutError("graph server startup timed out") is raised. Authorization, validation and immutable-definition conflicts raise immediately; the conflict message tells you to bump Agent(version=...). startup_timeout=0 makes a single attempt. Setting stop during startup cancels the outstanding request and serve returns without serving.

    Worker options

    The same options are available on app.serve() / app.run() and on the module CLI:

    CLI flagMethod argumentEffect
    --module module:attrthe Agent to load (app, then agent, when no attribute is given)
    --server URLAgent(graph_server=...)default $ATFGRAPH_SERVER or http://127.0.0.1:18880
    --api-key KEYAgent(api_key=...)default $ATFGRAPH_API_KEY
    --capacity Ncapacity=concurrent handler permits (default Agent(capacity=8))
    --max-waiting NAgent(max_waiting=...)parents allowed to release their permit while awaiting children (default 4 x capacity)
    --onceonce=Trueexit when the queue is empty and nothing is running
    --no-registerregister=Falseskip registration (the definition must already exist)

    python -m atfgraph.worker --module examples.python.container_node.agent:app --capacity 4
python -m atfgraph.worker --module examples.python.container_node.agent:app --once
atfg dev --module examples.python.container_node.agent:app --expect-label container-node

    --once is the queue-drain mode: the worker claims what is queued, finishes it and returns, which is how ServerlessHost runs the same Worker under the hood. atfg dev wraps python -m atfgraph.worker against a local graph server and reports when the label is registered; atfg install / atfg run manage a detached worker from an agentnode.yaml package (see ../howto-install-a-node.md).

    Serverless host: one bounded invocation per event

    atfgraph.serverless.ServerlessHost(agent, max_duration=30.0) (or serverless_host(app) / serverless_host("module:app")) maps a function-per-event runtime onto the outbound lease protocol. Nothing calls handlers directly: invoke submits a real traverser to the graph server and then runs the node's Worker with once=True, so the handler runs under a real ExecutionContext, every step is on the path, and memory, checkpoints, approvals and progress behave as in a daemon worker. Adapted from examples/python/on_demand_node/agent.py:

    from atfgraph import Agent
from atfgraph.serverless import ServerlessHost

app = Agent(node_id="on-demand-node", version="1.0.0", capacity=2)


@app.traversal()
async def hello(name: str = "ATFGraph") -> dict:
    ctx = app.ctx
    return {"greeting": f"Hello, {name}!", "traverser_id": ctx.traverser_id if ctx else None}


@app.traversal()
async def ping_child(target: str, message: str) -> dict:
    return {"from": app.node_id, "child": await app.traverse(target, name=message)}


host = ServerlessHost(app, max_duration=20)
handler = host.entrypoint()

    The event shape is generic: a dict (or a dict with a JSON-string body) with action, and for invoke a capability (bare or label.capability), an input object, optional session_id, idempotency_key, timeout_seconds and include_path. Responses are {"statusCode", "body"}.

    ActionWhat happensStatus
    invokesubmit, serve once, return the terminal state with output or error, worker stats, and path when asked200 succeeded, 500 failed, 409 cancelled, 504 timed out
    serveclaim and finish whatever is queued for this node until idle or the deadline200 with completed and claimed counts
    drainmark the enrolled worker draining on the server and forget it200
    discoverreturn app.definition()200
    a bad event, an unknown capabilityhandle never raises for these400, 404
    graph server unreachable503 graph_server_unavailable

    await host.handle(event) is the async entry; host.handle_sync(event) runs a fresh event loop per call and closes the client's connections at the end (the worker enrolment survives across calls); host.entrypoint() returns handler(event, context) and, when context.get_remaining_time_in_millis() exists, caps the budget to that minus safety_margin. Wiring to a specific cloud runtime is the deployer's step; the module states this is verified only against the local graph server.

    When the deadline passes mid-handler the host abandons the lease instead of inventing a result: the response is 202 with the traverser id and a note, the server requeues the traverser while max_attempts allows (the first attempt is recorded with error lease_expired) and a later serve finishes it. tests/test_python_controls.py asserts exactly this against the daemon. Sync handlers in worker threads cannot be interrupted by that deadline; their result is discarded.

    python -m examples.python.features.serverless.invoke quote '{"legs":[{"origin":"BNE","destination":"SYD"}]}'
python -m examples.python.features.serverless.invoke --action serve
python -m examples.python.features.serverless.invoke --action drain

    examples/python/features/serverless/agent.py combines the host with RateLimiter and ResultCache; see ./11-resilience-and-controls.md.

    Realtime sessions

    await app.realtime_session(model=..., provider="openai", transport="websocket", **options) opens a live provider session from the worker process; no server change is involved, and the usage from each turn is recorded on the running traverser through app.record_usage. Three provider and transport pairs exist in python/atfgraph/realtime.py:

    provider / transportMechanismNeeds
    openai / websocketRFC 6455 client over asyncio streams, no third-party packageOPENAI_API_KEY
    openai / webrtcSDP offer to /v1/realtime/calls, events on the oai-events data channel, audio on the media trackOPENAI_API_KEY and the optional aiortc package
    openrouter / audio_turnsone chat-completions HTTP request per turn() with input_audio partsOPENROUTER_API_KEY

    A browser voice call should never see the provider key. The pattern is a node skill that mints a short-lived client secret with the server-side key, a page that asks for it through the graph server and opens WebRTC to the provider with that secret only, and a second skill that records each transcript turn so the conversation lands in the run path and session memory. examples/python/realtime_browser (realtime-browser.session_token, .turn, .transcript plus static/index.html) is that pattern end to end, with a fixture mode that runs without any credential.

    validate_session_transport(provider, transport) raises SessionTransportError for any other pair. Without aiortc, openai/webrtc raises RealtimeError naming the optional package; the SDK does not depend on it. The default model comes from model= or ATFGRAPH_REALTIME_MODEL; without either, ValueError. Adapted from examples/python/features/realtime/agent.py:

    from typing import Optional

from atfgraph import Agent, HandlerError
from atfgraph.realtime import RealtimeError, SessionTransportError, validate_session_transport

app = Agent(node_id="voice", version="1.0.0")


@app.traversal()
async def say(text: str, transport: str = "websocket", voice: Optional[str] = None, model: Optional[str] = None) -> dict:
    try:
        validate_session_transport("openai", transport)
    except SessionTransportError as exc:
        raise HandlerError(str(exc), code="unsupported_transport") from exc
    try:
        session = await app.realtime_session(model=model or "gpt-realtime", transport=transport, instructions="Answer in one short sentence.", modalities=["text", "audio"], voice=voice)
        async with session:
            turn = await session.ask(text, timeout=60)
    except RealtimeError as exc:
        raise HandlerError(str(exc), code="realtime_error") from exc
    return {"text": turn.text, "transcript": turn.transcript, "usage": turn.usage, "cost_usd": turn.cost_usd, "cost": app.execution_cost()}

    session.ask(text) sends one user message and collects deltas until response.done; append_audio(pcm16) plus commit_audio() then turn() is the audio path; send_function_result(call_id, output) answers a tool call the model made. turn() returns only what the provider sent, and a provider error raises RealtimeError. This snippet needs a provider key on the worker host; without one the traversal fails with realtime_error. The wire behaviour is verified against local fixtures in tests/test_realtime_extended.py (a WebSocket server, an aiortc loopback peer, a scripted HTTP endpoint). Not verified: live behaviour against OpenAI or OpenRouter; the endpoints are configurable through ATFGRAPH_REALTIME_URL, ATFGRAPH_REALTIME_CALLS_URL and ATFGRAPH_OPENROUTER_CHAT_URL if a provider's paths differ.

    Containers and Compose

    A worker container is the SDK wheel plus your module, started with python -m atfgraph.worker (or your own main()) and pointed at the graph server through ATFGRAPH_SERVER and ATFGRAPH_API_KEY. examples/python/container_node/Dockerfile is the minimal form:

    docker build -f examples/python/container_node/Dockerfile -t container-node .
ATFGRAPH_CONTAINER_SERVER=http://host.docker.internal:18880 docker compose -f examples/python/container_node/compose.yaml up

    The Compose file in that directory sets init: true so SIGTERM reaches the worker and it drains before exiting. For a graph server and worker together, atfg deploy scaffold ./my-node --label my-node --module my_node:app writes a Dockerfile, compose.yaml and .dockerignore, and atfg deploy compose up --name demo --build waits for /health and for the label to register; see ../howto-deploy-compose.md and ../howto-deploy-kubernetes.md. Readiness for a worker is "the server lists the label", which atfg dev --expect-label and the scaffolded health check both use.
