    Multi-node systems

    By the end of this page one agent node calls a capability on another node and the graph server records the edge on the path; you discover capabilities at runtime with app.discovery, pin a call to a node version, run two versions of a label side by side, and host several nodes in one process for tests with OfflineMesh. It requires a running graph server for everything except the OfflineMesh section.

    A cross-node edge

    Inside a handler, await app.traverse("label.capability", ...) submits a nested child of the current step and waits for it. The graph server records the child as a second step on the same path, so the parent's Handle.path() lists both. Adapted from examples/databricks/two_node/intake/agent.py and examples/databricks/two_node/pricing/agent.py:

    from pydantic import BaseModel

from atfgraph import Agent

intake = Agent(node_id="intake", version="1.0.0", description="Extract a request, then walk the edge to pricing.quote")
pricing = Agent(node_id="pricing", version="1.0.0", description="Deterministic nightly-rate quote")

NIGHTLY_RATES = {"lisbon": 140, "porto": 120}


class TripRequest(BaseModel):
    destination: str
    nights: int
    travellers: int
    confident: bool


@pricing.skill()
def quote(destination: str, nights: int, travellers: int) -> dict:
    nightly = NIGHTLY_RATES.get(destination.strip().lower(), 130)
    return {"destination": destination, "currency": "EUR", "total": nightly * nights * travellers}


@intake.traversal(timeout_seconds=180)
async def triage(request: str) -> dict:
    parsed = await intake.ai(system="Extract destination, nights and travellers.", user=request, schema=TripRequest)
    if not parsed.confident:
        return {"status": "needs_review", "request": request}
    result = await intake.traverse("pricing.quote", destination=parsed.destination, nights=parsed.nights, travellers=parsed.travellers)
    return {"status": "quoted", **result}

    Each node is a separate worker process (the two Agent objects can also live in one process, see below). intake.triage needs a model provider through ATFGRAPH_MODEL_URL / ATFGRAPH_MODEL_NAME; pricing.quote runs with nothing configured. tests/test_migrated_ops_examples.py runs both against the daemon with a fixture provider and asserts the path is [("intake.triage", "succeeded"), ("pricing.quote", "succeeded")].

    python -m atfgraph.worker --module examples.databricks.two_node.pricing.agent:app
python -m atfgraph.worker --module examples.databricks.two_node.intake.agent:app
python -m examples.databricks.two_node.call "Two people, four nights in Lisbon"

    The caller reads the edge from the path (adapted from examples/databricks/two_node/call.py):

    import asyncio
import os

from atfgraph import Client


async def main() -> None:
    async with Client(os.getenv("ATFGRAPH_SERVER")) as client:
        handle = await client.submit("intake.triage", {"request": "Two people, four nights in Lisbon"})
        print(await handle.result(timeout=180))
        for step in (await handle.path()).items:
            print(step.target, step.status, step.parent_step_id, len(step.attempts))


if __name__ == "__main__":
    asyncio.run(main())

    A parent that awaits a child releases its worker permit while it waits (up to max_waiting parents at a time), so a worker with --capacity 1 does not deadlock on its own child. See ./03-calling-other-nodes.md for fan-out and cancellation.

    Discover capabilities at runtime

    app.discovery is a Discover bound to the agent's client; await app.discover(**filters) is shorthand for app.discovery.capabilities(**filters). Discovery filters the authorized registry snapshot locally: label, version (needs label), name, kind ("skill" or "traversal"), a case-insensitive query over label, name and description, plus limit and offset. Each DiscoveredCapability carries the exact version it was discovered at and its schemas; .invoke() submits pinned to that version, as a nested child when called inside a handler. Adapted from examples/python/tool_discovery/agent.py:

    from atfgraph import Agent

app = Agent(node_id="orchestrator", version="1.0.0")


async def worker_targets(query: str = "", limit: int = 8) -> list[str]:
    capabilities = await app.discovery.capabilities(label="utility-worker", kind="skill", query=query, limit=limit)
    return [item.target for item in capabilities]


@app.traversal()
async def inspect_tools(query: str = "") -> dict:
    return {"targets": await worker_targets(query)}


@app.traversal()
async def weather_report(cities: str) -> dict:
    result = await app.ai(user=f"Report the example weather for {cities}", tools=await worker_targets("weather"), max_tool_rounds=3, max_tool_calls=5)
    return {"report": str(result)}

    inspect_tools runs with nothing configured; weather_report passes the discovered targets to app.ai(tools=...) and needs a provider. app.discovery.resolve("label.capability") returns one DiscoveredCapability or raises NotFoundError with code capability_not_found; app.discovery.invoke(target, input, version=...) resolves and calls in one step. Discovery requires the invoke role or admin; a client whose API key belongs to another namespace sees an empty registry (tests/test_discovery_identity.py).

    AgentMesh: a view restricted to labels

    AgentMesh(client, labels) is a Discover whose agents() and capabilities() only return the named labels; asking for another label raises NotFoundError with code mesh_target_not_found. It invokes durable executions on the graph server; it does not host nodes or start workers. Use it when an orchestrating capability should only ever see a fixed set of nodes.

    Several nodes in one process

    Two Agent objects can serve from one process against a real graph server: run serve() for each concurrently. This is how tests/test_feature_examples_extended.py runs fares 1.0.0 and 2.0.0 together. Adapted from that test's serving helper:

    import asyncio

from atfgraph import Client
from examples.python.features.version_routing.agent import v1, v2


async def main() -> None:
    stop = asyncio.Event()
    async with Client("http://127.0.0.1:18880") as client:
        v1.bind_client(client)
        v2.bind_client(client)
        workers = [asyncio.create_task(v1.serve(stop=stop)), asyncio.create_task(v2.serve(stop=stop))]
        try:
            print(await client.traverse("fares.quote", {"route": "BNE-SYD", "adults": 2}, timeout=30))
        finally:
            stop.set()
            await asyncio.gather(*workers, return_exceptions=True)


if __name__ == "__main__":
    asyncio.run(main())

    Each serve() registers its own definition and enrols its own worker; nested calls between them still go through the graph server and appear on the path.

    Version routing

    A definition is immutable per (label, version), and a worker only claims work for the version it enrolled with. Adapted from examples/python/features/version_routing/agent.py:

    from atfgraph import Agent

v1 = Agent(node_id="fares", version="1.0.0", description="Fare quotes, bags included", capacity=2)
v2 = Agent(node_id="fares", version="2.0.0", description="Fare quotes with unbundled baggage", capacity=2)


@v1.traversal()
async def quote(route: str, adults: int = 1) -> dict:
    return {"route": route.upper(), "total": 149.0 * max(1, adults), "served_by": "1.0.0"}


@v2.traversal(name="quote")
async def quote_v2(route: str, adults: int = 1, bags: int = 0) -> dict:
    return {"route": route.upper(), "total": 149.0 * max(1, adults) + 35.0 * bags, "served_by": "2.0.0"}


@v2.skill()
async def seat_map(route: str) -> dict:
    return {"route": route.upper(), "available": ["3A", "3B"]}

    Observed in tests/test_feature_examples_extended.py against the daemon:

    CallResult
    client.submit("fares.quote", {...}) with no versionrouted to the highest registered version, 2.0.0
    client.submit("fares.quote", {...}, version="1.0.0")pinned to 1.0.0, its schema and its workers
    pinned 1.0.0 with a bags fieldfails at the worker with invalid_input: the pin freezes the input contract
    client.submit("fares.seat_map", ..., version="1.0.0")NotFoundError, code capability_not_found
    version="9.9.9"NotFoundError, code agent_not_found

    Client.submit, Client.traverse (through its submit_kwargs), Agent.submit, Discover.invoke and atfg traverse --node-version accept version=. Agent.traverse does not take version=; use await (await app.submit(target, payload, version="1.0.0")).result() or app.discovery.invoke(target, payload, version="1.0.0") when a nested call must pin. client.capabilities("fares") returns the newest definition and client.capabilities("fares", "1.0.0") the pinned one.

    Publications

    app.discovery.publish(label, version=..., protocol="http" | "mcp" | "a2a", published=..., display_name=..., description=...) creates or updates a pinned descriptor; publications(query=...) searches them and remove_publication(id) removes only the descriptor, not the registered node. Publishing is an administrator operation and does not start a protocol server. tests/test_discovery_identity.py shows a reader role getting AuthError on publish and a disabled protocol answering APIError with code protocol_disabled; app.discovery.settings() reads that deployment policy, which is changed by editing the server's YAML and restarting.

    OfflineMesh for tests without a server

    atfgraph.offline.OfflineMesh (not exported from the package root) mounts several Agent objects as ASGI sub-applications under /{node_id} and answers the /api/v2 routes handler code uses from an in-memory graph: submit, traverser state, path, event log, memory, checkpoints, progress and usage. app.traverse between members runs in-process as a nested child; mesh.discovery is an AgentMesh over the offline registry. Adapted from examples/python/features/offline_mesh/run.py:

    import asyncio

from atfgraph.offline import OfflineMesh
from examples.python.features.offline_mesh.agent import concierge, fares


async def main() -> None:
    async with OfflineMesh([concierge, fares]) as mesh:
        result = await mesh.invoke("concierge.plan", {"origin": "BNE", "cities": ["SYD", "MEL"], "nights": 2}, session_id="trip-1")
        recalled = await mesh.invoke("concierge.recall", {}, session_id="trip-1")
        handle = await mesh.submit("concierge.plan", {"origin": "PER", "cities": ["ADL"]})
        await handle.result(timeout=10)
        path = await handle.path()
        print(result["total"], recalled, [(s.target, s.status) for s in path.items])
        print(mesh.usage(handle.id), [c.target for c in await mesh.discovery.capabilities()])


if __name__ == "__main__":
    asyncio.run(main())
    python -m examples.python.features.offline_mesh.run

    The same concierge and fares objects run unchanged as workers against a real graph server. The mesh never contacts a graph server and does not make anything durable; routes without an offline meaning (worker claim and renew, approvals, knowledge, publications, retention) answer 501 offline_unsupported, and mesh.graph.unsupported lists any that a handler touched. mesh.serve(host, port) and serve_async expose the ASGI app over TCP when the optional uvicorn package is installed. OfflineMesh is a convenience for unit tests of multi-node handler logic; the graph server is the product, and ./15-testing.md shows the real-daemon pattern that the repository itself uses.
