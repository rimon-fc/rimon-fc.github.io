    Python SDK guide

    The atfgraph package is one wheel that contains both halves of the SDK: Agent, for writing agent nodes that register capabilities with the graph server and claim work from it, and Client, for starting traversers and reading paths from any Python program. These pages teach the SDK in the order a node grows: a single capability first, then calls between nodes, state, model and harness calls, triggers, multi-node systems, hosting, security, observability and testing. Every snippet is adapted from one of the shipped examples under examples/ and is exercised by the repository's tests against the real graph server.

    Start with the quickstart if you have not run a graph server yet, and keep core concepts open for the vocabulary.

    Build a node

    1. Install and run a first node: the wheel, an Agent, one traversal and one skill, three ways to run the worker, the first recorded path.
    2. Traversals, skills, typed input and output, routers: what the two capability kinds mean on the path, Pydantic schemas, sync and async handlers, grouping capabilities with AgentRouter.
    3. Calling other nodes and fanning out: nested traverse, call and submit, asyncio.gather, capacity and deadlock avoidance, progress, cancellation, retries.
    4. Sessions and memory: server-created sessions, the four memory scopes, compare-and-set, TTL, vector memory, change feeds.
    5. Document knowledge: ingesting text, BM25 search with citations, when vector memory is the better tool.

    Reach out of the node

    1. Model calls: app.ai with structured output, tools and streaming, the multimodal family, provider configuration, cost entries.
    2. Delegating to a coding harness: app.harness and its providers, harness_doctor, typed output, how the run lands on the path.
    3. Approvals, pauses and checkpoints: durable human-in-the-loop waits, deciding out of band, replay that runs pre-pause work once.
    4. Emitters: schedules and webhooks: cron and interval triggers, authenticated webhook sources, transforms, duplicate suppression.

    Grow to a system

    1. Multi-node systems: discovery, several nodes in one process, the offline mesh, version routing, cross-node edges.
    2. Resilience and client-side controls: retries, budgets, cooperative cancellation, rate limiting, result caching, model routing.
    3. Hosting a node: the long-running worker, serverless invocation, realtime sessions, containers.

    Operate it

    1. Identity, credentials and access boundaries: node identities, verifiable execution credentials, access policies enforced by the server.
    2. Usage, logs and tracing: usage accounting, node logs, run metadata, webhooks, MLflow.
    3. Testing against the graph server: the real-daemon fixture the repository uses, fixture modes, and the limits of the in-memory contract double.

    Look things up

    1. Python API reference: every public export with its methods and purpose.
