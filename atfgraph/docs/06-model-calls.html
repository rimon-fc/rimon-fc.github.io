    Model calls

    By the end of this page you will be able to call a model from a handler with app.ai, get a typed answer back, let the model call your node's own capabilities as tools, stream deltas, send images and audio, generate media, and read what each call cost. It requires the SDK, a running graph server and, for anything that actually contacts a model, provider credentials in the worker's environment; every snippet says which.

    Prerequisites: a chat provider reachable from the worker (ATFGRAPH_MODEL_URL and ATFGRAPH_MODEL_NAME, or ATFGRAPH_MODEL_PROVIDER=anthropic with ANTHROPIC_API_KEY) for the app.ai snippets; OPENAI_API_KEY or another media key for the generation snippets.

    Configure a provider

    Agent(...) reads the model provider from the environment once at construction (python/atfgraph/model.py, model_from_env), unless you pass model= explicitly. Nothing is contacted until a handler calls app.ai.

    VariableMeaning
    ATFGRAPH_MODEL_PROVIDERopenai-compatible (default) or anthropic. Any other value raises ModelNotConfigured at construction.
    ATFGRAPH_MODEL_URLBase URL of the chat-completions endpoint. Required for openai-compatible; optional for anthropic (defaults to the Anthropic API).
    ATFGRAPH_MODEL_NAMEDefault model name. Required for both providers.
    ATFGRAPH_MODEL_API_KEYBearer key for openai-compatible. ATFGRAPH_MODEL_API_KEY_ENV names a different variable to read instead.
    ATFGRAPH_MODEL_AUTHauto (default), key or databricks. auto sends the key when one is set and, only for a Databricks serving host with no key, signs with the workspace identity instead. databricks always uses the identity; key never does.
    ANTHROPIC_API_KEYKey for anthropic when ATFGRAPH_MODEL_API_KEY_ENV is not set.
    ATFGRAPH_MODEL_PRICESOptional rate table for estimating what a call cost when the provider states no price: inline JSON, or the path of a JSON file, keyed by model name with input_per_million and output_per_million in USD (optional cache_read_per_million, cache_creation_per_million, cache_included_in_input). Estimates are recorded with cost_source="table"; see What a call cost.

    With none of these set, app.model is None and the first app.ai call raises ModelNotConfigured with the message "no model provider: pass model= to Agent or set ATFGRAPH_MODEL_URL and ATFGRAPH_MODEL_NAME (and optionally ATFGRAPH_MODEL_PROVIDER=anthropic)". The two provider classes are HTTPChatModel and AnthropicMessagesModel; tests/test_authoring_parity.py::test_model_from_env_selects_provider pins the selection rules. app.model = HTTPChatModel(url, name, transport=...) is how the tests substitute a scripted provider, and ModelRouter (11-resilience-and-controls.md) is a ModelProvider that dispatches per model name.

    Per-provider recipes

    The node code is the same in every case; only the environment changes. Any one of these blocks makes the plan traversal in 02-traversals-skills-and-routers.md call a real model.

    # Databricks Model Serving: the workspace URL, not an App URL; the endpoint name is the model.
# Two ways to authenticate, both supported:
export ATFGRAPH_MODEL_URL=https://adb-1234567890.12.azuredatabricks.net/serving-endpoints
export ATFGRAPH_MODEL_NAME=databricks-claude-sonnet-5
#  (a) a token you hold: `databricks tokens create`, or a service-principal OAuth token, with CAN_QUERY
export ATFGRAPH_MODEL_API_KEY=dapi-your-token
#  (b) no token at all: leave ATFGRAPH_MODEL_API_KEY unset and the call is signed by the workspace identity
#      through databricks-sdk unified auth -- inside a Databricks App that is the App's own service principal
#      (grant it CAN_QUERY on the endpoint), on a laptop an explicit ATFGRAPH_DATABRICKS_PROFILE. Needs the
#      [databricks] extra. ATFGRAPH_MODEL_AUTH=databricks forces (b) even when a key is set; =key forbids it.

# OpenRouter: reports usage.cost, so recorded calls carry a price
export ATFGRAPH_MODEL_URL=https://openrouter.ai/api/v1
export ATFGRAPH_MODEL_NAME=anthropic/claude-sonnet-4
export ATFGRAPH_MODEL_API_KEY=sk-or-your-key

# Anthropic directly
export ATFGRAPH_MODEL_PROVIDER=anthropic
export ATFGRAPH_MODEL_NAME=claude-sonnet-4-20250514
export ANTHROPIC_API_KEY=sk-ant-your-key

# A local OpenAI-compatible server (Ollama, vLLM): no key
export ATFGRAPH_MODEL_URL=http://127.0.0.1:11434/v1
export ATFGRAPH_MODEL_NAME=llama3.1

    The Databricks shape is the one examples/databricks/presets/databricks-model-serving.yml writes out for an App, with the token bound from a secret scope rather than typed into a shell. examples/databricks/presets/openrouter.yml is the OpenRouter equivalent.

    Where the key lives, by how you run the worker

    The graph server never holds a model key and has no route to accept one. The key is in the environment of the worker process, and the manifest declares its name so the tooling can check it is present.

    Declare the names in agentnode.yaml so atfg install and atfg run know what to look for. Adapted from examples/python/features/model_tools/agentnode.yaml:

    user_environment:
  required:
    - name: ATFGRAPH_MODEL_URL
      description: OpenAI-compatible chat base URL
    - name: ATFGRAPH_MODEL_NAME
      description: Model or serving-endpoint name
  optional:
    - name: ATFGRAPH_MODEL_PROVIDER

    The manifest carries the name and the type, never the value. Without any provider configured the worker still starts and its skills work; the first app.ai call raises ModelNotConfigured naming the variables to set.

    Several providers in one node

    When one node wants a cheap model for triage and a strong one for drafting, or a Databricks endpoint for some calls and Anthropic for others, build a ModelRouter and register each provider with the environment variable that holds its key (api_key_env); the value is still read from the environment, never passed in code. Constructor signatures are those of HTTPChatModel(base_url, model, *, api_key_env=...) and AnthropicMessagesModel(model, *, api_key_env=...) in python/atfgraph/model.py; routing rules are in 11-resilience-and-controls.md.

    from __future__ import annotations

from pydantic import BaseModel

from atfgraph import Agent, AnthropicMessagesModel, HTTPChatModel, ModelRouter

router = ModelRouter()
router.register(
    "databricks",
    HTTPChatModel(
        "https://adb-1234567890.12.azuredatabricks.net/serving-endpoints",
        "claude-sonnet-4-endpoint",
        api_key_env="DATABRICKS_TOKEN",
    ),
    models=["claude-sonnet-4-endpoint"],
    default=True,
    default_model="claude-sonnet-4-endpoint",
)
router.register(
    "openrouter",
    HTTPChatModel("https://openrouter.ai/api/v1", "openai/gpt-4o-mini", api_key_env="OPENROUTER_API_KEY"),
    prefixes=["openai/", "google/"],
)
router.register(
    "anthropic",
    AnthropicMessagesModel("claude-opus-4-1", api_key_env="ANTHROPIC_API_KEY"),
    models=["claude-opus-4-1"],
)

app = Agent(node_id="concierge", version="1.0.0", model=router)


class Route(BaseModel):
    needs_expert: bool
    reason: str


@app.traversal()
async def triage(message: str) -> dict:
    verdict = await app.ai(user=message, model="openai/gpt-4o-mini", schema=Route)  # OpenRouter, by prefix
    if verdict.needs_expert:
        return {"reply": await app.ai(user=message, model="claude-opus-4-1")}        # Anthropic, by name
    return {"reply": await app.ai(user=message)}                                      # default route: Databricks

    Each call is recorded under its own provider and model, so usage totals show the split. Not verified: the three endpoints above against live accounts; the routing rules are pinned by tests/test_python_controls.py with a fixture provider.

    Structured output on Databricks serving endpoints

    app.ai(schema=…) asks an OpenAI-compatible endpoint for structured output and steps down one shape at a time until the endpoint accepts one, remembering the answer for the rest of the process:

    1. `response_format: json_schema` with `strict: true` on Databricks hosts (documented support). The schema is first rewritten into the shape Databricks documents: nested models inlined instead of $ref, optionals as [type, "null"], title/default dropped, and every property required, because constrained decoding enforces nothing else and a self-report field is exactly what a model likes to skip. A schema that still uses pattern, allOf, oneOf or a recursive reference is sent without strict instead of failing every call. ATFGRAPH_MODEL_STRICT=true forces strict for any host, false never sends it. Live: databricks-claude-sonnet-5 accepts strict and then always states the fields it used to leave out.
    2. plain `response_format: json_schema`, when the strict request came back 400/422.
    3. one forced tool call (the schema as the function's parameters, arguments read back).
    4. the schema in the prompt: no response_format, no tools, a system instruction spelling out the JSON Schema; the reply's first JSON object (fences and prose tolerated) is validated like any other. This is the only shape the Claude Fable endpoints (databricks-claude-fable-5, -5-1) accept: they answer 400 to response_format ("Structured output is not supported for this model…") and to forced tool use ("tool_choice: type tool and any are not supported").

    ATFGRAPH_MODEL_STRUCTURED=json_schema (default) starts at the top; tools or prompt start lower when you know the endpoint. A 400/422 at the last step, and every other HTTP error, surfaces as ModelError with .status and .detail, the endpoint's own message (scrubbed): for example databricks-claude-sonnet-5 refuses the temperature parameter, and the message says so.

    Whatever the shape, a reply that does not validate is repaired once: the SDK sends the conversation back with the model's reply and the validation error quoted, then validates again; the second miss surfaces as the ModelError. ModelResponse.repaired says when the answer came from that second call. ATFGRAPH_MODEL_REPAIR=0 makes the first miss final.

    When a traversal wraps model calls in a fixture fallback — the co_consult example does — a rejected structured call does not fail the run; it degrades it. Read the run's usage rows (operation: fallback, message model call failed: ModelError) or the degraded flag in its metadata before trusting a suspiciously short path.

    One call, typed output

    app.ai("text") and app.ai(user="text") are equivalent. Without schema= the call returns the response text; with schema= (a Pydantic model or a JSON Schema dict) it requests structured output and returns the parsed instance. system=, model=, temperature= and max_tokens= pass through; context= is appended to the user message as JSON. Adapted from examples/python/image_studio/agent.py:

    from __future__ import annotations

from pydantic import BaseModel

from atfgraph import Agent

app = Agent(node_id="image-studio", version="1.0.0")


class DetailedPrompt(BaseModel):
    prompt: str
    style_notes: str


@app.traversal()
async def create_prompt(topic: str) -> dict:
    answer = await app.ai(
        user=topic,
        system="Write a vivid one or two sentence image prompt with composition, colour and lighting.",
        schema=DetailedPrompt,
    )
    return answer.model_dump()

    Two more forms are pinned by test_ai_accepts_positional_text_context_and_rejects_unsupported_inputs: response_format="json" returns a parsed dict without a schema, and return_response=True returns the full ModelResponse (text, parsed, model, usage, tool_calls, finish_reason, provider). A call with only system= and no user content raises ValueError; unknown keyword arguments such as the previous runtime's memory_scope= raise TypeError.

    Tools: the model calls your capabilities

    tools="self" offers this node's own capabilities to the model as function tools. Every tool call the model makes runs through app.traverse, so it is a recorded child step on the path. The loop is bounded by max_tool_rounds=8 and max_tool_calls=25. From examples/python/features/model_tools/agent.py:

    from __future__ import annotations

from datetime import date
from typing import List

from pydantic import BaseModel

from atfgraph import Agent

app = Agent(node_id="planner", version="1.0.0", description="Structured trip planning with tool calls")

FIXTURE_RATES_TO_AUD = {"AUD": 1.0, "NZD": 0.92, "USD": 1.52, "EUR": 1.65, "JPY": 0.0101}


class TripPlan(BaseModel):
    destination: str
    nights: int
    budget_aud: float
    highlights: List[str]


@app.skill()
def nights(check_in: str, check_out: str) -> dict:
    """Nights between two ISO dates."""
    return {"nights": (date.fromisoformat(check_out) - date.fromisoformat(check_in)).days}


@app.skill()
def convert(amount: float, currency: str) -> dict:
    """Convert an amount to AUD with fixture rates."""
    rate = FIXTURE_RATES_TO_AUD.get(currency.upper())
    if rate is None:
        raise ValueError(f"unknown currency {currency!r}")
    return {"amount_aud": round(amount * rate, 2), "rate": rate}


@app.traversal()
async def plan(brief: str) -> TripPlan:
    answer = await app.ai(
        system="You plan trips. Use the tools for date arithmetic and currency conversion; never guess numbers.",
        user=brief,
        tools="self",
        schema=TripPlan,
    )
    return answer.parsed

    With tools the return value is a ToolCallResponse: .text, .parsed (when a schema was given), .usage and .trace, a ToolCallTrace with calls (each a ToolCallRecord with tool_name, target, arguments, result, error, latency_ms, round), rounds and stopped_by_limit. What tests/test_authoring_parity.py::test_ai_tool_loop_runs_capabilities_as_child_steps_and_returns_structured_output verifies with a scripted provider:

    • Tool names are label__capability (planner__nights); the running capability is never offered to itself.
    • A tool that raises returns {"error": ...} to the model instead of failing the traversal, and the loop continues.
    • The path under planner.plan shows one planner.nights step and two planner.convert steps, one per tool call.
    • When the round limit is reached the closing turn is sent without tools so the model must answer (test_tool_loop_stops_at_round_limit_and_asks_for_a_final_answer).

    Other values: tools="discover" offers every registered node's capabilities; a list mixes label.capability targets and ready-made tool schemas (capability_to_tool_schema(target, capability) builds one). Any other string raises ValueError. stream=True and modalities= cannot be combined with tools; both raise TypeError.

    Run the example from this repository's root with a provider configured:

    python -m atfgraph.worker --module examples.python.features.model_tools.agent:app
python -m examples.python.features.model_tools.call

    Streaming

    stream=True returns a ModelStream immediately. Iterate stream.text() for text deltas, or iterate the stream itself for StreamEvent objects (type is text, tool_call, audio, transcript, usage or done). After the stream ends, stream.response() is the assembled ModelResponse, and usage is recorded on the current task at that point. From examples/python/features/multimodal/agent.py:

    from __future__ import annotations

from typing import List

from atfgraph import Agent

app = Agent(node_id="media", version="1.0.0")


@app.traversal()
async def narrate_stream(text: str) -> dict:
    stream = await app.ai(f"Rewrite this as a two-sentence travel teaser: {text}", stream=True)
    chunks: List[str] = []
    async for delta in stream.text():
        chunks.append(delta)
        await app.note(delta, tags=["delta"])
    return {"text": "".join(chunks), "usage": stream.response().usage, "cost": app.execution_cost()}

    Forwarding deltas as app.note progress events is what lets a caller watch the text arrive through client.events(traverser_id).

    Images and audio as input

    Positional arguments to app.ai may mix text with Image, Audio, File, pathlib.Path or ready-made content parts; they become one user message with content parts. Image.from_url(url), Image.from_file(path) and Image.from_bytes(data) build image parts; Audio.from_file(path) and Audio.from_bytes(data, format) build inline audio; Audio.from_url accepts only data: URLs. The describe traversal from the multimodal example:

    from __future__ import annotations

from typing import List, Optional

from pydantic import BaseModel

from atfgraph import Agent, Image

app = Agent(node_id="media", version="1.0.0")


class Findings(BaseModel):
    summary: str
    objects: List[str]
    readable_text: Optional[str] = None


@app.traversal()
async def describe(image_url: str, question: str = "What is in this image?") -> dict:
    findings = await app.ai(question, Image.from_url(image_url), schema=Findings)
    return {"findings": findings.model_dump(), "cost": app.execution_cost()}

    Each provider declares capabilities (text, vision, audio_in, audio_out, files, tools, structured, stream, image_out). A request the provider cannot serve raises MediaCapabilityError before any I/O; tests/test_media_parity.py shows Anthropic Messages rejecting audio input this way while converting images and documents. Raw bytes passed positionally raise TypeError asking for a media type. ai_with_multimodal(...) is the explicit spelling of the same call with modalities= and audio_config=; ai_with_audio(...) asks for spoken output, either through the chat provider (modalities=["text", "audio"]) or, when model= names a TTS model, through the media router.

    Generating media

    Image, speech, music, video and transcription go through app.media, a MediaRouter built lazily from the environment (python/atfgraph/media_providers.py, default_media_router). The model prefix picks the provider; the key is read at request time, so a missing key raises MediaProviderNotConfigured naming the variable.

    dall-e, gpt-image, tts-, whisper, gpt-4o-transcribe, openai/OpenAIOPENAI_API_KEY

    Every output carries either a url or inline data. save_all(directory, prefix=) writes the inline outputs and skips URL-only outputs; nothing is downloaded implicitly. From examples/python/features/multimodal/agent.py:

    from __future__ import annotations

import os
from pathlib import Path
from typing import Optional

from atfgraph import Agent

app = Agent(node_id="media", version="1.0.0")
ARTIFACT_DIR = Path(os.environ.get("ATFGRAPH_MEDIA_DIR", "/tmp/atfgraph-media"))


@app.traversal()
async def poster(prompt: str, model: Optional[str] = None, size: str = "1024x1024") -> dict:
    result = await app.ai_generate_image(prompt, model=model, size=size)
    saved = [str(p) for p in result.save_all(ARTIFACT_DIR, prefix="poster")]
    return {"saved": saved, "urls": [i.url for i in result.images if not i.is_inline], "cost_usd": result.cost_usd, "cost": app.execution_cost()}

    The same example's transcribe traversal wraps base64 input as Audio(input_audio={"data": ..., "format": "wav"}) and passes it to ai_transcribe_audio, which also accepts raw bytes, a data: URL or an http(s) URL. The provider tests in tests/test_media_parity.py run every provider over httpx.MockTransport; examples/python/features/multimodal has no fixture mode and needs real keys to produce media.

    What a call cost

    Every app.ai and ai_generate_* call records a CostEntry (python/atfgraph/costs.py) on the current task: model, provider, source (llm, media, realtime, harness), operation (chat, image, audio, music, video, transcription, realtime), token counts, cost_usd and cost_source. Without a rate table the price is only what the provider reported (OpenRouter's usage.cost, or a media provider's own field); the SDK has no price table, so cost_usd stays None for calls whose provider reports none, which is not the same as 0.0 (test_openai_compatible_vision_posts_content_parts_and_records_usage).

    Estimating a price the provider does not state. Databricks serving, Azure OpenAI and most self-hosted endpoints return token counts and no price, so their calls are unpriced in the ledger and the Console. A node that wants an estimate configures a rate table, either Agent(prices={...}) or ATFGRAPH_MODEL_PRICES in its .env (inline JSON, or the path of a JSON file):

    export ATFGRAPH_MODEL_PRICES='{"databricks-claude-sonnet-5": {"input_per_million": 2.00, "output_per_million": 10.00, "cache_read_per_million": 0.20}}'

    The table fills cost_usd only when the provider stated nothing and the call carried tokens, marks the entry cost_source="table", and keeps the rates it used in extra["rate"]; a provider-reported price always wins. The Console shows such calls as ≈ $0.0123 with an estimated tag on the run page, MLflow and OpenTelemetry spans carry atfgraph.usage.cost_source = table, and the usage totals count them as priced. Keys match either the model name the provider reports in its response (the ledger's model, which for a Databricks databricks-claude-sonnet-5 endpoint is global.anthropic.claude-sonnet-5) or the name the node requested (ATFGRAPH_MODEL_NAME or model=), ignoring case; provider/model keys match on the part after the slash. When the two names differ the ledger keeps the requested one in extra.requested_model. Cached prompt tokens are priced at cache_read_per_million when given, otherwise as input; set cache_included_in_input: false for Anthropic-shaped usage, whose input_tokens excludes them.

    The SDK ships no rates: they are the node's to choose and maintain. Databricks publishes pay-per-token rates in DBU per million tokens on its pricing page for Anthropic foundation model serving; multiply by your workspace's USD rate per DBU for the serving SKU. On 2026-09-23 that page listed Claude Sonnet 5 at 28.571 DBU input, 142.857 DBU output and 2.857 DBU cache read per million tokens, which at the commonly quoted $0.07 per DBU list rate is the $2.00, $10.00 and $0.20 above. Check the page and your contract before copying these figures; an estimate is a planning number, not a bill.

    app.execution_cost() returns the totals for the current execution as a dict with total_calls, total_input_tokens, total_output_tokens, total_tokens, total_cost_usd, calls_without_price and by_model (per model: calls, tokens, cost_usd). total_cost_usd is None unless at least one call reported a price; calls_without_price says how many did not. The same entry is written to the traverser's event log as a usage progress event and, by default, shipped to the graph server's usage store (test_usage_is_recorded_as_progress_events_on_the_execution). A caller reads the events back with UsageEvent.from_event, adapted from examples/python/features/multimodal/call.py:

    from __future__ import annotations

import asyncio
import os

from atfgraph import Client, UsageEvent


async def main() -> None:
    async with Client(os.getenv("ATFGRAPH_SERVER")) as client:
        handle = await client.submit("media.narrate", {"text": "Welcome to Brisbane. Your gate is B12."})
        print(await handle.result(timeout=300))
        async for event in client.events(handle.id):
            usage = UsageEvent.from_event(event)
            if usage is not None:
                print(f"  usage {usage.operation:<14} {usage.model:<28} tokens={usage.total_tokens} cost_usd={usage.cost_usd}")


if __name__ == "__main__":
    asyncio.run(main())

    app.record_usage(CostEntry(...)) records a call you made outside the SDK's providers; 14-observability.md covers the durable store, usage_totals and the reporting counters.
