    ATFGraph vNext documentation

    Overview

    Start here

    ATFGraph vNext is a graph server for multi-agent systems: agent nodes register their functions and every call between them is routed and recorded by the server as a step on a path. It is installed from source today.

    1. Overview: what it is and what it is not.
    2. Quickstart: server, node, traverser and path in five minutes.
    3. Core concepts: the ten nouns.
    4. Why ATFGraph, and how it compares: what production means for an agent.
    5. How-to guides: one problem per page.
    6. API reference, CLI reference and Troubleshooting: for looking things up.

    Build Python agent nodes, invoke them through the CLI or HTTP API, and deploy workers with Docker Compose, Kubernetes or Databricks.

    Vocabulary

    The names used throughout this reference, as the contract uses them.

    TermMeaning in the contract
    graph serverthe only inbound endpoint; it owns the graph, the queue and the durable records
    agent nodea registered label at an immutable version, carrying a set of capabilities
    capabilityone entry point on an agent node: a traversal or a skill (the CapabilityKind enum)
    traverserone durable execution of label.capability; nested calls get their own id and share a root_id
    paththe recorded steps and attempts of a traverser, read with getPath
    sessiona server-created scope that serialises root turns and anchors session memory
    workeran outbound process that enrols, claims tasks for one label and version, renews its lease and reports results
    emittera scheduled or event-driven source that starts traversers on the server's side
