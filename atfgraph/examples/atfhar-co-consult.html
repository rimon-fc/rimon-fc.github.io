    README

    Rendered from examples/atfhar/co-consult/README.md; the source file is not modified.

    Use this profile to chat with co-consult through atfHar. It points the atfgraph MCP server at http://127.0.0.1:18880/mcp (the vNext daemon's default listen address) and allows exactly the five tools the graph server's MCP surface currently exposes:

    ToolUse
    discover_agentslist nodes and their entry points
    get_reasoner_schemaread the input/output schema of co-consult.chat
    execute_reasonersubmit one chat turn; returns a run ID
    get_runinspect a run
    wait_runwait up to 120 s for a terminal state

    Normalised tool names in harness.yml are mcp__atfgraph_<tool>.

    Files

    • harness.yml: the profile manifest. The model role is ${ATFHAR_DEFAULT_MODEL} and modelProviders.allow is empty, so the operator's own atfHar model configuration decides which provider is used. No provider or credential is named in this repository.
    • mcp.example.json: the MCP server definition. atfHar reads it as .mcp.json inside the profile directory, so rename it when you install the profile (dotfiles are kept out of this example tree). If the daemon requires an API key, add an environment-backed X-API-Key header following the atfHar MCP documentation; never write the key into the file.
    • prompts/coordinator.md: the coordinator prompt (vNext session semantics).
    • extensions/session.ts: scopes every co-consult.chat call to one harness conversation. Because vNext sessions are server-created, the extension lets the first turn run without a session_id, records the ID the node returns in the wait_run / get_run result, and forces it on later turns. It also sets request_id from the tool-call ID so a retried turn is idempotent.

    Use

    This directory is an example; it does not modify ~/atf-harness/profiles. To load it, point atfHar serve --profile-dir at a directory that contains this profile (for example by copying examples/atfhar somewhere under your harness workspace), start the vNext daemon on 18880, run the co-consult worker, then start the harness UI:

    python -m atfgraph.worker --module examples.python.co_consult.main:app --server http://127.0.0.1:18880
atfHar serve --workspace-root "$PWD" --profile-dir /path/to/profiles --ui-dir packages/ui/dist

    Check your connection

    Start with a new conversation and ask for a travel plan. Confirm the first wait_run result contains a session_id, then ask a follow-up about a saved offer. Subsequent calls should use that same session ID.

    This profile is an example configuration; end-to-end operation with your atfHar installation and model provider must be verified before relying on it. If a tool is missing, check that MCP is enabled on the graph server and the profile has the correct server URL and API key. If follow-ups start new sessions, check that your atfHar version loads extensions/session.ts and supports its tool_result hook.
