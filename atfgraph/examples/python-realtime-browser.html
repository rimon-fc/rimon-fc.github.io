    Directory examples/python/realtime_browser

    One small node (realtime-browser, three skills) and one static page. The browser talks to the OpenAI Realtime API over WebRTC, but the provider API key never reaches the browser: the page asks the node, through the graph server, for a short-lived client secret, and every transcript turn goes back through the node so the conversation is visible in the run path.

    README

    Rendered from examples/python/realtime_browser/README.md; the source file is not modified.

    One small node (realtime-browser, three skills) and one static page. The browser talks to the OpenAI Realtime API over WebRTC, but the provider API key never reaches the browser: the page asks the node, through the graph server, for a short-lived client secret, and every transcript turn goes back through the node so the conversation is visible in the run path.

    browser  --POST /api/v2/traversers {target: realtime-browser.session_token}-->  graph server  --claim-->  node (OPENAI_API_KEY)
browser  <--poll GET /api/v2/traversers/<id> ... output.client_secret (ephemeral)--  graph server  <--complete--  node
browser  --SDP offer + Bearer <client_secret>-->  OpenAI /v1/realtime/calls  (audio + data channel, direct)
browser  --POST /api/v2/traversers {target: realtime-browser.turn}-->  graph server  --claim-->  node (session memory)
    CapabilityKindWhat it does
    session_token(instructions="", voice=None)skillMints an ephemeral Realtime client secret with the node's OPENAI_API_KEY (POST https://api.openai.com/v1/realtime/sessions). Returns client_secret, expires_at, model, voice, calls_url, mode. The API key is never returned, logged or put in a progress event.
    turn(role, text, item_id=None, realtime_session=None)skillRecords one transcript turn (user or assistant) as a progress event and, when the call carries an ATFGraph session, appends it to session memory under realtime-browser.transcript (deduplicated on item_id, last 200 turns).
    transcript()skillThe turns recorded in the current session.

    Fixture vs live

    REALTIME_BROWSER_MODEsession_tokenNetworkPage behaviour
    fixture (default)returns ek_fixture_<hex> with calls_url: null and a note saying no provider was contactednoneno WebRTC; a "typed turn" box exercises realtime-browser.turn so the round-trip through the graph server is visible without any credential
    livePOST REALTIME_BROWSER_SESSIONS_URL with Authorization: Bearer $OPENAI_API_KEY, body {model, voice, modalities, instructions}; returns the provider's client_secret.value and expires_atone HTTPS call per sessionopens WebRTC to calls_url with the ephemeral secret, streams microphone audio, forwards input_audio_transcription.completed and response.*audio_transcript.done events as turns

    Errors are explicit, never a fabricated token: live mode without OPENAI_API_KEY fails with not_configured; a provider rejection surfaces as http_<status> with the provider's message (the request never contained anything but the model and voice); an unreachable endpoint is provider_unreachable (retryable).

    The live path is not verified in this checkout: no test contacts OpenAI. The sessions endpoint, the calls endpoint and the model name are all environment overrides (REALTIME_BROWSER_SESSIONS_URL, REALTIME_BROWSER_CALLS_URL, REALTIME_BROWSER_MODEL), so a change on the provider side needs no code change. The test tests/test_realtime_browser_example.py runs the node against a real atfgraphd in fixture mode and checks session_token, turn, transcript and that the daemon serves the page.

    Running it

    1. Start a graph server that serves this page as its UI (under /ui/) so the page and the API share an origin (the daemon sends no CORS headers):
    ATFGRAPH_UI_DIR=examples/python/realtime_browser/static target/debug/atfgraphd --listen 127.0.0.1:18880 \
    --database-url "sqlite:///tmp/realtime-browser.db?mode=rwc"

    Any reverse proxy that forwards /api/ to the graph server and serves static/ works the same way; the page defaults its server URL to its own origin.

    1. Run the node (fixture mode needs nothing):
    python -m atfgraph.worker --module examples.python.realtime_browser.agent:app --server http://127.0.0.1:18880
# live:
REALTIME_BROWSER_MODE=live OPENAI_API_KEY=sk-... python -m atfgraph.worker --module examples.python.realtime_browser.agent:app --server http://127.0.0.1:18880

    or install it as a package: python3 examples/run.py python/realtime_browser.

    1. Open http://127.0.0.1:18880/ui/ (the daemon serves ATFGRAPH_UI_DIR under /ui/) and press Start session. The log shows the session_token traverser id, the mode, and one traverser id per recorded turn; GET /api/v2/traversers/<id>/path on any of them shows the step.

    If the server requires an API token, paste it into the page's token field; it is sent as Authorization: Bearer to the graph server only, never to the provider.

    What the page does (plain JS, no bundler)

    static/index.html:

    • POST /api/v2/sessions to get an ATFGraph session so turns share memory;
    • POST /api/v2/traversers with {"target": "realtime-browser.session_token", "input": {...}, "session_id": ...}, then GET /api/v2/traversers/<id> until status is succeeded (or a terminal failure);
    • with a live secret: RTCPeerConnection, microphone track in, remote audio track out, an oai-events data channel, POST calls_url with the SDP offer and Authorization: Bearer <client_secret>, then applies the SDP answer;
    • transcript events from the data channel become POST /api/v2/traversers calls with target realtime-browser.turn. Audio never goes through the graph server.

    Honest limits

    • Live OpenAI behaviour (endpoint shapes, event names) follows the provider's published Realtime WebRTC flow and is not exercised by any test here.
    • The client secret is short-lived by the provider's rules (about one minute to start the call); the page mints a new one per Start session.
    • The graph server has no CORS support, so the page must be same-origin with the API.
