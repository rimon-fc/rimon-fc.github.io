    README

    Rendered from examples/python/on_demand_node/README.md; the source file is not modified.

    Run these commands from the atfgraph-vnext checkout. Install the authoring SDK and build the CLI once:

    python -m pip install -e ./python
cargo build --bin atfgraphd --bin atfg
export PATH="$PWD/target/debug:$PATH"
atfg server start

    The server defaults to http://127.0.0.1:18880; its browser UI is /ui/. Set ATFGRAPH_SERVER and ATFGRAPH_API_KEY for a different server.

    python -m examples.python.on_demand_node.call --discover
python -m examples.python.on_demand_node.call hello '{"name":"Ada"}'
python -m examples.python.on_demand_node.call ping_child '{"target":"on-demand-node.hello","message":"Ada"}'

    Each invocation starts a bounded outbound worker, submits a real traversal, claims its work and returns the graph server's recorded result and path. No permanent worker process or inbound /execute callback is required. ping_child records another step and can target another registered node (that node needs an active worker).

    A function runtime can invoke agent.handler(event, context) with {"action":"invoke","capability":"hello","input":{"name":"Ada"}}. The handler also accepts discover, serve (consume queued work) and drain. Configure the runtime's graph server URL, authentication and network egress. Cloud provider trigger wiring is deployment-specific; this example is locally runnable and does not provision a cloud function.

    For ordinary long-running hosting and CLI calls:

    python -m atfgraph.worker --module examples.python.on_demand_node.agent:app
atfg traverse on-demand-node.hello --in '{"name":"Ada"}'
