    README

    Rendered from examples/python/features/realtime/README.md; the source file is not modified.

    One node, three traversals, three provider/transport pairs. All wire behaviour is verified against local fixtures, never a live model:

    TraversalPairTransport detailFixture test
    say(text, transport="websocket")openai / websocketpure-Python RFC 6455 client, session.update → response.done, deltas collected, usage recordedtests/test_media_parity.py (local WebSocket server)
    say(text, transport="webrtc")openai / webrtcSDP offer (m=audio + oai-events data channel) POSTed as application/sdp to /v1/realtime/calls?model=…, answer applied, events on the data channel, model audio decoded from the media track into PCM16, PCM16 in via append_audio onto the outgoing track; optional aiortc, no audio devicetests/test_realtime_extended.py (aiortc answering peer over loopback)
    listen(audio_b64, transport)same twoPCM16 in, commit_audio, text/transcript/audio outsame
    audio_turn(text, audio_b64)openrouter / audio_turnsone /chat/completions request per turn: input_audio parts in, modalities: ["text","audio"] + audio: {voice, format} out, usage: {include: true} so usage.cost is the recorded price; history replayed each turntests/test_realtime_extended.py (scripted HTTP endpoint)
    python -m atfgraph.worker --module examples.python.features.realtime.agent:app

    Every turn's provider usage is recorded on the execution through app.realtime_session's on_usage hook: app.execution_cost(), a usage progress event, and the durable usage store. cost_usd is only what the provider states (OpenRouter usage.cost); OpenAI realtime reports tokens but no price, so it stays None.

    Honest limits

    • Without OPENAI_API_KEY / OPENROUTER_API_KEY the traversals fail with realtime_error; nothing fabricates an answer.
    • Live OpenAI/OpenRouter behaviour is not verified here; endpoint URLs are overridable (ATFGRAPH_REALTIME_URL, ATFGRAPH_REALTIME_CALLS_URL, ATFGRAPH_OPENROUTER_CHAT_URL) so fixtures and future endpoint changes need no code change.
    • Over WebRTC the model's audio arrives on the media track asynchronously; turn.audio_b64 is whatever the track delivered between response.create and response.done, resampled to PCM16 mono 24 kHz. Boundaries are not frame-exact.
    • audio_turns keeps the assistant side of the history as transcript text by default (history_mode="audio_id" replays the provider's audio.id reference instead).
