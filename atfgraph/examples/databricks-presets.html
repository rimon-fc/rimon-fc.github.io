    Databricks presets for Python agent nodes

    Directory examples/databricks/presets

    Two complete Databricks App bundle files for an ATFGraph vNext Python node, differing only in where the node's model calls go. Both follow deploy/databricks/bundle/databricks.yml: one App running the shared worker_entrypoint.py, which starts the node as an outbound worker and serves the status page on DATABRICKS_APP_PORT.

    README

    Rendered from examples/databricks/presets/README.md; the source file is not modified.

    Two complete Databricks App bundle files for an ATFGraph vNext Python node, differing only in where the node's model calls go. Both follow deploy/databricks/bundle/databricks.yml: one App running the shared worker_entrypoint.py, which starts the node as an outbound worker and serves the status page on DATABRICKS_APP_PORT.

    PresetFileModel route
    Databricks Model Servingdatabricks-model-serving.ymlATFGRAPH_MODEL_URL=https://<workspace-host>/serving-endpoints, ATFGRAPH_MODEL_NAME=<serving-endpoint>
    OpenRouteropenrouter.ymlATFGRAPH_MODEL_URL=https://openrouter.ai/api/v1, ATFGRAPH_MODEL_NAME=<vendor>/<model>

    Use one: build the node's bundle, copy the preset over its databricks.yml, check it, then validate and deploy with an explicit profile.

    scripts/product/build-databricks-bundle.sh --node-dir path/to/node --package my_node --module my_node.agent:app --label my-node
cp examples/databricks/presets/databricks-model-serving.yml target/dist/databricks/my-node/databricks.yml
.venv/bin/python scripts/product/check_databricks_bundle.py target/dist/databricks/my-node
cd target/dist/databricks/my-node
databricks bundle validate -t dev --profile <PROFILE> --var server_url=https://<graph-server> --var api_key_scope=atfgraph \
  --var model_url=https://<workspace-host>/serving-endpoints --var model_name=databricks-claude-sonnet-4 --var model_key_scope=atfgraph

    Variables shared by both presets

    VariableEnv it setsWhy
    server_url (no default)ATFGRAPH_SERVERthe graph server the worker connects to, outbound HTTPS
    api_key_scope (no default), api_key_keyATFGRAPH_API_KEY via value_from: api-keythe graph server API key, bound from a secret; never a literal
    worker_module, node_labelWORKER_MODULE, ATFGRAPH_NODE_LABELwhich module:agent to run and the label the status page waits for
    worker_capacityATFGRAPH_WORKER_CAPACITYconcurrent handler permits

    DATABRICKS_HOST, DATABRICKS_CLIENT_ID, DATABRICKS_CLIENT_SECRET and DATABRICKS_APP_PORT are injected by Databricks Apps; do not set them.

    Port

    Databricks Apps route traffic to exactly one port, given to the process in DATABRICKS_APP_PORT. worker_entrypoint.py binds it for the JSON status page (GET /health: graph-server reachability, registration, worker phase). Agent traffic never goes through it; callers use the graph server API.

    Preset 1: Databricks Model Serving

    The SDK's OpenAI-compatible provider posts to <ATFGRAPH_MODEL_URL>/chat/completions with model=<ATFGRAPH_MODEL_NAME>, which is Model Serving's OpenAI-compatible route for Foundation Model APIs and custom endpoints (databricks-claude-sonnet-4, databricks-meta-llama-3-3-70b-instruct, ...). ATFGRAPH_MODEL_URL is the workspace URL plus /serving-endpoints, not the App URL.

    The credential is ATFGRAPH_MODEL_API_KEY, bound from the secret model_key_scope/model_key_key: a personal access token or a service-principal OAuth token whose principal has CAN_QUERY on the endpoint.

    Preset 2: OpenRouter

    ATFGRAPH_MODEL_URL=https://openrouter.ai/api/v1 and ATFGRAPH_MODEL_NAME=<vendor>/<model> (default google/gemini-2.5-flash). The OpenRouter key is bound from the secret openrouter_key_scope / openrouter_key_key as ATFGRAPH_MODEL_API_KEY; it is never a literal in the file. Outbound access from the App to openrouter.ai must be allowed by the workspace's egress policy. The SDK adds OpenRouter's attribution headers itself when it recognises the host.

    Local dry run

    Both presets are valid without Databricks: export the same ATFGRAPH_MODEL_* values (and a key) in your shell and run the node with python -m atfgraph.worker --module <module:agent> against a local graph server. agentnode.yaml manifests declare the same variables for atfg install.

    Differences from the original presets, and gaps

    • The original presets configured litellm (AI_MODEL=databricks/<endpoint>, openrouter/<model>, DATABRICKS_API_BASE). vNext's provider is the SDK's own OpenAI-compatible client, so the three ATFGRAPH_MODEL_* variables replace them; ATFGRAPH_MODEL_PROVIDER=anthropic selects the Anthropic Messages client instead.
    • No service-principal token minting. The original node, with ATFGRAPH_AUTH=databricks, minted OAuth tokens from the App's injected client id and secret for graph-server calls, and litellm did the same for Model Serving through databricks-sdk. vNext has neither: the graph-server key and the model credential are both secret bindings. Recorded as a gap.
    • No inbound principal allowlist (ATFGRAPH_DATABRICKS_ALLOWED_PRINCIPALS): a vNext node has no inbound agent endpoint. The App's status page carries no credentials and is the only listener.
    • The files are databricks.yml bundle files (App resource, variables, secret resources), not bare app.yaml manifests, so databricks bundle validate checks them and no URL or key is ever a literal.
    • databricks bundle validate/deploy/run were not run for these presets; they were checked offline with scripts/product/check_databricks_bundle.py.
