    Two nodes on Databricks, one path, one trace

    Directory examples/databricks/two_node

    Two agent nodes deployed as two Databricks Apps. intake receives a free-text travel request, extracts the bindings with one model call and walks one edge to pricing, whose deterministic skill returns a quote. A cron emitter on intake fires the same edge every fifteen minutes so the path (and, with tracing on, its MLflow trace) exists even when nobody calls. Both nodes are outbound workers: they connect to the graph server, register, and claim their work; the Apps expose only the status page the platform requires.

    Agent node label pricing, version 1.0.0.

    Capabilities

    CapabilityKindSignatureModuleSummary
    probetraversal(trigger: TriggerContext | None = None) -> dictexamples/databricks/two_node/intake/agent.pyEmitter: walk the same edge every fifteen minutes with a fixed request.
    triagetraversal(request: str, model: Optional[str] = None) -> dictexamples/databricks/two_node/intake/agent.pyExtract destination, nights and travellers from a request, then quote it.
    quoteskill(destination: str, nights: int, travellers: int) -> dictexamples/databricks/two_node/pricing/agent.pyPrice a stay: nightly rate per traveller times nights times travellers.

    Non-default capability options: probe: timeout_seconds=180; triage: timeout_seconds=180

    README

    Rendered from examples/databricks/two_node/README.md; the source file is not modified.

    Two agent nodes deployed as two Databricks Apps. intake receives a free-text travel request, extracts the bindings with one model call and walks one edge to pricing, whose deterministic skill returns a quote. A cron emitter on intake fires the same edge every fifteen minutes so the path (and, with tracing on, its MLflow trace) exists even when nobody calls. Both nodes are outbound workers: they connect to the graph server, register, and claim their work; the Apps expose only the status page the platform requires.

                     +----------------------+   edge    +----------------------+
  request -----> | intake.triage        | --------> | pricing.quote        |
  (or emitter)   | traversal . AGENT    |           | skill . TOOL         |
                 +----------------------+           +----------------------+
                   app atfgraph-intake                app atfgraph-pricing
                            |   register, claim, renew leases, sync emitters  |
                            +------------->  graph server  <-----------------+
                                       (Compose / Kubernetes / Helm)
    NodeLabelElementsModule
    intake/intaketraversal triage (entry point); traversal probe with cron emitter */15 * * * *examples.databricks.two_node.intake.agent:app
    pricing/pricingskill quoteexamples.databricks.two_node.pricing.agent:app

    Each node directory has agent.py, agentnode.yaml (install/package manifest), databricks.yml (the App bundle) and requirements.txt.

    Run the same two nodes locally

    Nothing in agent.py is Databricks-specific. With a graph server and any OpenAI-compatible provider (the bundled fixture provider works offline):

    python -m examples.python.features.resilience.fixture_model --port 18899
export ATFGRAPH_MODEL_URL=http://127.0.0.1:18899 ATFGRAPH_MODEL_NAME=fixture-fast
target/debug/atfgraphd
python -m atfgraph.worker --module examples.databricks.two_node.pricing.agent:app
python -m atfgraph.worker --module examples.databricks.two_node.intake.agent:app
python -m examples.databricks.two_node.call "Two people, four nights in Lisbon"

    With a real model the expected result is

    {"status": "quoted", "destination": "Lisbon", "nights": 4, "travellers": 2, "currency": "EUR", "nightly_rate": 140, "total": 1120}

    and the printed path has two steps, intake.triage then pricing.quote. The fixture provider answers from the schema instead ("fixture destination", 2 nights, 2 travellers, total 520 at the default rate); it is a stub, not a model. When the model is not confident the traverser stops with needs_review; a quote with nights < 1 fails with the skill's ValueError.

    To trace locally, install python[mlflow], set ATFGRAPH_MLFLOW_TRACING=true and ATFGRAPH_MLFLOW_EXPERIMENT (the same name on both workers) and, if you run a tracking server, ATFGRAPH_MLFLOW_TRACKING_URI. The traversal is an AGENT span, the model call an LLM span, the edge a CHAIN span, and the pricing skill a TOOL span in the same trace; see docs/mlflow.md.

    Before you deploy

    Follow deploy/databricks/README.md: you need a graph server reachable from the workspace over HTTPS, its API key in a Databricks secret scope, and for intake a model provider credential in a secret scope (see ../presets/ for Model Serving and OpenRouter). For MLflow, add mlflow>=3.11,<4 to both requirements.txt files and create the experiment (/Shared/atfgraph/two-node by default) with CAN_EDIT for both Apps' service principals.

    Build, validate and deploy the two Apps

    # 1. Build both bundles locally (wheel, node package, requirements, entrypoint checks; no workspace)
scripts/product/build-databricks-bundle.sh --node-dir examples/databricks/two_node/pricing \
    --package pricing --module pricing.agent:app --label pricing
scripts/product/build-databricks-bundle.sh --node-dir examples/databricks/two_node/intake \
    --package intake --module intake.agent:app --label intake

# 2. Put each node's own bundle file in place (the build script writes the generic template)
cp examples/databricks/two_node/pricing/databricks.yml target/dist/databricks/pricing/databricks.yml
cp examples/databricks/two_node/intake/databricks.yml  target/dist/databricks/intake/databricks.yml
.venv/bin/python scripts/product/check_databricks_bundle.py target/dist/databricks/pricing
.venv/bin/python scripts/product/check_databricks_bundle.py target/dist/databricks/intake

# 3. Validate, deploy and start each App with an explicit profile (nothing here picks one)
(cd target/dist/databricks/pricing && \
  databricks bundle validate -t dev --profile <PROFILE> --var server_url=https://<graph-server> --var api_key_scope=atfgraph && \
  databricks bundle deploy   -t dev --profile <PROFILE> --var server_url=https://<graph-server> --var api_key_scope=atfgraph && \
  databricks bundle run agent_node -t dev --profile <PROFILE>)
(cd target/dist/databricks/intake && \
  databricks bundle validate -t dev --profile <PROFILE> --var server_url=https://<graph-server> --var api_key_scope=atfgraph \
    --var model_url=https://<workspace-host>/serving-endpoints --var model_name=<serving-endpoint> --var model_key_scope=atfgraph && \
  databricks bundle deploy   -t dev --profile <PROFILE> --var ... && \
  databricks bundle run agent_node -t dev --profile <PROFILE>)

    The Apps need no URL exchange: a worker only dials out, so there is no second deploy to fill in callback URLs. Each App's status page (GET /health on the App URL) reports registered: true once the graph server lists its label.

    Walk the edge

    export ATFGRAPH_SERVER=https://<graph-server> ATFGRAPH_API_KEY=<the key in the secret scope>
python -m examples.databricks.two_node.call "Two people, four nights in Lisbon"

    What to look at

    1. Console. $ATFGRAPH_SERVER/ui/: the traverser you started, its two-step path, and the probe emitter with its next due time.
    2. MLflow (when enabled). The trace in the shared experiment has an AGENT span intake.triage, under it the LLM span of app.ai, the CHAIN span of the edge, and the TOOL span pricing.quote produced on the other node and joined through the run metadata.
    3. Emitter. Without calling anything, a new traverser appears every fifteen minutes from intake.probe, walking the same edge with a fixed request.
    4. Signed path. GET $ATFGRAPH_SERVER/api/v2/traversers/<id>/path and the identity routes export the recorded and signed path.

    Differences from the original

    • Nodes are outbound workers, so AGENT_CALLBACK_URL, the PORT from DATABRICKS_APP_PORT and the two-pass deploy are gone; the shared worker_entrypoint.py binds the App port for the status page only.
    • ATFGRAPH_AUTH=databricks (service-principal OAuth tokens on graph-server calls, inbound principal allowlists) does not exist in vNext: the worker authenticates to the graph server with ATFGRAPH_API_KEY from a secret binding, and there is no inbound node surface to allowlist. Recorded as a gap.
    • The model provider is the SDK's OpenAI-compatible client (ATFGRAPH_MODEL_URL/ATFGRAPH_MODEL_NAME/ATFGRAPH_MODEL_API_KEY) rather than litellm's databricks/ or openrouter/ prefixes; the credential is a secret binding, never minted from the App's service principal.
    • mlflow_autolog=True became opt-in ATFGRAPH_MLFLOW_TRACING=true via atfgraph.mlflow.enable_from_env; span types are unchanged.
    • The graph server is not a Databricks App in vNext; deploy it with Compose, Kubernetes or Helm (deploy/).
    • databricks bundle validate/deploy/run were not run for this example; the bundles were built and checked locally only.

    Tests: tests/test_migrated_ops_examples.py runs both nodes on a real daemon with the fixture provider and checks the bundle files offline.
