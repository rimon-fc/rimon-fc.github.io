    Retrieval example (semantic + hybrid knowledge)

    Directory examples/python/features/retrieval

    One node, five traversals, no server change. Documents live in the node's global knowledge scope (BM25 with doc_id#ordinal citations); SemanticKnowledge embeds every server chunk with the configured provider and stores one vector per chunk in the same scope's memory vectors (kb:desk:<doc_id>#<ordinal>). Queries run lexically, semantically or fused by reciprocal rank, and every semantic hit is verified against the live document revision before it is returned.

    Agent node label retrieval_desk, version 1.0.0.

    Embedding provider

    The provider is explicit. With ATFGRAPH_EMBEDDING_URL and ATFGRAPH_EMBEDDING_MODEL set, http_embedding_provider posts to an OpenAI-compatible /embeddings endpoint (only when a traversal embeds text). Without them the node uses embeddings.py: a deterministic concept-lexicon vectoriser that maps luggage/baggage and charges/fees to shared concepts and hashes other words. It is a demonstration embedder, not a model; its purpose is an offline, reproducible workflow in which "luggage charges" retrieves the excess baggage passage although neither word occurs in the corpus, while BM25 returns nothing.

    Run

    python -m atfgraph.worker --module examples.python.features.retrieval.agent:app
python -m examples.python.features.retrieval.call

    call.py ingests fixtures.py, asks each question in SEMANTIC_QUERIES in all three modes (printing BM25 and cosine scores and ranks side by side), applies a metadata filter, forgets policy:baggage and shows the semantic query no longer returns it, then prints the status.

    Lexical and semantic rankings are different things: BM25 scores are term statistics, cosine scores are provider geometry. The example never presents one as the other; hybrid passages show both. Use reindex after changing the embedding model or repairing an interrupted ingestion.

    Tests: tests/test_semantic_knowledge.py (wire bodies over a recording transport, bounded concurrency, retry and failure consistency, stale-vector handling, the node through the contract double, and the real daemon over HTTP).
