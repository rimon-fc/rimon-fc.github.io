    README

    Rendered from examples/python/container_node/README.md; the source file is not modified.

    Run these commands from the atfgraph-vnext checkout. Install the authoring SDK and build the CLI once:

    python -m pip install -e ./python
cargo build --bin atfgraphd --bin atfg
export PATH="$PWD/target/debug:$PATH"
atfg server start

    The server defaults to http://127.0.0.1:18880; its browser UI is /ui/. Set ATFGRAPH_SERVER and ATFGRAPH_API_KEY for a different server.

    python -m examples.python.container_node.agent
# Another terminal:
atfg traverse container-node.demo_echo --in '{"message":"container check"}'
python -m examples.python.container_node.call hello '{"name":"Ada"}'

    Run the same worker in Docker:

    docker compose -f examples/python/container_node/compose.yaml up --build
# Inspect both stdout and stderr heartbeats:
docker compose -f examples/python/container_node/compose.yaml logs -f
# Stop only this example:
docker compose -f examples/python/container_node/compose.yaml down

    The worker connects outbound; no callback port is required. Set ATFGRAPH_CONTAINER_SERVER to a reachable server URL. A host server bound only to loopback may need an explicit reachable interface or a shared Docker network. The example does not start or change your graph server's listener.

    Stdout/stderr heartbeats remain container logs. To additionally ship structured execution logs, an administrator must enable node_logs_enabled using the observability settings API; then set ATFGRAPH_DEMO_SHIP_LOGS=1 before launching. For example, from an administrator Python client:

    import asyncio
from atfgraph import Agent

async def configure():
    app = Agent(node_id="log-settings")
    try:
        await app.observability.set_settings(node_logs_enabled=True)
    finally:
        await app.client.aclose()

asyncio.run(configure())

    The SDK ships logger records made inside traversals, not arbitrary process output. No model credentials are required.
