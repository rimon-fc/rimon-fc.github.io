    Execution resilience checks

    Directory examples/resilience

    Sixteen scenarios for what happens when a model backend errors or hangs, a worker is saturated, killed or crashes, or a run outlives its caller's patience. Migrated from the parent examples/resilience (the issue #316 scenarios). Every check runs against a real graph server with three fixture agents and a mock model backend; no model provider, credential or network is involved.

    Agent node label test-slow, version 1.0.0.

    Capabilities

    CapabilityKindSignatureModuleSummary
    crashskill(message: str = 'boom') -> dictexamples/resilience/agent_flaky.pyAlways raise; the traverser fails with ``RuntimeError`` and this message.
    maybe_failskill(fail_rate: float = 0.5) -> dictexamples/resilience/agent_flaky.pyFail with the given probability (0.0 never, 1.0 always); the failure is terminal, not retried.
    pingskill() -> dictexamples/resilience/agent_flaky.pyInstant answer; submitted while the worker is down it waits in the queue until a worker returns.
    timeout_then_failskill(delay_seconds: float = 60) -> dictexamples/resilience/agent_flaky.pyHang for a long time, then raise; the 5-second budget ends it first (``handler_timeout``).
    addskill(a: int = 0, b: int = 0) -> dictexamples/resilience/agent_healthy.pyDeterministic, instant arithmetic.
    askskill(prompt: str = 'ping') -> dictexamples/resilience/agent_healthy.pyOne model call through the configured provider.
    echoskill(message: str = 'hello') -> dictexamples/resilience/agent_healthy.pyInstantly return the input; verifies that basic execution works.
    bounded_taskskill(duration_seconds: float = 30) -> dictexamples/resilience/agent_slow.pyBlocks past its 3-second budget on purpose; the worker ends it with ``handler_timeout``.
    slow_taskskill(duration_seconds: float = 30, slice_seconds: float = 0.1) -> dictexamples/resilience/agent_slow.pyWait for ``duration_seconds`` (stopping early on cancel) and report the actual time taken.

    Non-default capability options: timeout_then_fail: timeout_seconds=5; ask: max_attempts=2, timeout_seconds=4; bounded_task: timeout_seconds=3; slow_task: timeout_seconds=600

    16Worker death mid-runstale reaperSIGKILL during an attempt: the lease expires and the run fails interrupted ("no retries remain")

    The runner also starts the daemon with its model-health monitor pointed at the mock (ATFGRAPH_MODEL_HEALTH_*) and prints the daemon's confirmation line. That monitor probes and tracks a circuit per endpoint inside the daemon, but vNext has no API route or admission guard for it yet, so no check depends on it.

    Differences from the original, and open gaps

    • No admission-time model circuit breaker. The parent refused executions with 503 llm_unavailable while its LLM health circuit was open. The vNext daemon runs a model-health monitor (src/model_health.rs, ATFGRAPH_MODEL_HEALTH_*) but the status route and admission guard are not mounted, so the checks show backend failure through retried attempts and budgets instead. Recorded as a gap for the coordinator.
    • Queueing instead of `429`. Capacity is a worker property; excess work waits as queued and is never rejected. Callers bound their own concurrency with Client(max_in_flight=..., max_pending=...).
    • No agent status endpoint. vNext lists registered agent definitions, not per-worker health; workers are monitored through leases. The check probes with a real call.
    • Durable queue while a worker is dead. The parent reported agent_unreachable; vNext keeps the run queued until a worker returns (a run's deadline starts at its first claimed attempt). Cancel it if nobody will.
    • Error codes are the SDK's envelope (retryable, handler_timeout, timed_out, interrupted, cancelled, the exception class name), not the parent's error_category vocabulary.
    • agent_flaky.timeout_then_fail now awaits instead of blocking the event loop.
    • run_tests.sh became run_checks.py; the checks are importable and tests/test_migrated_ops_examples.py runs them against a real daemon.
