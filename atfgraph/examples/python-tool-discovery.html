    README

    Rendered from examples/python/tool_discovery/README.md; the source file is not modified.

    Run these commands from the atfgraph-vnext checkout. Install the authoring SDK and build the CLI once:

    python -m pip install -e ./python
cargo build --bin atfgraphd --bin atfg
export PATH="$PWD/target/debug:$PATH"
atfg server start

    The server defaults to http://127.0.0.1:18880; its browser UI is /ui/. Set ATFGRAPH_SERVER and ATFGRAPH_API_KEY for a different server.

    Start the utility worker and orchestrator in separate terminals:

    python -m atfgraph.worker --module examples.python.tool_discovery.worker:app
python -m atfgraph.worker --module examples.python.tool_discovery.agent:app
atfg traverse utility-worker.calculate --in '{"operation":"add","a":2,"b":3}'
python -m examples.python.tool_discovery.call inspect_tools '{}'

    These calls need no provider credentials. get_weather always returns labelled fixture data. Division by zero and unknown calculator operations fail explicitly.

    Configure a model on the worker that needs it before startup: ATFGRAPH_MODEL_URL (an OpenAI-compatible chat-completions endpoint), ATFGRAPH_MODEL_NAME, and ATFGRAPH_MODEL_API_KEY where required. Then:

    atfg traverse orchestrator.ask_with_tools --in '{"question":"Use the calculator to add 2 and 3."}'
atfg traverse orchestrator.weather_report --in '{"cities":"Tokyo and Sydney"}'
atfg traverse orchestrator.smart_query --in '{"question":"Multiply 42 by 17."}'
atfg traverse orchestrator.guarded_query --in '{"question":"Divide 20 by 4."}'
atfg traverse utility-worker.summarize --in '{"text":"Our itinerary has three days in Bali and a beach afternoon."}'

    The orchestrator discovers only utility-worker skills. Weather selection filters capability name/description. smart_query first asks the model to select from candidate target names, checks its answer against the allowlist, then supplies only the selected schemas. This is application-level two-stage selection; registry schemas are still fetched eagerly. guarded_query allows three tool rounds and five calls. All actual tool executions are recorded child traversals. Provider requests may incur charges; without model configuration the model-backed handlers fail.
