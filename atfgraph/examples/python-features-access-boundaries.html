    README

    Rendered from examples/python/features/access_boundaries/README.md; the source file is not modified.

    What a restricted caller can reach, decided by the graph server rather than by the node. agent.py contains no authorisation code at all; boundaries.py installs the rules and then tries to cross them.

    ATFGRAPH_CONFIG_FILE=examples/python/features/access_boundaries/config.example.yaml \
  target/debug/atfgraphd
ATFGRAPH_API_KEY=local-concierge-node \
  python -m atfgraph.worker --module examples.python.features.access_boundaries.agent:app
python -m examples.python.features.access_boundaries.boundaries

    config.example.yaml defines three fixture principals on a scratch database: operator (admin), concierge-node (admin + worker, so the node can register itself and enrol a worker) and partner (invoke only). The tokens in it are throwaway strings for a loopback daemon, not credentials; override them with $ATFGRAPH_OPERATOR_TOKEN and $ATFGRAPH_PARTNER_TOKEN.

    The two mechanisms

    Access policies (/api/v2/access/policies) match on label, capability and principal and decide invocations:

    PolicyEffect on partner
    deny on concierge.refundevery refund submission is 403 policy_denied
    allow on concierge.quote with constraints currency == AUD, nights <= 7a 14-night quote is 403 constraint_denied
    allow on concierge.itinerary with rate: 0.001/s, burst: 2the third call in a burst is 429 rate_limited

    Constraints are checked against the submitted input, so a field the rule names must actually be present: omitting currency is a refusal, not a default. An allow rule never adds authority — it only narrows what the caller's role already permits — and a run that is refused is never created, so nothing is charged and no handler starts.

    Connector manifests (/api/v2/access/connectors/{principal}) bind a principal to a list of operation grants. The partner is granted traversers.submit, traversers.get, traversers.path and agents.capabilities, so client.list_agents() (agents.list) comes back 403 connector_forbidden even though its invoke role would otherwise allow it. Grants restrict; they never widen. A principal can always read its own manifest (GET /api/v2/access/connector) to discover what it is allowed to do, and POST /api/v2/access/evaluate previews one operation without consuming a rate token.

    Revocation persists: after POST /api/v2/access/connectors/partner/revoke the partner is refused everywhere and does not fall back to being an ordinary bearer. Re-running the script rebinds it.

    The same checks apply on the MCP and A2A surfaces and to emitter-driven runs, so a partner cannot route around them by choosing a different protocol.

    Tests: tests/test_feature_examples_extended.py runs this configuration against a real daemon and asserts each outcome in the table.
