    README

    Rendered from examples/python/retrieval_quality/README.md; the source file is not modified.

    Evaluate faithfulness, relevance, hallucination and configurable principles. Quick mode uses one perspective per metric; standard uses a critic and defender; thorough adds an independent judge. Live runs also evaluate each configured principle. Domain weights change the constitutional score.

    Run locally

    From the atfgraph-vnext checkout, with its Python SDK installed in your active environment:

    atfg server start
EXAMPLE_MODE=fixture python -m atfgraph.worker --module examples.python.retrieval_quality.main:app
# In a second terminal:
python -m examples.python.retrieval_quality.call

    Or install and run the node as a managed local installation:

    atfg install ./examples/python/retrieval_quality
atfg run retrieval_quality

    The node.py entrypoint also works when this folder is copied out of the checkout. The graph server defaults to http://127.0.0.1:18880; inspect traversers and child calls at http://127.0.0.1:18880/ui/.

    Call with the CLI

    atfg traverse retrieval_quality.evaluate_rag_response --in '{"question": "When does the desk open?", "context": "The desk opens at 9am.", "response": "The desk opens at 9am.", "mode": "quick"}'

    Providers

    EXAMPLE_MODE=fixture is the default: deterministic local example data and calculations, no model or search calls. Fixture scores demonstrate mechanics, not model quality.

    To use live model decisions, set EXAMPLE_MODE=live, ATFGRAPH_MODEL_URL, ATFGRAPH_MODEL_NAME and, when needed, ATFGRAPH_MODEL_API_KEY. Configure these before starting the worker. Missing settings fail explicitly; live failures never silently fall back to fixture answers.

    Python client

    from atfgraph import Client

async with Client("http://127.0.0.1:18880") as client:
    result = await client.traverse(
        "retrieval_quality.evaluate_rag_response",
        {'question': 'When does the desk open?', 'context': 'The desk opens at 9am.', 'response': 'The desk opens at 9am.', 'mode': 'quick'},
        timeout=300,
    )
    print(result)

    Evaluation dashboard

    The optional Next.js dashboard submits v2 traversers and displays results and runtime events. Its server-side proxy keeps ATFGRAPH_API_KEY out of browser JavaScript. The dashboard uses the model configured on the worker; it does not choose arbitrary provider models per request.

    cd examples/python/retrieval_quality/ui
npm ci
ATFGRAPH_SERVER=http://127.0.0.1:18880 npm run dev -- --hostname 127.0.0.1
# Open http://127.0.0.1:3000

    Use this convenience dashboard on a trusted local machine. The proxy uses its configured server identity, so add your own user authentication before sharing the dashboard across users.

    Docker Compose

    Build the graph server image from the checkout and choose a local API key. Run this stack instead of a graph server already occupying port 18880:

    docker build -f deploy/docker/Dockerfile.server -t atfgraph-vnext/graph-server:local .
export ATFGRAPH_API_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
docker compose -f examples/python/retrieval_quality/compose.yaml up --build -d
atfg traverse retrieval_quality.evaluate_rag_response --in '{"question":"When does the desk open?","context":"The desk opens at 9am.","response":"The desk opens at 9am.","mode":"quick"}'
docker compose -f examples/python/retrieval_quality/compose.yaml down

    The evaluation dashboard is on port 3000; the graph server API and embedded UI are on 18880. Data persists in the named Compose volume.

    Local ML checks and principles

    config/constitution.yaml defines weighted principles and domain overrides. The domain preset YAML files are provided as editable configuration examples. The active configuration is constitution.yaml; the API's domain selects its weight overrides.

    For optional NLI checks, install requirements-ml.txt (or build with INSTALL_ML_DEPS=true) and call with use_ml=true. This downloads the configured model on first use and reports NLI results separately from model or fixture scores. ml_services/ner.py and ml_services/embeddings.py also expose local entity-extraction and similarity utilities for extending your evaluation. Their model downloads require network access and may be substantial. Fixture mode alone needs no ML downloads. All scores are diagnostic judgements, not guarantees of factual accuracy or safety.
