    ATF Harness as a graph traversal

    Directory examples/harness

    python/agent.py calls the local atfHar runtime through the SDK's harness bridge (app.harness(...), provider atf-harness). The traversal harness-example.answer returns the text, token usage, cost and harness session id the CLI reported, and the run is recorded as an ordinary traverser with its path and progress events. It does not substitute a fixture when the provider fails: a failed invocation fails the traverser with the harness's message.

    Agent node label remote-coder, version 0.1.0.

    Capabilities

    CapabilityKindSignatureModuleSummary
    answertraversal(prompt: str, model: Optional[str] = None, cwd: Optional[str] = None, variant: Optional[str] = None, provider: Optional[str] = None, timeout: float = DEFAULT_TIMEOUT_SECONDS) -> dictexamples/harness/python/agent.pyRun one prompt through the harness with no tools and return what it reported.
    doctorskill() -> dictexamples/harness/python/agent.pyWhich harness CLIs are available on this worker (nothing is executed).
    continuetraversal(task: str, timeout: Optional[float] = None) -> dictexamples/harness/remote/agent.pyA follow-up in the same harness session (same ATFGraph session id required).
    doctorskill() -> dictexamples/harness/remote/agent.pyReachability, readiness and profile availability of the configured harness. No turn is started.
    implementtraversal(task: str, timeout: Optional[float] = None) -> dictexamples/harness/remote/agent.pyRun ``task`` in the operator's workspace. One attempt: coding work has side effects.

    Non-default capability options: answer: max_attempts=1, timeout_seconds=180; continue: max_attempts=1, timeout_seconds=1800; implement: max_attempts=1, timeout_seconds=1800

    README

    Rendered from examples/harness/README.md; the source file is not modified.

    python/agent.py calls the local atfHar runtime through the SDK's harness bridge (app.harness(...), provider atf-harness). The traversal harness-example.answer returns the text, token usage, cost and harness session id the CLI reported, and the run is recorded as an ordinary traverser with its path and progress events. It does not substitute a fixture when the provider fails: a failed invocation fails the traverser with the harness's message.

    CapabilityKindWhat it does
    answertraversalone prompt, no tools, one attempt, 120 s harness timeout
    doctorskillwhich harness CLIs are installed on the worker host (none is executed)

    Prerequisites

    Python 3.10+, the vNext SDK (python -m pip install -e 'python[test]' from the this repository's root), a running graph server, atfHar on the worker process PATH, a configured model and that provider's credentials. The harness configuration lives in ~/.atf-harness/agent/config.yml and models.yml; this example does not change it and does not log into a provider.

    Run

    atfHar --version
export ATFGRAPH_HARNESS_MODEL='your-provider/your-model'
export ATFGRAPH_HARNESS_WORKDIR="$PWD"
# Export the provider credentials your harness model needs into this shell:
# the worker process is what runs atfHar.
target/debug/atfgraphd
python -m atfgraph.worker --module examples.harness.python.agent:app
# Another terminal:
python -m examples.harness.python.call --doctor
python -m examples.harness.python.call "Reply with the word ready."

    ATFGRAPH_SERVER defaults to http://127.0.0.1:18880. answer also accepts model, cwd, variant, provider and timeout in its input, so one worker can serve several models or directories; the environment variables are the defaults. Set ATFGRAPH_HARNESS_THINKING only to override the configured model variant. Other providers (claude-code, codex, opencode) are selected with ATFGRAPH_HARNESS_PROVIDER or --provider; tool access stays disabled where the provider can control it.

    A provider credential that is absent or expired surfaces as a failed traverser whose error message is the harness's own report (a 401 from the model provider included). doctor checks only that the CLI is discoverable; it does not prove provider authentication.

    Package or install

    target/debug/atfg install examples/harness/python --python python3 --sdk python
target/debug/atfg run harness-example

    The manifest declares ATFGRAPH_HARNESS_MODEL and ATFGRAPH_HARNESS_WORKDIR as required user environment; the installer prompts for them and never copies a provider credential.

    Differences from the original

    • The node is an outbound worker (app.run() claims tasks); there is no inbound HTTP port, so the original PORT variable and app.run(host, port) are gone.
    • HarnessConfig(max_retries=0) became @app.traversal(max_attempts=1): retries are a capability property enforced by the graph server.
    • The original passed max_turns=1; the atf-harness provider runs one print turn by construction and has no such flag. claude-code accepts max_turns through app.harness(..., max_turns=1) if you switch providers.
    • Harness failures raise HarnessFailure inside the worker instead of returning is_error=True; the traverser's error.message carries the report.
    • Progress: every harness JSON event is recorded as a durable progress event on the traverser (call.py counts them), which the original did not do.

    Tests: tests/test_migrated_ops_examples.py runs the worker against a real daemon with a fixture atfHar executable on PATH; no model provider is contacted.

    Remote harness (remote/)

    remote/agent.py is remote-coder: the same app.harness(...) call with transport=RemoteHarness(...) and workspace=ExistingWorkspace(...), so the coding work runs in a workspace on a remote ATF Harness host while ATFGraph records the path, pauses for approvals and totals usage. No harness CLI is needed on the worker.

    CapabilityKindWhat it does
    implementtraversalone task in the operator's workspace, one attempt
    continuetraversala follow-up in the same harness session (same ATFGraph session id)
    doctorskillreachability, readiness and profile availability of the harness; no turn

    Configure ATFGRAPH_HARNESS_URL, ATFGRAPH_HARNESS_PROFILE, ATFGRAPH_HARNESS_WORKSPACE (and ATFGRAPH_HARNESS_EDGE_AUTH, ATFGRAPH_HARNESS_TOKEN when the deployment needs them), then python -m atfgraph.worker --module examples.harness.remote.agent:app and python -m examples.harness.remote.call "...". The workspace must already exist on the harness host: this example does not clone repositories or return patches. See docs/python/07-harness.md.
