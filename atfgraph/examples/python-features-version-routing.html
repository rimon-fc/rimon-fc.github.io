    README

    Rendered from examples/python/features/version_routing/README.md; the source file is not modified.

    Two registered versions of the node label fares, served by two workers, and the rule that decides which one a call reaches. Fixture fares, no supplier, no keys.

    VersionCapabilitiesDifference
    1.0.0 (agent:v1)quote(route, adults)bags are bundled into the fare
    2.0.0 (agent:v2)quote(route, adults, bags), seat_map(route)baggage is a separate line; new capability
    target/debug/atfgraphd
python -m atfgraph.worker --module examples.python.features.version_routing.agent:v1
python -m atfgraph.worker --module examples.python.features.version_routing.agent:v2
python -m examples.python.features.version_routing.call --route BNE-SYD --bags 1

    Both worker commands are needed: a worker enrols for one (label, version) and claims only work admitted for that exact version, so 1.0.0 work queues until its own worker runs.

    The rule

    CallResolves to
    submit("fares.quote", ...)the highest registered version — 2.0.0 once it exists
    submit("fares.quote", ..., version="1.0.0")exactly 1.0.0, its schemas and its workers
    submit("fares.seat_map", ..., version="1.0.0")404 capability_not_found
    submit("fares.quote", ..., version="9.9.9")404 agent_not_found

    client.capabilities("fares") and client.capabilities("fares", "1.0.0") return the two definitions, and every run records the version it resolved to (TraverserResult.version), so a path shows which definition served each step.

    Pinning freezes the whole contract, not just the routing: call.py also sends 2.0.0's bags field to the pinned 1.0.0 call, and the run fails at the worker with invalid_input because that handler has no such parameter. Registering a changed definition under a version that already exists is rejected — bump the version instead.

    Installing this directory with atfg install installs 2.0.0 (entrypoint.module: agent:v2); 1.0.0 stays a second worker command against the same source.

    Tests: tests/test_feature_examples_extended.py serves both versions against a real daemon and asserts each routing outcome above.
